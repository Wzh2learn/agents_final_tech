## 8. 执行节奏纪律 (全局规则, 2026-08-25 用户批准)

- 主线程禁用 >5min 阻塞 sleep; 一切里程碑等待 = GB10 cron one-shot + 文件工件 + 结 turn。
  watcher session / sleep 链模式作废 (理由: 等待不是工作, 工件才是; 三害 = 阻塞插不进话 /
  上下文压缩 / ssh 长连接脆弱)。先例: 池xGUC 修复窗 (2026-08-25 凌晨) 门禁转 cron 工件。
- 收集与判定分离: 数据收集保留夜间 cron (机器时间, 流量干净); 一切需用户拍板的判定移至白天——
  主线程每日上午产出《判定一页纸》(分段数据 + 选项 + 推荐 + 红线核对), 用户白天圈选。
  任务卡不得把人类决策排在 22:00 后; 夜间窗口只执行已批准的确定性动作。
- cron one-shot 三件套: 跑完自删条目 (先例: b4_checkpoint) + abort 分支写死在脚本里
  (失败自动回滚, 不依赖主线程在线判断) + 工件路径在任务卡中显式声明。
- **UTF-8 字节截断必须字符安全（2026-08-25 E1b 钉死）**: `head -c N` 截中文/LLM 文本必配 `| iconv -f utf-8 -t utf-8 -c`;
  判定类工件读取默认 errors="replace" + 第二数据源（dispatch_log 等）兜底。
  案例: 08-25 gate=UNKNOWN——position 657 "资产市[值]"字符腰斩 → rd() 吞 UnicodeDecodeError 返回空串。回归用例 = 当晚 PASS。
- **cron 闸语义（2026-08-25 E1a 固化）**: 闸不达标 = 改期（至多 N 次）, **禁止 SKIP**;
  改期耗尽 = BLOCKED 标记 + 台账, 仍不静默。工具: scripts/graph/cron_gate_helper.sh。
  案例: 08-25 01:50 W4 闸撞 W3 eval 收尾（01:05→01:51）, SKIP 致 W5 连环 abort。
- **pending 卡交接必须 cron one-shot 触发（2026-08-25 E1c 固化）**: 入账"稍后执行"类任务卡
  必须同批安装触发 cron（或显式用户唤醒约定）; 禁止依赖"硬停后会话仍活"。
- **watcher 双实证 = 常备派发前置检查（A4w 落地, 当前输入合同）**: 任何任务卡只要安装
  cron/one-shot 观察器, 派发前必须跑 `scripts/graph/dispatch_precheck.sh`（需 Bash 与 Python 3 标准库）,
  并把输出**逐字入卡**。至少提供一个 `--watcher PATH` 和一个 `--tick-marker RECEIPT.json`, 两项缺一不派发。
  ① **执行位实证** —— 每个 watcher 必须存在、是非空普通文件、有执行位且通过 `bash -n`;
     输出 mode + 完整 SHA256 + 语法检查结果。预检只做静态检查, **绝不执行 watcher**。
  ② **执行收据合同** —— tick 必须是普通文件中的 JSON 对象, 不是任意非空文本/Markdown 模板。
     每个传入 watcher 至少绑定一份合格收据（按解析后的绝对路径匹配）; 拒绝未知 watcher、缺字段、
     错误 SHA、非整数零退出码和未来时间。任一所给收据不合格都 FAIL, 不能用另一份有效收据掩盖。
     可复制的 JSON 字段模板如下（**不是执行证据**, 必须由获授权的实际执行结果填写, 不得直接冒用）:

  ```json
  {
    "watcher": "/absolute/path/to/watcher.sh",
    "watcher_sha256": "<该 watcher 执行版本的完整 64 位 SHA256>",
    "observed_at": "2026-09-22T08:00:00+08:00",
    "exit_code": 0
  }
  ```

  `watcher` 必须是绑定传入脚本的绝对路径; `watcher_sha256` 必须与该脚本**当前字节**相符, 改脚本后旧收据失效;
  `observed_at` 填真实执行观测时间, 使用带时区的 ISO8601（如上例或 `2026-09-22T00:00:00Z`）;
  `exit_code` 填真实退出码, 只有 JSON **整数 0** 合格（字符串、布尔值、浮点数均不合格）。
  可加 `--max-tick-age-min N`: N 必须为非负整数; N>0 按收据 `observed_at` 精确核新鲜度,
  **不使用文件 mtime**, N=0 仅取消年龄上限, 仍拒绝未来时间。缺参数/缺值/非法年龄退出 64, 证据失败退出 1。
  如提供 `--cron-line '<cron 原文>'`, 仍须静态核验: 仅支持五字段或标准 `@宏` 后直接调用 watcher 绝对路径,
  或 `bash/sh`（含 `/bin/`、`/usr/bin/` 路径）加 watcher 绝对路径, 并以 `> 日志路径 2>&1` 或
  `>> 日志路径 2>&1` 结尾。未知/不存在目标、丢弃日志、无日志或复杂 shell 调用均 FAIL;
  这不是完整 cron 调度器, 不验证调度字段、运行环境、日志可写性或未来执行。
  **收据是可审计输入合同, 不声称防恶意伪造; 预检不执行 watcher、不自动制造 tick、不安装 cron。**
  理由仍为 F-0907-1「挂了 crontab ≠ 观察器在跑」。**本条不改变 §8 既有的 sleep 禁令与三件套。**
  先例 = D4 卡 BG-7（历史卡保留其当窗证据口径, 不回改为本合同）。
- **窗口时段规则（2026-08-31 用户裁定明确化）**: 端点窗（任何 :8004/:8006/:8007 等模型服务调用）= 仅白天错峰,
  夜间零调用; 零端点窗（纯确定性计算/本地资产加载, 运行时断言零模型调用）= 不限时段。
  卡内必须显式声明窗口类型（端点窗/零端点窗）, 时段注记按本条销账或改期。
  案例: 08-25 晨间序列卡入账后零执行（会话未活, 无人触发）。与 sleep 禁令同源: 里程碑等待=工件化。
- **执行-报告阶段分离 + 检查点持久化（A22 文档侧固化, 2026-09-11 决策 22; 脚本侧另批）**: 任何「分析 + 报告」同批的任务卡
  必须把两个阶段写成**可分别重做的两段**, 三条硬要求:
  ① **报告会话中断只重做报告, 不重跑分析** —— 分析结果必须已落盘为收据/工件, 报告阶段只读工件不再产生新事实;
     卡内必须显式声明「报告可从哪些工件重建」, 缺该声明 = 两阶段未分离, 中断即全批重跑
     （令牌耗尽家族 3 次的成因: D2 / DR4 首跑）。
  ② **分析全程以收据 + 记录分段写盘** —— 不允许「跑完再一次性写」; 每个阶段结束即写一段
     （收据 JSON / JSONL 逐行 / 分段 markdown）, 使中断点之前的成果**不依赖会话存活**。
     承 A4w 同一教训族: 那里是「挂了 ≠ 在跑」, 此处是「**跑过 ≠ 存下**」。
  ③ **实际 usage 记账** —— 卡内预算门给的是**上界**, 收口必须回填**实际**用量（调用数 / token / 时长）
     并与上界对照; 只报上界不报实际 = 下一批的预算门失去校准依据
     （承 D3 阶段 B 计数器 31 ≤ 200 的双恒等式姿势）。
  先例 = D3 autopsy 批（决策 6A「一次到底」）已按 ①② 实践: 收据
  `logs/graph/eval/d3_autopsy_recompute.json` 先落盘、报告后组装, 故该批中断可只重做报告。
  **本条为文档侧固化; 检查点持久化与 usage 记账的机械实现属脚本侧, 不在 09-11 夜批**
  （决策 22 范围划分: 脚本类等 A4/A5 验收后另批派发 Loop A）。
