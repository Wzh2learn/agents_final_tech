# Problem-Solving Methods

Use these methods to generate and challenge solution paths. They do not authorize implementation.

## 1. Complementary Expert Panel

Run this method for a problem that crosses disciplines.

1. Restate the problem, known facts, goal, and constraints.
2. Select three genuinely complementary perspectives.
3. Reject perspectives that differ only by job title.
4. For each perspective, answer:
   - how it reframes the problem;
   - its preferred solution path;
   - risks the other perspectives overlook;
   - evidence that would change its judgment.
5. Cross-examine the perspectives:
   - identify shared facts;
   - identify real disagreements;
   - expose assumptions behind each disagreement.
6. Synthesize one recommendation with:
   - applicability conditions;
   - largest risk;
   - exit condition;
   - first action.

Do not imitate or attribute positions to real people.

Output template:

```markdown
# Expert Panel: <problem>
## Reframing
## Perspective A
## Perspective B
## Perspective C
## Cross-Examination
## Recommendation
## Conditions, Risk, Exit, First Action
```

## 2. First Principles

Run this method when existing solutions have accumulated patches or path dependence.

1. Separate:
   - confirmed facts that cannot be avoided;
   - habitual assumptions that have not been verified;
   - the actual goal;
   - resources and constraints.
2. Set aside industry convention and existing solutions temporarily.
3. Derive feasible paths only from facts, goals, and constraints.
4. Identify which parts of the current solution only patch symptoms.
5. State the new path, its premises, and the first validation step.

Output template:

```markdown
# First Principles: <problem>
## Confirmed Facts
## Unverified Assumptions
## Goal
## Resources and Constraints
## Surface Patches in the Current Solution
## Re-derived Path
## Premises
## First Validation
```

Do not label a common practice as a confirmed fact without evidence.

## 3. Cross-Domain Borrowing

Run this method when the current domain's standard solutions have failed.

1. Remove domain jargon and describe the underlying problem structure.
2. Identify the core contradiction and why ordinary solutions fail.
3. Find at least three distant domains with similar structures.
4. For each case, document:
   - the problem in that domain;
   - the mechanism used;
   - structural similarity;
   - transferable parts;
   - failure conditions.
5. Select the three strongest mechanisms.
6. Translate each mechanism into the current context.
7. Recommend one low-cost, reversible experiment.

Output template:

```markdown
# Cross-Domain Borrowing: <problem>
## Abstract Structure
## Core Contradiction
## Why Standard Solutions Fail
## Analogous Cases
## Transferable Mechanisms
## Adapted Options
## Low-Cost Reversible Experiment
```

Require structural similarity, not superficial vocabulary similarity. Record historical cases with source and date when external research is authorized.
