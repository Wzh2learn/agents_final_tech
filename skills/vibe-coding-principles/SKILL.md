# Vibe Coding 核心原则

Vibe Coding 是一种以"意图对话"为核心的 AI 辅助编程方式。本文档定义了 5 大核心原则，供其他技能和子代理引用。

## 五大核心原则

### 1. 意图先于实现（Intent Before Implementation）

**核心思想**：先清晰表达"要什么"（业务目标、用户价值、期望行为），再让 AI 决定"怎么实现"（具体技术方案、代码结构）。

**为什么重要**：
- AI 擅长从高层意图推导实现细节
- 过早陷入实现细节会限制 AI 的创造力
- 意图清晰可以让 AI 提供更优的技术方案

**实践要点**：
- 用"我想要一个能够..."而不是"帮我写一个函数..."
- 描述用户场景和业务价值
- 让 AI 提出技术方案，而不是直接要求特定实现

### 2. 分层设计（Layered Design）

**核心思想**：从「系统 → 模块 → 接口 → 具体实现」逐层细化，而不是一次性要求"帮我把整个系统写完"。

**为什么重要**：
- 降低复杂度，每次只关注一个层级
- 便于验证和调整架构
- 避免 AI 生成过于庞大、难以维护的代码

**实践要点**：
- 第一步：系统架构和模块划分
- 第二步：定义模块间的接口
- 第三步：逐个实现模块
- 第四步：集成和测试

### 3. 上下文管理（Context Management）

**核心思想**：主动管理对话上下文，通过 @ 文件、总结关键信息等方式，避免"AI 失忆"。

**为什么重要**：
- AI 的上下文窗口有限
- 长对话中信息容易丢失
- 明确的上下文能提高 AI 响应质量

**实践要点**：
- 使用 `@文件路径` 明确指定相关文件
- 定期总结当前状态和待解决问题
- 在新话题开始时重新建立上下文
- 使用 context-manager 技能维护上下文清单

### 4. 质量前移（Quality First）

**核心思想**：在代码生成后立即进行质量检查（风格、安全、性能、可测性），而不是等到上线后再救火。

**为什么重要**：
- 早期发现问题成本更低
- 养成质量意识，避免技术债累积
- AI 生成的代码需要人工把关

**实践要点**：
- 生成代码后立即运行 quality-gate 检查
- 关注安全漏洞、性能瓶颈、可测试性
- 使用自动化工具（linter、测试、安全扫描）
- 不要盲目信任 AI 生成的代码

### 5. 迭代优化（Iterative Refinement）

**核心思想**：贯彻"生成 → 检查 → 精炼"的短循环，一次解决 1-2 个问题，逐步打磨代码质量。

**为什么重要**：
- 避免一次性改动过多导致混乱
- 每次迭代都有明确的改进目标
- 便于验证改进效果

**实践要点**：
- 首次生成：快速实现核心功能
- 第一轮精炼：可读性和代码风格
- 第二轮精炼：性能优化
- 第三轮精炼：安全加固和边界情况
- 每轮迭代后运行测试验证

## 好用法 vs 坏用法对比

### 示例 1：用户认证功能

#### ❌ 坏用法（违反"意图先于实现"）
```
用户：帮我写一个 JWT 认证的中间件函数，要用 bcrypt 加密密码，
     用 Redis 存 token，数据库用 PostgreSQL。
```

**问题**：过早指定技术细节，AI 只能按要求实现，无法提供更优方案。

#### ✅ 好用法（遵循"意图先于实现"）
```
用户：我需要一个用户认证系统，要求：
     1. 用户可以注册、登录、登出
     2. 密码需要安全存储
     3. 登录后的会话需要持久化
     4. 支持多设备同时登录

     请先建议技术方案，再实现。
```

**优势**：清晰表达业务需求，AI 可以根据场景推荐最佳技术栈。

### 示例 2：数据处理模块

#### ❌ 坏用法（违反"分层设计"和"迭代优化"）
```
用户：帮我写一个完整的数据处理系统，包括数据采集、清洗、
     转换、存储、查询、可视化，全部一次性写完。
```

**问题**：范围过大，难以把控，生成的代码可能不符合实际需求。

#### ✅ 好用法（遵循"分层设计"和"迭代优化"）
```
用户：我需要一个数据处理系统，先帮我设计整体架构和模块划分。

AI：[给出架构方案]

用户：好的，我们先实现数据采集模块，要求能从 API 和文件两种来源获取数据。

AI：[实现数据采集模块]

用户：运行 quality-gate 检查一下这个模块。

AI：[检查并报告问题]

用户：针对性能问题，帮我优化一下批量处理逻辑。
```

**优势**：逐层推进，每步都可验证，代码质量更高。

### 示例 3：上下文管理

#### ❌ 坏用法（违反"上下文管理"）
```
[对话进行了 50 轮]

用户：刚才那个函数为什么报错？

AI：[不知道你指的是哪个函数，因为上下文已经丢失]
```

#### ✅ 好用法（遵循"上下文管理"）
```
用户：@src/auth/jwt_handler.py 中的 verify_token 函数报错了，
     错误信息是 "Invalid signature"。

     当前上下文：
     - 正在实现用户认证功能
     - 已完成 login 和 register 端点
     - 使用 PyJWT 库

     请帮我排查问题。
```

**优势**：明确指定文件和函数，提供错误信息和上下文，AI 可以精准定位问题。

## 总结

Vibe Coding 的核心是"对话式协作"，而不是"命令式编程"。通过遵循这五大原则，你可以：

- 更高效地与 AI 协作
- 生成更高质量的代码
- 避免常见的陷阱和问题
- 建立可持续的开发流程

**记住：好的 Vibe Coding 是一场结构化的对话，而不是一次性的代码生成。**
