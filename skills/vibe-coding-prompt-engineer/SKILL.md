# Vibe Coding 提示工程师

## 用途

帮你把随口一句"帮我写个 xxx"重写成结构化、高质量的 prompt，让 AI 能更准确地理解你的意图并生成更好的代码。

## 如何触发

你可以这样对我说：

```
帮我优化这个提示词：[你的原始想法]
```

或者：

```
我想让你帮我写个用户登录功能，但不知道怎么说清楚，帮我重写一下提示词。
```

## 5 要素检查清单

一个高质量的 Vibe Coding 提示词应该包含以下 5 个要素：

### 1. 角色（Role）
明确 AI 应该扮演什么角色，例如：
- "作为一名资深 React 工程师"
- "作为一名安全专家"
- "作为一名系统架构师"

### 2. 目标（Goal）
清晰描述要完成什么能力或解决什么问题：
- "实现一个用户登录功能"
- "优化数据库查询性能"
- "修复 XSS 安全漏洞"

### 3. 约束（Constraints）
明确技术栈、框架、性能、安全、规范等限制：
- 语言和框架：Python + FastAPI
- 性能要求：响应时间 < 100ms
- 安全要求：防止 SQL 注入
- 代码规范：遵循 PEP 8

### 4. 上下文（Context）
提供相关文件路径、依赖、现有代码等背景信息：
- 相关文件：@src/auth/models.py
- 依赖库：使用 PyJWT 进行 token 管理
- 现有实现：已有用户注册功能

### 5. 期望输出（Expected Output）
明确你期望得到什么样的结果：
- 完整的代码实现
- 单元测试
- API 文档
- 部署说明

## 优化示例

### 示例 1：用户登录功能

#### ❌ 优化前（模糊、缺少关键信息）
```
帮我写个登录功能
```

#### ✅ 优化后（结构化、信息完整）
```
【角色】作为一名资深 Python 后端工程师

【目标】实现一个安全的用户登录功能

【约束】
- 技术栈：Python 3.11 + FastAPI
- 数据库：PostgreSQL
- 认证方式：JWT Token
- 安全要求：
  * 密码使用 bcrypt 加密
  * 防止暴力破解（登录失败 5 次锁定 15 分钟）
  * Token 有效期 24 小时
- 代码规范：遵循 PEP 8，使用类型注解

【上下文】
- 相关文件：@src/auth/models.py（用户模型已定义）
- 依赖库：已安装 PyJWT、bcrypt、SQLAlchemy
- 现有功能：用户注册功能已完成

【期望输出】
1. 登录 API 端点实现（POST /api/auth/login）
2. JWT Token 生成和验证逻辑
3. 登录失败次数记录和锁定机制
4. 单元测试（覆盖正常登录、密码错误、账号锁定等场景）
5. API 文档（请求/响应格式）
```

### 示例 2：性能优化

#### ❌ 优化前
```
这个查询太慢了，帮我优化一下
```

#### ✅ 优化后
```
【角色】作为一名数据库性能优化专家

【目标】优化用户列表查询的性能，将响应时间从 2 秒降低到 200ms 以内

【约束】
- 数据库：PostgreSQL 15
- 数据量：用户表 100 万条记录
- 不能改变 API 接口
- 需要保持数据一致性

【上下文】
- 问题代码：@src/api/users.py 第 45-60 行
- 当前查询：
  ```python
  users = db.query(User).filter(User.is_active == True).all()
  for user in users:
      user.posts_count = db.query(Post).filter(Post.user_id == user.id).count()
  ```
- 性能分析：主要瓶颈是 N+1 查询问题

【期望输出】
1. 优化后的查询代码（使用 JOIN 或子查询）
2. 必要的数据库索引建议
3. 性能对比数据（优化前后的执行时间）
4. 代码注释说明优化思路
```

2. 单元测试（覆盖边界情况）

## 工作流程

当你请求我优化提示词时，我会：

1. **分析原始提示**：识别缺失的要素
2. **追问关键信息**：如果某些要素不明确，我会主动询问
3. **重写提示词**：按照 5 要素结构重新组织
4. **确认优化结果**：让你确认是否符合预期
5. **执行任务**：确认后，我会按照优化后的提示词执行任务

## 使用建议

### 什么时候使用这个技能？

- 当你不确定如何清晰表达需求时
- 当你的需求比较复杂，担心遗漏关键信息时
- 当你想让 AI 生成更高质量的代码时
- 当你是 Vibe Coding 新手，还不熟悉如何与 AI 对话时

### 两步走策略

建议采用"先优化提示，再执行任务"的两步走策略：

```
第一步：
用户：帮我优化这个提示词：我想做个博客系统

AI：[输出优化后的结构化提示词]

第二步：
用户：好的，就按这个提示词来实现

AI：[按照优化后的提示词执行任务]
```

这样可以确保 AI 准确理解你的意图，避免返工。

## 遵循的原则

本技能严格遵循 Vibe Coding 的核心原则：

1. **意图先于实现**：帮你明确"要什么"，而不是直接跳到"怎么做"
2. **上下文管理**：强调提供相关文件和背景信息
3. **质量前移**：在提示词阶段就考虑测试、安全、性能等质量要求

## 注意事项

- 优化后的提示词可能会比较长，但这是为了确保信息完整
- 如果某些要素不适用，可以省略（例如简单任务可能不需要复杂的约束）
- 提示词优化是一个迭代过程，可以根据实际情况调整
- 不要为了结构化而结构化，保持自然和实用
