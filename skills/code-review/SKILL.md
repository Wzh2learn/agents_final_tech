# 深度代码审查

## 用途

对代码进行深度、全面的审查，包括架构设计、业务逻辑、安全性、性能和可维护性。

## 如何触发

```
请审查 @src/auth/login.py 的代码
```

## 审查维度

| 维度 | 关注点 |
|------|--------|
| 架构设计 | 模块划分、职责单一、SOLID 原则 |
| 业务逻辑 | 逻辑正确性、边界条件、异常处理 |
| 安全性 | 输入验证、注入防护、敏感信息保护 |
| 性能 | 算法复杂度、查询优化、资源管理 |
| 可维护性 | 可读性、命名规范、测试覆盖 |

## 审查报告格式

```markdown
# 代码审查报告

**文件**: src/auth/login.py
**总体评分**: B+ (85/100)

## 优点
1. 代码结构清晰
2. 错误处理完善

## 问题清单

### 严重问题 (必须修复)
1. **安全问题**: 密码未加盐哈希 (第45行)

### 中等问题 (建议修复)
2. **性能问题**: N+1 查询 (第78行)

### 轻微问题 (可选优化)
3. **可读性**: 函数过长
```

## 与 quality-gate 的区别

- **quality-gate**: 快速检查（秒级），常见问题，代码生成后立即执行
- **code-review**: 深度审查（分钟级），架构逻辑，功能完成后执行

## 注意事项

- 先看整体架构，再看关键逻辑，最后看细节
- 提供具体的改进建议，不要只说"不好"
- 按优先级修复：安全 > 性能 > 可读性
