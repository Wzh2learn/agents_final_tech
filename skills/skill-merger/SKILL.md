# Skill 合并器

帮助用户把一堆职责重叠、触发边界模糊的 skill 合并成少量聚焦、边界清晰的 skill。skill 越多、描述越相近，模型越难判断该触发哪一个；合并同类项能显著提升触发准确率和可维护性。

## 核心原则

- **半自动、非破坏性**：先分析、出报告、等用户确认，再动手。合并前把原始 skill 备份到 `skills-backup/<时间戳>/`，绝不直接删除。
- **合并的是"同类项"**：只合并职责真正重叠或高度互补的 skill，不为了减少数量而强行捏合无关能力。
- **透明**：每一步都让用户看到"哪些被合并、为什么、合并后长什么样"。

## 工作流

### 第 1 步：探测 skill 目录

不要写死路径。按以下顺序探测，把找到的都列给用户，让其确认扫描范围：

- 用户级：`~/.claude/skills/`
- 项目级：`./.claude/skills/`（当前工作目录及其上层）
- Qoder 对应的 skills 目录（若用户使用 Qoder，询问其 skill 存放位置）

若探测到多个位置，先问用户对哪个范围做合并。

### 第 2 步：扫描并提取元数据

运行 `scripts/scan_skills.py <skills目录>` 汇总每个 skill 的：`name`、`description`、SKILL.md 行数、`scripts/references/assets` 资源清单。基于输出建立全局视图，避免逐个人肉读取。

若脚本不可用，则逐个读取每个 SKILL.md 的 front matter。

### 第 3 步：识别可合并的簇

基于 description 语义和职责，把 skill 分组。判断"该不该合并"的信号：

- **职责重叠**：两个 skill 做的是同一类事（如都在"处理 PDF"）。
- **触发词冲突**：description 里的触发场景高度相似，模型难以区分。
- **父子/流程关系**：一个是另一个的子步骤，或它们常被连续使用。
- **共享资源**：引用了相同的脚本或参考文件。

**不要合并**的情况：职责不同只是名字像；合并后单个 skill 会超过 500 行且难以维护；两者面向完全不同的用户意图。这类情况在报告里标注"建议保持独立"。

### 第 4 步：产出合并建议报告

用下面的固定结构输出，先给全景再给每个簇的细节：

```
# Skill 合并建议报告

## 扫描概况
- 扫描目录：<路径>
- 发现 skill：<N> 个

## 建议合并的簇
### 簇 1 → 合并为 `<新名字>`
- 成员：`skill-a`、`skill-b`
- 合并理由：<为什么它们重叠>
- 新 description（草案）：<...>
- 资源处理：<脚本/引用如何迁移、是否有命名冲突>
- 风险/需注意：<触发边界变化、可能误触发的场景>

## 建议保持独立的 skill
- `skill-x`：<理由>

## 待用户确认
<列出需要用户拍板的点，例如新名字、是否保留某能力>
```

报告出完后**停下来等用户确认**，不要直接改文件。若有多个簇，按"合并收益"排序建议先做哪个：收益 = 触发冲突严重程度 × 涉及 skill 数量；优先合并"最容易互相误触发"的簇。

### 第 5 步：执行合并（用户确认后）

对每个被确认的簇：

1. **备份**：把该簇所有原始 skill 目录整体复制到 `<skills目录>/skills-backup/<YYYYMMDD-HHMMSS>/`。
2. **写新 skill**：
   - 融合 description：覆盖所有成员的触发场景，去重、消歧，保持"做什么 + 何时用"完整。
   - 合并指令正文：按逻辑重组而非简单拼接；提取公共步骤，保留各自特有分支。
   - 迁移资源：把成员的 `scripts/references/assets` 复制到新 skill 对应子目录；遇同名文件按"来源前缀"重命名并在正文更新引用。
   - 控制篇幅：新 SKILL.md 超过 500 行时，把细节下沉到 `references/` 并在正文加指引。
3. **移除原 skill**：仅在备份成功后，从活动目录移除被合并的原 skill（保留备份）。
4. **更新下游引用**：搜索是否有其它文件按旧 skill 名引用了被合并的 skill，逐一更新为新名。重点检查 `skill-hook-trigger` 的 `routes.json`——其 `skill` 字段可能指向刚被合并的旧名，不更新会让 hook 路由指向不存在的 skill。
5. **回执**：告诉用户新 skill 路径、备份路径、下游更新了哪些文件、以及如何回滚（把备份目录拷回即可）。

## 边界与安全

- 只在用户确认的 skills 目录内操作，绝不触碰工作空间之外的文件。
- 备份未成功则**中止合并**。
- 若某簇只有 1 个成员，说明无需合并，跳过。
- 合并后主动读取新 SKILL.md 校验 front matter 合法（name 合规、description 完整含"做什么+何时用"；语言与原 skill 保持一致，英文 skill 不强制改中文）。
