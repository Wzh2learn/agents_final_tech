# Vibe Coding 上下文管理器

## 用途

管理整个对话/项目中的"上下文状态"，避免 Vibe Coding 时信息散乱：
- 自动列出活跃文件/关键目录
- 建议在合适的时机 @ 文件/总结上下文
- 生成"当前上下文摘要块"，可以粘贴回对话让 AI 接着用

## 如何触发

你可以这样对我说：

```
帮我总结一下当前的上下文
```

或者：

```
我们现在在做什么？有哪些活跃文件？
```

或者：

```
生成一个上下文摘要，我要开启新对话
```

## 核心功能

### 1. 活跃文件追踪

自动识别当前对话中涉及的文件：
- 最近读取的文件
- 最近修改的文件
- 最近讨论的文件

### 2. 关键目录识别

识别项目中的关键目录：
- 源代码目录（src/）
- 配置目录（config/）
- 测试目录（tests/）
- 文档目录（docs/）

### 3. 任务状态追踪

记录当前正在进行的任务：
- 已完成的任务
- 正在进行的任务
- 待解决的问题

### 4. 上下文摘要生成

生成结构化的上下文摘要，包含：
- 项目概况
- 活跃文件列表
- 关键模块说明
- 当前任务状态
- 待解决问题

## 使用场景

### 场景 1：长对话中途总结

当对话进行了 20+ 轮后，信息开始散乱：

```
用户: 帮我总结一下当前的上下文

AI: [生成上下文摘要]

用户: 好的，我们继续刚才的任务
```

### 场景 2：开启新对话前

当你需要开启新对话，但想保持上下文：

```
用户: 生成一个上下文摘要，我要开启新对话

AI: [生成详细的上下文摘要]

用户: [复制摘要，在新对话中粘贴]
```

### 场景 3：多人协作

当你需要把上下文分享给其他开发者：

```
用户: 生成一个上下文摘要，我要分享给同事

AI: [生成包含项目状态、关键文件、待解决问题的摘要]
```

### 场景 4：AI 失忆时

当 AI 忘记了之前的上下文：

```
用户: 你忘记我们在做什么了吗？帮我回顾一下上下文。

AI: [分析最近的对话，重建上下文]
```

## 上下文管理最佳实践

### 1. 主动 @ 文件

在提问时明确指定相关文件：

```
✅ 好的做法:
@src/auth/login.py 中的 verify_token 函数报错了

❌ 不好的做法:
那个函数报错了
```

### 2. 定期总结

建议每 15-20 轮对话总结一次上下文：

```
对话轮次 1-15: 实现用户注册功能
对话轮次 16: 总结上下文
对话轮次 17-30: 实现用户登录功能
对话轮次 31: 总结上下文
```

### 3. 新话题前重建上下文

当切换到新话题时，先重建上下文：

```
用户: 我们现在要开始做权限管理了，先总结一下当前状态。

AI: [总结当前状态]

用户: 好的，现在开始规划权限管理模块。
```

### 4. 使用上下文标记

在对话中使用明确的标记：

```
【当前任务】实现用户登录
【相关文件】@src/auth/login.py
【依赖】用户注册功能已完成
【目标】支持邮箱和用户名两种登录方式
```

## 自动化建议

### 何时建议总结上下文？

我会在以下情况主动建议你总结上下文：

1. **对话轮次过多**: 超过 20 轮
2. **涉及文件过多**: 超过 10 个文件
3. **任务切换**: 从一个模块切换到另一个模块
4. **出现混乱**: 检测到上下文信息不一致

### 建议示例

```
AI: 我注意到我们已经讨论了 25 轮，涉及 12 个文件。
    建议现在总结一下上下文，避免信息散乱。
    需要我生成上下文摘要吗？
```


## 遵循的原则

本技能严格遵循 Vibe Coding 的核心原则：

1. **上下文管理**: 这是本技能的核心目标
2. **分层设计**: 按层级组织上下文信息
3. **迭代优化**: 持续更新和完善上下文

## 注意事项

- 上下文摘要不是一成不变的，需要持续更新
- 不要过度依赖上下文管理，保持对话的自然流畅
- 上下文摘要应该简洁明了，避免信息过载
- 定期清理过时的上下文信息
