# 实验尸检 — Experiment Autopsy（通用版）

> **设计哲学**：每个实验都是一次对假设的检验。信息量取决于分析深度，而非结果数字本身。跑 100 个实验每个只看指标 → 不如跑 10 个每个做完整尸检。
> ⚠️ 弹性声明：以下维度/模式是思考框架而非清单，按当前实验的实际形态增删维度、自由发散归因。

## 输入

实验日志/结果表、配置差异（vs baseline 改了什么）、或现象描述（"辅助 loss 暴降但主指标不动"）。

## 核心流程：4 步尸检法

### Step 1: 解剖——多维度拆解（不要只看最终指标）

至少覆盖：① 主指标 vs baseline ② 训练动态（loss 轨迹形态）③ 辅助指标 ④ 参数健康度（norm 演进/坍缩/饱和）⑤ 训练稳定性 ⑥ 收敛速度（前后期斜率）⑦ 工程观测（速度/显存/NaN）。每个维度给出"观测值 / vs Baseline / 判断"三列表。

**关键心法**（通用模式，按现场扩展）：
- 辅助 loss 大幅改善但主指标不动 → **信息瓶颈**：该模块的改进没连通到预测路径
- 主指标先降后追平 → **早期学习被干扰**：新 loss/模块增加了优化难度
- 参数 norm 持续增长未饱和 → **还有训练空间**：epoch 可能不够
- 某 loss 在训练阶段切换时飙升 → **输入分布突变**：loss 目标与新解冻参数不匹配

### Step 2: 诊断——提炼 1-3 个核心洞察

洞察标准：**非显而易见**（"指标降了所以方法不好"不是洞察）、**可泛化**（能指导后续设计）、**可验证**（能推导新实验）。

模板：`洞察一句话 → 证据（Step 1 哪些观测）→ 机制（架构/梯度/信息论解释）→ 推论（若成立则 X 也应成立）→ 验证（跑什么实验确认）`

**通用根因模式**（快速匹配起点，鼓励超出此表归因）：

| 现象 | 常见根因方向 |
|------|---------|
| 辅助 loss 改善 + 主指标不变 | 容量竞争 / 信息瓶颈 / 优化目标与评估目标脱节 |
| 主指标先降后追平 | 多任务干扰 / 优化路径冲突 |
| 参数 norm 坍缩到常数 | 梯度断裂 / 学习率过小 |
| 门控/权重全 0 或全 1 | 初始化偏差 / 正则不足 → 塌缩 |
| 训练末期 loss 震荡 | 学习率过大 / batch 内样本冲突 |
| 新 loss 加了完全没动 | detach 过度 / 梯度路径被切断 |
| 两处同时改善但总效果不变 | 改善互相抵消 / 都不在瓶颈上 |
| 离线代理指标与线上/全量评估背离 | 代理指标假设失效（分布/口径/BS 差异） |

### Step 3: 交叉验证——用精读笔记扩展思路（本 skill 独特价值）

拿洞察去精读笔记找理论支撑或反例。搜索策略：① 关键词直接搜 ② **对立面搜**（我们发现 X 无效 → 搜"X 有效"的论文，条件差异就是下一步实验方向）③ 机制类比搜（不搜相同技术，搜类似机制）④ Web 补充（arXiv 近半年）。

输出：`论文 → 相关段落 → 关系（支持/反驳/条件性）→ 条件差异（数据规模/模型容量/任务类型）→ 可借鉴`

本域搜索路径：`docs/reading/`（HSTU 系精读）+ `../paper/reading_notes/`（77 篇论文库，入口 INDEX.md，只读）。

### Step 4: 行动——产出可执行的下一步

三类：新实验 / 代码改动 / 设计记录。每个行动含：描述、类型、优先级（P0/P1/P2）、依赖、预期（成功/失败分别意味着什么）、命令（实验给出批次定义）。

## 多实验对比模式

2+ 实验时：统一维度对齐一张表 → 放大最大分歧点 → 交叉推理归因到具体组件 → 排序哪个方向最值得深挖。

**增补手法（2026-07-31，源自 #16-#20 批次实践）**：
- **tradeoff 前沿共线检验**：把各实验点放到 (收益, 代价) 平面（如 recall vs popular），看是否近似共线——共线 = 各旋钮在同一条 tradeoff 线上滑动（无免费甜点），偏离 = 存在机制不同的独立杠杆。这是区分"换汤旋钮"与"真手术刀"的最快判别法
- **持平实验反推噪声尺度**：批次里的持平实验（如 wd0/linear 与 baseline 差 0.15-0.31pp）是免费的噪声标定，用它校验判据带宽（±1pp）是否合理，也防止把噪声当信号解读

## 消融批次判读纪律（2026-07-31 增补）

**先裁决，后尸检，最后预注册**——三段缺一不可：

1. **裁决段**：严格按 Goal Card / INSTRUCTION 的**预注册判据**逐实验定 verdict（成功线/持平带/失败线），**禁止让结果数字反过来定义成功**（反例：#18 globalneg8 recall 0.3403 全场最高被称"新最佳"，但对锚 v1 +0.59pp 落 ±1pp 持平带内，按预注册判据应判"剂量收益不显著"——两种定性导向完全不同的下一步）
2. **尸检段**：走上面 4 步（HSTU 域的 Step 1 维度基准 = TREND 14 项 + 五件套 + 训练动态曲线；判读锚与标定结论见 `docs/评估体系全貌.md`——排序族方向可信幅度 ~0.67 折、构成族方向不可靠须 DataWarehouse 终判）
3. **预注册段**：分析产出的机制假设，必须转成**对下一批实验的数值预测**并落盘（如"按共线内插 α=0.25 → recall ~0.324 压线"），出数后对答案——预测中 = 机制假设升级为结论；预测偏 = 偏离方向本身就是新信息

## 反模式提醒

| 反模式 | 正确做法 |
|--------|---------|
| 指标降 → 方法不行 pass | 分析 WHY：方法本身 vs 超参/训练策略/数据 |
| 指标涨 → 方法好收工 | 涨在哪个子群？可持续吗？ |
| 只看最终指标 / 只和 baseline 比 | 看完整曲线形态；和所有已跑实验横向比找趋势 |
| 洞察停在"A 和 B 不同" | 追到"为什么不同"和"意味着什么" |
| 论文说有效就照搬 | 检查条件差异 |
| 一个实验验证一个想法 | 一个实验应同时排除/确认多个假设 |
| 只裁决不尸检（批次跑完只回填 verdict 就收工） | 裁决只是第一段；机制发现和预注册预测才是批次的主要信息产出 |
