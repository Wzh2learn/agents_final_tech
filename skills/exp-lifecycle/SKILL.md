# exp-lifecycle — 实验生命周期五阶段闭环编排器

> 判读 → 设计 → 工程 → 审计 → 治理，带反馈环的一键流程。
> 本 skill 是**编排层**：各阶段方法论复用域内既有 skill，本层只定义阶段衔接、产物契约、拍板门与循环条件。
> 立法：2026-08-20（distilled from multi-day practice: judgment→design→engineering→audit→governance full-chain validation）。

## 何时触发

- 用户说"跑 lifecycle / 走闭环 / 一键流程 / 对 X 实验完整处置"
- 实验出数后（从判读进入）
- 工程交付后（从审计进入）
- 积累数日后（从治理进入——知识卫生）
- 支持从任意阶段进入（实际常为跳跃式），但**环内顺序不可乱**

## 流程总览

```
┌─────────────────────────────────────────────────────────────┐
│  [1 判读] ──P1──▶ [2 设计] ──P2──▶ [3 工程] ──▶ [4 审计]     │
│  autopsy        design         Claude Code     repo-audit    │
│  预注册对照      预注册线写死     实现+单测       fresh eyes   │
│     ▲                                            │          │
│     │                                            ├──🔴>0──▶ │
│     │                                            │   回[3]修 │
│     │                                            ↓ 🔴=0     │
│  [5 治理] ◀──────────────────────────────────────┘          │
│  neat-freak：修正批+文档同步+memory 立法案 ──P3──▶ 收口       │
│     收口物 = supersede 链更新 = 下轮 [1] 的弹药               │
└─────────────────────────────────────────────────────────────┘
```

## 拍板门（agent 必停，标注"待 user"后停轮）

| 门 | 位置 | 内容 | 依据纪律 |
|---|---|---|---|
| **P1** | 判读后 | 判读结论终裁（预注册"只判读不裁决"） | 预注册纪律 |
| **P2** | 设计后 | 预注册线/配置/排期确认（写死进 runner 前） | 消融单变量纪律 |
| **P3** | 治理尾 | memory 立法（新条目/删旧条） | memory SSOT 惯例 |

例外：紧急 🔴 修复可代执行，commit 标注"代执行待追认"。

## 阶段定义（输入→方法→产物→出口条件）

### [1] 判读
- **方法**：`experiment-autopsy` skill（4 步尸检/多实验对比模式）；重要结论加**双 agent 对照**（fresh eyes 三段式：先独立→self-diff→对照，隔离禁读清单见 goal 卡实践）
- **输入**：实验出数（local-eval/proxy-eval/online-eval any layer）+ 预注册线 + 历史锚
- **产物**：判读报告（预注册线对照表 + 机制解释 + 置信度）+ **supersede 链增量**（本轮推翻了什么旧结论）
- **出口**：判读落档（experiment log entry + HANDOFF 心跳）→ P1
- **铁律**：锚同源核验（人群/池/GT 日三件套）；判读实验必读原始日志勿只读汇报表
- **两速制**（2026-08-26 增补）：执行分支选择可快（错=一夜 GPU 成本），**结论叙事（终判/降级/形态候选）必须过定谳件才落「成立」，定谳件在途一律标「候选/待谳」**（某次凭在途状态越权定案的教训）；判读者报告条件状态，裁决权在 user
- **判读三级分流**（同日增补）：A 级（战略叙事/跨实验综合/上线建议）审计后落档；B 级（单实验档位）速查卡执行+落档后抽查；C 级（执行态记录）即时刻
- **判读卡预制**（同日增补）：出数前预制填空式判读卡（数字+线+档位→动作），出数后照卡执行，消除现场推理（某个模式变体的速查卡案——5 分钟判读代替现场纠结）

### [2] 设计
- **方法**：`research-driven-design` skill（文献检验 + 前置数据依赖）
- **输入**：P1 通过的判读结论 + goal 卡 §五·八 方向清单
- **产物**：设计卡（或 goal 卡行）+ 预注册判读线（阈值写死）+ 成本/排期 + **反向清单检查**（新方向是否踩已证伪区）
- **出口**：预注册线入档 → P2 →（can dispatch to remote server / coding agent）

### [3] 工程
- **方法**：Claude Code 实现（或主 agent 小修）；配置类改动先查既有 runner 逐参数对照（某对照实验三连失败教训）
- **产物**：代码 + 单测（含回归用例）+ smoke 证据**落档日志**（勿只写 commit message——审计 🟡 教训）
- **出口**：单测全绿 + commit（无 push 依赖时等审计后一起）

### [4] 审计
- **方法**：`repo-audit` skill + fresh eyes（审计者与实现者分离；发现与 commit message 冲突时以代码实态为准）
- **输入**：[3] 的 commit + 验收清单 + 已知风险点
- **产物**：分级发现表（🔴 会断/会错 / 🟡 风险遗漏 / ⚪ 观察）+ 修复建议
- **出口**：🔴=0 → [5]；🔴>0 → 回 [3]（修复后**轻量重审计**：只验 🔴 项 + 跑单测，不必全量重审）

### [5] 治理
- **方法**：`neat-freak` skill（先盘点后修改、supersede 留声明、单一权威层）
- **产物**：① 🔴🟡 修正批（单 commit）② 文档面同步（结构/路径/口径——机械替换全域 grep）③ memory 立法案（新铁律一句话草稿 × N → P3）④ **supersede 链更新**（本轮 全部被推翻结论 → 更新至链表，作为下轮 [1] 的排雷弹药）
- **立法落代码不落文档**（2026-08-26 增补）：防坑立法的执行层必须进代码/runner 自检门——只写文档的立法必复发（「下载完成判定等 Succeed 行非文件数」三犯案、pkill 自匹配四犯案；立法则问一句「这条的执行点在哪段代码」）
- **出口**：P3 通过 → 收口（HANDOFF 心跳 + experiment log final state）

## 反馈环规则

1. 审计 🔴 → 工程修复 → 轻量重验（只验 🔴 + 单测）→ 再进 [5]
2. 治理中发现设计缺陷（非实现 bug）→ 回 [2] 重设计（罕见，标注"设计返工"）
3. 判读被 offline-eval 终审推翻（local eval coarse-screen misjudgment）→ 回 [1] 重判读 + supersede 链记录

## 产物契约速查（阶段交接物）

| 从 → 到 | 交接物 | 必含字段 |
|---|---|---|
| 1→2 | 判读结论 | 方向/幅度/置信度/机制/supersede 增量 |
| 2→3 | 实现规格 | 配置逐项/单测验收/边界（不做什么） |
| 3→4 | 审计输入 | commit hash/验收清单/已知风险 |
| 4→5 | 分级发现表 | 文件/问题/证据/建议动作 |
| 5→1（下轮） | supersede 链 | 旧表述/现行结论/出处 commit |

## 边界

- 本 skill 不替代各阶段 skill 的方法论，只做编排
- 拍板门不可跳过（P1/P2/P3）；紧急代执行必须标注追认
- 全程 git 纪律照域规：显式列路径/单 commit 原子/commit message 真实性
- when remote jobs are in-flight, respect scheduling discipline and lock protocols
