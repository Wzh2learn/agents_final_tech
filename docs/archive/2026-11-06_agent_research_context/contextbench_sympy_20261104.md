## SWE-ContextBench：真实问题对与经验时间边界（2026-11-04）

为从 benchmark 构造需求扩展到真实 GitHub 问题，取得 [SWE-ContextBench 论文](https://arxiv.org/abs/2602.08316)、[原作者代码与轨迹](https://github.com/jiayuanz3/SWEContextBench)和[数据](https://huggingface.co/datasets/jiayuanz3/SWEContextBench)。Lite 公开切片为 300 个经验任务、99 个相关目标任务；目标与经验连接表在这一切片中形成 102 条关联，分布在同一仓库。对 102 条记录按数据字段比较 `created_at`：源早于目标 33、相同 28、晚于目标 41；这些仅是记录时间的元数据，不足以证明历史对目标求解时真实可用。完整数据卡的 1,007/362 与论文 v3 的 1,100/376 数量不一致，原因未核实，不影响上述固定 Lite 切片的实际计数。

**已发现需要控制的真实边界**：`django__django-16910` 的公开源轨迹生成于 2025-12，早于目标 base 的历史问题却不等于当时生成的轨迹。该轨迹第 90–91 行通过 `git log --all` 得到了目标 `#35356` 的修复提交摘要 `83f5478225`；API 显示目标 base 位于该修复之前，而源 PR merge 本身是目标 base 的祖先。这证明该条轨迹包含目标之后的提交元数据，不证明读取了完整补丁或目标 Agent 已使用该信息。其余五个候选未发现目标 ID 字面标记，不能据此证明语义层面无泄漏。论文附录给出的求解设置要求移除 Git 历史；该单条发布轨迹的观察不能外推为作者所有运行或作者结论均受污染。

**下一步实验资格**：在新建的隔离历史版本目录中，优先让本项目 Agent 从源 base 重新执行并形成经验；不挂载目标 patch、目标测试或可看到后续历史的 `.git`，执行后用独立环境验证。目标比较至少包含无历史、原始历史、普通摘要/检索、经验或 skill 及信息/预算匹配的简单策略，记录形成、检索、验证和目标执行成本。数据集卡标注 MIT，但代码仓库根目录未找到许可文件、具体项目许可证也需分别检查；源轨迹暂不再分发或用于训练。官方镜像声明 `linux/amd64`，GB10 为 ARM；先做适配环境的正负控制，再决定可运行任务，不能称为官方镜像复现。公开题目与模型预训练暴露未知。

**SymPy 自然问题的 ARM 环境资格**：固定源 `sympy__sympy-19487`（`sign` 改写）和不同题面的目标 `sympy__sympy-19484`（`sign` 与绝对值的化简），分别从数据指定的 GitHub commit 下载无 `.git` 的源码快照，保留原项目许可证及归档哈希。研究者侧[资格脚本](../../../research/agent_frontier_portfolio_20261029/qualify_swe_contextbench_sympy_20261104.py)把 benchmark 的测试补丁与参考修复仅用于隔离控制目录，未向 Agent 提供。目标相关测试在原始源码失败、参考修复后通过；源任务也呈现同样的失败→通过，另选源 1 项、目标 2 项原有回归检查均通过。该结果只覆盖选择的检查，不等于完整 SWE-bench 测试集或官方镜像复现。

**首轮 Agent 合同（运行前）**：[运行器](../../../research/agent_frontier_portfolio_20261029/run_swe_contextbench_sympy_20261104.py)先在源问题、再在目标问题分别执行一次无历史 Agent；均使用完整 issue 原题、对应历史 base、同一 OpenCode 与本地 Qwen、只读依赖和兼容 shim，不提供另一问题、历史经验、目标测试补丁或参考修复，也不挂载 `.git`。每次最多 48 个 HTTP 请求、6 MB 请求体及 1,800 秒；代理统一转发 seed `7201` 和温度 `0.2` 并逐请求记元数据，实际后端采样行为仍未知。Agent 结束后在另一份候选副本上加入 benchmark 测试补丁，运行上述选定的目标/回归检查；若测试补丁与 Agent 对测试文件的修改冲突则记 `UNRESOLVED`。这是两题各一次的开发探针，研究者已看过问题与测试，不是盲法或完整官方评估。源输出及其独立反馈只有在实际形成后才用来设计经验臂，形成、目标执行和验证成本分开记账。
