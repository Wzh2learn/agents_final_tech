## SWE-Skills-Bench / aiohttp：真实项目执行资格（2026-11-04）

[SWE-Skills-Bench](https://github.com/ControllableModel/SWE-Skills-Bench) 的 `asyncio-patterns` 在真实 aiohttp 固定提交 `c41e3b6ea2eccdeb6a32f9755525aecac48ba265` 上提供相邻的两项公开需求：受限并发映射与异步任务池。它们是 benchmark 为真实仓库编写的需求，不冒充仓库历史 issue 或两个独立项目；官方固定 skill 可作为公开强对照。研究者已阅读两题和测试；测试只在 Agent 执行后挂载，不称盲选或官方 harness 复现。benchmark 快照 `4d3450d9216a590a8726fcb3604b5143daca776b`，项目仓库声明 MIT，aiohttp 固定快照为 Apache 2.0；各自许可按原项目保留。

GB10 ARM 使用隔离 Python 3.12 镜像与只读依赖。资格首轮因 Docker 对镜像 SHA 的解析失败；后续发现容器权限及 aiohttp 锁定的 pytest 插件与本地环境不一致。逐次日志均保留。按项目锁定的 pytest-asyncio 1.4.0、pytest-timeout 2.4.0 修复后，[资格脚本](../../../research/agent_frontier_portfolio_20261029/qualify_swe_aiohttp_20261104.py)的研究者手写正例分别通过公开测试 `15/15` 和 `14/14`，空实现分别为 `1/15` 和 `0/14`；正例参考了题面与公开测试，是环境可用性和简单强基线，不是隐藏 gold 或 Agent 成绩。资格回执 SHA-256 `54d45a4ee7b117ec8c889a63b585b4481577187a3daf6440dab063ce63d33aca`，镜像 ID 和插件哈希见回执。事后环境查询显示 pytest `9.0.1`、pytest-aiohttp `1.1.0`，与该仓库完整测试锁定的 `9.0.3`、`1.1.1` 不同；其余依赖来自只读挂载的项目 venv，未整体做不可变快照。因此该环境是通过正负控制的本地适配，不等同官方镜像或完整锁文件复现。

**下一组开发比较**：先让本地 OpenCode Agent 解决并发映射任务并记录真实源轨迹与结果；再在相同固定仓库和任务池目标上比较无历史、来源轨迹历史、由来源轨迹与反馈生成的 skill、公开 `asyncio-patterns` skill。各条件只用当前需求、已授权的源材料和相同工具/上限，任务完成后挂载独立测试；研究者手写正例不提供给 Agent。若 source 或 target 存在环境失败先修环境并保留旧账，不能当作方法优劣；每种条件的测试通过、实际读取和生成/使用成本分开记。首轮各一次仅为开发，若有区分信号再针对跨来源、重复和预算匹配扩大。

**首轮适配事故**：源、目标各运行一次后，发现复制仓库时保留的根目录权限使 post-run 测试无法创建临时 driver；因此这两次的上游测试分数不作有效 Agent 成绩。两次 Agent 分别触及 POST 字节总量及请求数上限，属于资源边界而非已确认的能力失败。旧 raw 和现场不覆盖，实际累计 46 POST、706,067 报告 tokens（其中缓存读取 607,523）、2 次受限请求。后续运行器在复制后恢复可写目录、用同一更宽松上限重跑，并与原始现场分开；如仍出现接口或预算故障，继续单独报告。

**修复后进行中**：源 Agent 正常退出并通过 `15/15`；原输出在再次验证前后哈希未变。根据 25 个真实源工具动作、源函数和仅含源检查结果的反馈生成一份 skill，源目标之外的数据未提供给生成器，使用 1 次 POST、14,324 报告 tokens。生成请求在调用时只记录了哈希，事后依据源历史与同一构造过程重建请求并验证哈希一致，不能说原始请求当时已落盘。目标无历史 Agent 正常退出，公开检查为 `12/14`；其中一项涉及已捕获任务异常在退出上下文时再次传播，另一项为 Agent 自写测试套件未通过，后者需要区分测试本身与实现问题。其最后一次模型输出以 `length`、8,192 output tokens 结束，不能把退出码 0 等同无截断。源历史、生成 skill 与公开 skill 对照正在按同一设置推进，不能据当前单次结果断言方法收益。

**基于已观察结果追加的开发对照**：源历史组本次 `6/14` 且触及请求上限；直接使用生成 skill 为 `12/14` 且同样触及上限。为探索旧经验的条件适配，追加两种各一次的规划：同一模型各用一次调用、相同输出上限生成（a）仅依当前题目的中性计划，（b）依据当前题目筛选源生成 skill 的计划；随后两条目标 Agent 使用同一仓库、工具、请求上限和测试。两次规划的信息量与实际 token 不同，不称严格等 token；两条计划都不读取目标测试或参考，保留计划生成与实际执行成本。目标规划是事后依据前面面板提出的开发实验，不称预注册或新方法确认。若中性计划追平，额外规划可解释收益；若条件计划引用旧路径或与当前要求冲突，原样保留并分析，不手工修成优势结果。

**全部目标条件及额外复核**：各格均为一个已曝光项目/任务的单次运行，`14` 个检查不是 14 个独立任务。原样记录被拒绝请求与输出截断；以下 3 项独立行为检查是看到首批产物后依据目标需求补做的开发探针，正例全部通过、空实现不可导入，不能作为预先冻结的泛化评估。
