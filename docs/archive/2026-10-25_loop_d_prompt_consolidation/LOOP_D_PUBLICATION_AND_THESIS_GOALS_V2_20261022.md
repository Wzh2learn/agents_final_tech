## 5. G2：研究什么证据足以确认变化任务真正完成

### 5.1 重新定义待检验假设

当前研究问题是：在允许合理等价实现、缓存与回退的合同下，增强行为测试之外的证据，何时能减少错误放行或错误拒绝，代价是什么？

区分三件事：**目标调用发生、目标结果影响后续计算、完整迁移符合任务要求**。它们不能互相替代。先根据上游任务意图明确必须完成的变化；若任务只要求行为等价，就不能擅自追加必须消费某个依赖的要求。

先把审计反例加入回归：调用 detector 后丢弃返回值，再独立尝试 UTF-8/Latin-1，旧判据仍放行。新判据需能拒绝或诚实标未决，而非仅为这一段代码加特判。

### 5.2 两件事并行，避免一直停在旧面板

**方法开发：**

- 将现有 enhanced behavior 单独纳入比较，与 basic behavior、静态合同、候选动态/消费证据分别报告。原仓库测试与单函数开发样例分清，不把 UTF-8 单例的表现叫作原仓库全部行为测试表现。
- 自主尝试同输入合法返回值干预、运行时依赖替换、动态追踪、数据流或其他可核查方法；不预定一定采用因果追踪。
- 先证明干预作用于真实执行路径，且没有破坏合同允许的行为。未观察到输出变化可能来自缓存、等价返回值、合法回退、输入不足或干预失败，不能直接判未消费。
- 在真实模块或保留依赖关系的执行单元中检查 import/helper/wrapper/alias/adapter/动态导入，避免预注入全局变量掩盖模块缺陷。能力不足的形式保留 UNRESOLVED。
- 让独立审查者基于冻结合同构造方法作者未见的控制；原已见十例永远属于开发控制。

**真实任务扩展：**

- 优先复用 PyMigBench 的 36 条预检、33 条来源审计、可恢复环境、NtripBrowser/DateTimeRange 记录；从最可能有信息增益的真实 commit 开始。
- 尽早取得至少一个不同于旧 NtripBrowser 的新真实任务执行观察，再逐步增加机制与来源覆盖。这是本阶段扩展动作，不是用一个新任务认证泛化。
- 环境按任务需要冻结 Python、依赖、传递版本、tzdata、时区、系统因素及测试合同；不要求每个来源都强行复活。先验证 parent/parent、gold/gold 和合理环境/错误控制，再解释候选失败。
- 允许少量真实模型 scout，暴露自然错误、合法等价实现与合同缺口；不要求收齐确认集后才允许探索。先准备必要任务合同，开发后若改合同则标版本并另留确认对象。
- 不限于 API 改名：可以探索依赖替换、返回值/默认值变化、异常与回退、资源/环境变化、数据或规则变化。来源切换由信息价值决定。
- 若模型普遍成功，针对有科学依据的困难切片或其他模型/工具设置诊断；不能只不断增加同类成功样本。
- 困难切片及按错误筛选的样本标为诊断性选择，保留候选来源、纳入/排除与资格失败。未经相应抽样设计，不据此估计自然错误率或总体模型表现。

### 5.3 参考、指标与确认

- 任务意图绑定可追溯上游材料；候选标签根据实际代码与合同，不能按 BASE/PROSE/STRUCTURED 名称赋值。
- 参考至少允许 VALID / INVALID / UNRESOLVED，环境无效另列；参考应独立于被比较 verifier。AI 辅助审查保留证据身份，不强行等待不存在的人工专家，也不自称人工 Gold。
- 自然模型输出、人工控制与人工 mutant 分开统计，不用合成比例估计自然错误率。
- 分别报告行为、结构、运行时证据、最终决策、误放行、误拒、未决与成本；单一 hybrid pass 不能掩盖各组成项的失效。
- 在相近覆盖与风险下比较增量；按 commit/repository/family 等适合的独立单位处理重复候选，不能把同一任务多次输出当多个独立任务。
- 开发阶段允许快速探索；确认前冻结合同、方法、比较、主要估计量及停止/精度规则，再取未用于调参的新对象。已经看过的任务不得恢复“未见”身份。
- 样本量依据机制覆盖、效应与区间精度决定。“至少八个 families”撤回为硬门；任务数不是创新认证。

### 6.1 先让动作真实发生

允许基于真实执行日志离线重放策略，须说明顺序依赖、缓存、状态变化及适用假设。有副作用的动作不能当成独立常数查表；缓存命中和首次环境构建成本分别说明。

### 6.2 强对照与主要判断

复用同一套动作、任务事实、权限和参考，比较：不重验证、always-defer、合理短路的 full revalidation、预先固定的简单顺序、简单成本/覆盖规则、最强单一动作/固定组合，以及候选策略。可合并真正等价的对照并解释，不用重复臂扩大规模。

环境预检失败时采用合理短路，不虚构后续有效观测；未执行动作不得虚计费用，实际发生的失败、误执行与环境构建成本仍照实记录。G2/G3 的 verifier 结果必须来自同一实现/证据，不能重新手填 alias/wrapper 的失败来制造静态误拒。

先问动作是否互补，再问策略是否必要。主要评估相近错误放行风险与覆盖下的真实成本；分别报告误放行、误拒、未决、环境阻断、覆盖分母、动作数、wall-clock、模型/计算消耗与风险取证成本。对未知或环境无效对象的错误放行也要呈现。

“与 full 决策一致”仅为辅助指标，full 本身也可能错。正确拒答与成功完成分开；小样本零错误不能声称风险相同。任务、方法和成本重复层级要明确。

### 6.3 可以发展的方法与替代方向

有真实互补性、稳定差异和可解释机制后，再选择规则策略、检索、成本敏感选择、概率校准、学习型方法或其他机制。无需预定复杂 planner 胜出，也不要求先证明“只有训练能解决”才允许训练。

若简单固定策略已经足够，停止复杂策略候选并保留可复核边界；判断其是否有新科学发现，不能自动把负结果认证为第三贡献。必要时自主改线：

- **条件化经验/证据有效期**：过去正确的证据在依赖、规则或环境变化后，何时可以复用、需要失效或重新获取？
- **最低充分证据与可靠未决**：哪些组合足以作出受限决策，何时必须保留未知，如何校准覆盖—风险？
- **机制定位与修复选择**：真实失败中，依赖/执行 trace 是否比更多通用反馈更能改变诊断和动作？

这些是待筛选问题，不要求三条全做。根据现有真实错误与近邻工作选择最有希望的一至两条 scout。MA-CERD、历史经验和变化任务材料可复用；旧已饱和面板与已使用 test 不变成新确认集。

**G3 本次出口：**真实动作、可观察风险信号与成本记录，强对照下的必要性判断，以及继续/停止/替换方向的证据。若换线，至少有实际探针和可证伪新问题，不能只提交新标题。
