# M1/M2 联合数据闭环计划

**决策日期：2026-07-22。** 本文定义角色 B 在 GB10 上的数据、模型、评测和微调主线。M1 与 M2 不是两个独立任务，而是一条共享文档、证据和指标的端到端链路。

## 1. 目标链路

```text
原始 PDF/图片
  -> M1 OCR、版面/表格恢复、规则结构化
  -> 统一文档表示、切分和现有知识库入库
  -> M2 检索、重排、带证据问答和无证据拒答
  -> OpenCode 主协调、M1、M2、校验 Agent
  -> 收集可复现轨迹，形成 SFT/DPO 数据
```

现有 Web、`RAGService`、PGVector/BM25 和来源追溯仍是唯一知识底座。OpenCode 通过 MCP 调用任务级工具，不另建向量库。GB10 第一版让多个逻辑 Agent 共用一个生成模型服务，视觉、Embedding 和 Reranker 按需加载。

## 2. 数据集决策

### 主数据集：TAT-DQA

TAT-DQA 同时提供金融 PDF、带坐标的解析 JSON、问答、答案、计算过程和证据块映射，许可证为 CC BY 4.0，是第一版联合链路的唯一主数据集。

- 官方说明：https://nextplusplus.github.io/TAT-DQA/
- 官方下载：https://drive.google.com/drive/folders/1SGpZyRWqycMd_dZim1ygvWhl5KdJYDR2
- 原始规模：2,758 份文档、3,067 页、16,558 道问题。
- 本地数据目录：`~/wzh/datasets/tat-dqa/`，不得提交 Git。

固定 `joint-v1` 子集为 100 份文档、最多 500 道问题：60 份训练、20 份验证、20 份测试。必须按文档划分以避免泄漏，固定随机种子 `20260722`，并尽量平衡 `span`、`spans`、`arithmetic`、`counting` 和 comparison 样例。测试集在完成方案冻结前不得用于 Prompt、SFT 或 DPO 选择。

### 补充集

| 数据集 | 小样本 | 用途 | 使用边界 |
| --- | ---: | --- | --- |
| XFUND 中文 | 50 份表单 | 中文 OCR、键值抽取，并模板化生成约 150 个问答 | CC BY-NC-SA 4.0，仅非商业科研 |
| FinanceBench | 10-15 份 PDF、30-50 题 | 长金融报告、跨页检索、引用和拒答 | 数据许可证不清晰，只做内部评测，不进入微调 |

暂不下载完整 PubTables-1M、FinTabNet、FinQA 或 DocVQA。只有联合基线证明表格恢复、数值推理或通用扫描件是明确瓶颈时，才补对应单项数据集。

## 3. 数据产物

公开原始数据、模型权重、渲染页面、索引、日志和模型原始输出均留在开发机。Git 只保存：

1. 下载和校验脚本；
2. 确定性抽样脚本及测试；
3. 公共样本 ID、split、问题类型和许可证组成的 `manifest.json`；
4. 不含原始正文的聚合指标和脱敏失败分类；
5. 数据卡、运行命令和实验记录。

每个样本必须保留 `dataset_id`、`document_id`、`page_no`、`question_id`、`answer_type`、`source_block_ids`、`split` 和许可证来源。M1 产物还要保留解析器、模型版本和页面坐标；M2 结果保留检索 chunk、排序分数、引用和拒答原因。

## 4. 基线与指标

第一轮只跑未微调模型，冻结基线后再微调。

| 层级 | 主要指标 |
| --- | --- |
| M1 解析 | OCR 文本相似度、证据块覆盖率、表格结构可用率、耗时、峰值显存 |
| M1 结构化 | JSON/Pydantic 通过率、字段 F1、来源坐标完整率、人工修正率 |
| M2 检索 | Recall@5、MRR、证据块命中率、Rerank 增益 |
| M2 回答 | Exact Match/F1、数值准确率、引用命中率、无证据拒答率 |
| 联合链路 | 端到端答案准确率、OCR 错误传播率、总延迟、失败阶段分布 |
| Agent | 工具选择成功率、步骤完成率、无效调用数、重试次数 |

优先做三组对照：官方解析 JSON 上的 M2 上限、传统 PDF 文本提取链路、GB10 OCR/VLM 链路。这样才能区分错误来自 M1、检索还是生成。

## 5. SFT、DPO 与多 Agent

SFT 仅使用训练 split，目标格式包含答案、引用证据和必要的计算过程；同时记录正确的 MCP 工具轨迹，用于工具调用 SFT。验证和测试 split 不进入训练。

DPO 不靠随机篡改答案批量伪造。先让基线模型为训练问题生成多个候选，再依据答案、算式、证据和引用校验选出 chosen/rejected。第一轮目标为 300-500 条 SFT 和至少 200 对真实失败 DPO。

多 Agent 顺序为主协调 Agent、M1 文档 Agent、M2 问答 Agent、证据校验 Agent。单 Agent 联合链路达到数字基线后才启用自动委派；多 Agent 的首要对照是相同模型下单 Agent 与多 Agent 的质量、延迟和调用成本差异。

## 6. 开发机执行顺序

1. 只读检查 Git、磁盘、GPU、网络和现有 tmux，不假定服务仍运行。
2. 实现 TAT-DQA 下载说明、完整性校验、确定性抽样器和单元测试。
3. 下载到 `~/wzh/datasets/tat-dqa/`，生成 `joint-v1` manifest；下载前先报告预计空间，失败时不无限重试。
4. 将 PDF 页渲染到本地派生目录，接通 Vision MCP -> 统一文档表示 -> 现有知识库。
5. 在官方解析 JSON 上跑 M2 上限，再跑真实 M1 -> M2 联合基线。
6. 固定指标和失败样例后，准备 SFT；基线真实错误积累后再准备 DPO。
7. 最后验证 OpenCode 多 Agent 自动委派，并把冻结接口与数据口径交给工程同学。

阶段完成标准不是“数据已下载”，而是固定 manifest 可复建、联合链路可复跑、指标可解释、训练与测试无泄漏。
