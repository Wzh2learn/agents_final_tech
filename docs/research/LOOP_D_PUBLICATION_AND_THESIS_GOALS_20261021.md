### 6.1 从有价值反例走向可检验问题

当前有效观察是：某真实迁移的 BASE 通过 7 个既有本地测试，但未导入的旧 detector 调用被异常捕获，UTF-8 回退仍满足 fixtures。它说明这组行为测试没有识别目标迁移未完成。

这里有三个必须修正的设计问题：BASE 没有得到同样明确的目标依赖要求；prose/structured 原子事实量不同；AST 扫描的 import/call presence 尚未证明可达性、作用域或实际结果消费。不能以此声称模型明知合同却违反、结构化表示胜负，或静态结构检查充分。

### 6.2 允许自主选择的研究机制

优先考虑**基于目标依赖实际消费的合同验证**：结合真实变更意图、行为测试、必要静态分析和有针对性的运行时干预，区分行为保留、迁移完成与等价实现。你可以改选更简单、文献更有空隙的机制，例如：

- 回退、默认值、缓存怎样掩盖依赖未迁移；增加输入测试、依赖干预和调用/消费证据分别能识别什么。
- 合同如何允许 alias、wrapper、adapter 或动态导入等合法实现，同时拒绝死代码 target call、伪调用和未消费结果。
- 任务意图、环境合同与错误归因怎样相互影响；在哪些条件下纯行为验证已足够，新增检查只增加误拒绝。

先精读直接近邻，再决定方法最小增量。**SWE Refactor Bench 已明确区分 migration completeness 与 behavioral correctness，并采用多阶段验证。** 因此“行为测试再加结构检查”本身不能当成新颖性。可复用其公开任务或方法作为比较，但先核实许可证、任务适配和运行成本；不要只引用标题，也不要为了避开近邻而忽略它。

### 6.3 实验顺序与比较

先复用现有候选，争取建立 4–8 个不同真实迁移的开发 pilot，覆盖不止一种变化机制。该数量是调试设计的起点，不是发表或创新认证阈值。优先修复少量可恢复环境；单个历史环境连续无进展时换候选。若来源产出很低，直接换成目标和维护测试更清楚的真实提交/公开任务，不把数周消耗在全量复活上。

所有 actor 获得同样明确的共同任务意图；如研究表示方式，原子事实完全一致。目标合同来自上游意图和可复核证据，不要求逐字重现 gold diff。独立正确性参考使用 `VALID / INVALID / UNRESOLVED`，争议保留，自动参考先用已知控制检验；AI 审查标明 AI 身份，不能替代声称需要人工的 Gold。

比较至少覆盖已有行为测试、必要的增强行为测试、简单静态合同以及候选方法。加入上游 gold、合理等价实现、错误回退、死代码调用等控制，分别检查误接受和误拒绝。人工构造 mutant 用于压力测试，不混入自然候选错误发生率。

分别报告 behavior pass、contract pass、hybrid pass、两类评价的分歧、独立裁决确认的假接受/假拒绝与未决比例，以及环境资格产出和成本。`behavior=pass, structure=fail` 首先是分歧，不自动等于错误。假接受率写明分母；以 commit/repo/family 为独立单位，生成重复和多测试用例不冒充更多独立任务。

方法和参考经控制验证后，保留未接触的新 repo/families 做确认。规模由目标效应、机制覆盖、区间精度及可用任务决定；不强行凑 20/40 个任务，也不把一两个成功案例升级成广泛结论。

**推进判断：** 存在有解释力的错误机制，方法在有效参考下改善误判而不系统拒绝合理实现，且新来源能复现，继续完善方法章。若增强行为测试或简单规则已足够，接受该结果并收窄或换候选；若参考不独立，先修测量，不堆模型调用掩盖缺陷。

## 7. G3：选择一个有真实空间的验证决策或适应问题

**目标：** 为第三项贡献找出有可识别收益的决策/适应问题。优先共享 G2 的可信任务与 oracle；不同时开三套新 benchmark，不预先强迫 Memory 或训练获胜。

### 7.1 默认候选：证据驱动的预算重验证

当输入、依赖或规则变化后，智能体应先验证什么，何时已有足够证据，何时需要升级工具/模型/修复？复用 Adaptive V3 的执行隔离、固定 repairer、预算扫描和配对分析，把 authored fixtures 换为可重建的真实任务。

先验证真实 headroom：不同验证动作确有成本差异与互补信息，简单 greedy/规则/固定顺序存在可重现的错误或浪费。对照至少包括不重验证、全量验证、固定顺序、成本或覆盖 greedy；有 defer 时加入 always-defer，分别报告覆盖与错误风险。

可探索的最小方法是依据变化范围、依赖消费证据或不确定性选择下一项验证动作/停止时机。只有 actor 当时可得的证据进入策略，不使用 gold 标签、未来测试结果或评估器私有 trace。独立 held-out 任务上比较同预算正确完成率、误放行风险与覆盖、达成相同质量所需成本；保持修复器和工具权限相同，避免把更强模型/更多事实优势算成策略改进。

旧 Adaptive fixtures 已给出 greedy 足够的边界。真实任务若同样饱和，自主结束当前策略候选，不换十种复杂 planner 追正结果。

### 7.2 可替换候选：条件化经验利用及失效识别

若真实任务出现重复但非重复样本的可修复错误，可以改研究：经验中的哪些条件应复用，条件变化后何时拒用或重验证？从实际错误、反馈与动作改变的链条采集经验，不把无错误的一次成功、手写 lesson 或隐藏 Gold 包装成自学习。

对照无经验、强规则、普通 solved example、固定检索/RAG，以及条件化经验方法。按 repo/家族/时间切分来源和新任务，控制检索事实、示例长度、模型与工具预算。评价未来独立任务净收益、correct→wrong 回归、条件变化时的失效判断、成本和覆盖；收益只胜无经验而不胜普通示例/规则时，不认领独特经验机制。

如有合理学习目标，允许小规模 LoRA/SFT：先用已有可训练工件确认 GB10 资源和训练链，再在开发数据上比较基础模型、同预算提示/检索与 adapter；评估未见家族及回归。无需另行证明“只有训练能解决”才准训练，但必须说明它检验的假设、数据与评价隔离。不要把训练 loss 下降、adapter 生成或同训练题得分提高当成第三创新。

研究 Memory 使用隔离目录/命名空间，可研究写回、更新、删除和适用条件；不写生产 Memory/PG，不把确认集反馈回流到同一次确认评分。LoRA/Memory 都可以被结果淘汰。

### 7.3 选择权与收缩

前两周可并行做两个候选的廉价诊断；第 3–4 周选择一个主攻。若二者都无空间，可以据现有素材提出一个更有识别力的新问题，如最低充分变化证据、验证结果校准或依赖 trace 的选择性获取，并先跑小探针。新问题须服务同一大论文主题，并交代与最近邻的差异及六个月内可完成性。

不因“任务资格还不完美”一律禁止模型 scout。用小额调用定位真实错误和信息缺口，清楚标成开发探索；确认实验再冻结设计。暂时不能形成第三创新时，尽早向 Owner 给出两个可执行替代方案和缺口，不把边界材料直接宣布为学位已达标。

## 8. G4：持续完成大论文素材、正文和认定倒排

**目标：** 从第一周开始写作，形成三个研究点相互连接的学硕论文。论文完成度与研究进度并行增长，不等所有探索结束才生成提纲。

先整理既有 `THESIS_RESEARCH_ARCHITECTURE_v3.md`、`THESIS_EXECUTION_BLUEPRINT_v1.md`、`THESIS_RESEARCH_GOVERNANCE_BASELINE_v1.md`、`paper/research_asset_map_v2.md` 和 `paper/thesis_manuscript_scaffold_v1.md`。保留历史快照和证据，更新现役说明；旧“长流程评估→蒸馏→规则进化”骨架不继续默认为本轮题目。已有数据缺陷和停止结论保留，旧阶段的执行授权范围由本次新任务衔接。

建议六至七章：绪论；相关工作与问题定义；测量有效性审计；正确性验证方法；验证决策/适应方法；必要的综合讨论；总结。章节结构随实证调整。

首轮即形成测量审计章节的**完整中文正文**，而非只有目录；G2/G3 写清问题、方法、对照和已完成实验，缺失结果明确标识。充分使用已有失败尸检、复现差距、等价性分析和来源资格经验解释设计选择，不把所有项目名各写成一个“创新”。金融文档可承接 Paper E 与新增方法验证；是否另加金融实验由它能回答的具体问题决定，不为背景统一额外制造数据工作。

同时准备一页导师讨论稿：暂定主题、三项贡献候选、各自最接近的工作、已有证据、缺口及替代出口；导师确认的是方向和学位贡献，不是每轮模型参数。

## 9. 资源、并行与自主决策

以首四周约 **4,096 次请求尝试 / 2,000 万总 tokens** 作为容量规划起点，覆盖探索、失败、重试、评估模型和新模型比较。它不是必须花完的指标，也不是要求你到额度才停止。Owner 已允许更多投入，你可依据实际吞吐、证据收益和送审时间自主调整阶段额度，并在账本记录新额度、原因与下一检查点；不逐次请求批准。

建议早期把约 60% 的主动工作精力用于 Paper E 与发表推进，其余用于 G2/G3 探索及大论文写作；稿件达到可投稿状态后转向后两项。比例按实际阻塞调整，不等待 Owner 回复时空耗机器，也不让新线挤掉首投修订。

优先复用 GB10 已有权重、可训练 checkpoint、工具与环境。新模型先核实 revision、许可和可运行性，再做少量异质模型诊断；确认阶段只保留有解释力的比较。训练从 smoke 到小训练分阶段进行，记录 GPU 时间、显存、数据量和训练 token；必要时按资源可用性串行调度，不同时争抢服务资源。允许为本轮隔离研究环境补必要依赖，不改变生产依赖、端点策略或凭证。

新建一个本轮账本，与历史 `101 attempts / 57,987 tokens`、`747 / 1,564,176`、更早账本分开。原始 failed/partial 保留，重复请求、canary、judge/独立审查的模型调用同样记账；训练和推理成本分列。若使用新的研究型 LLM judge，先校准于可独立核查的样本，不能替代可执行 oracle，也不把同一模型的自评叫独立真值。

你可自主决定文献筛选、问题收缩、来源切换、工具组合、模型、prompt、开发规模、Memory 和小训练安排，以及子代理分工。只有实际需要个人/导师身份、署名、付款、对外发送、公开许可或最终学位范围决定时集中交 Owner 处理。当前授权不包含新增付费 API/云资源采购或生产配置变更。

论文、方法和数据边界审查可由 A/C 并行承担；同一路径必须明确唯一写入责任。验证基于真实命令与原始证据，不能只认可另一 agent 的总结。治理只修复影响执行/复现的问题：原始证据保全、合理原子提交、必要 lint/链接/hash/定点测试；不新造审批平台、daemon 或自动科研判定器。

按子任务选择少量现有 skills：写作使用 research-writing-skill、paper-review-check，最终投稿使用 paper-polish-and-audit；文献需要时使用 paper-deep-reading；实验设计/复盘按需使用 exp-lifecycle、experiment-autopsy、offline-eval-playbook；收口使用 verify-before-done 与 jinrong-docs-sync。每个子任务遵循项目装载数量限制，不一次加载全部武库，不把读 skill 的数量当进展。

## 10. 首轮交付与持续回执

收到本任务后，先用现有任务卡写清本轮执行路径、资源和职责，然后直接工作。不要只返回下一份计划。

首轮回执至少包含：

1. **Paper E 可审阅成稿及投稿包**，统计处理的真实结果、主备渠道的官方核查与最迟行动时间；明确哪些已完成、哪些等 Owner 的具体操作。
2. **素材复用映射**，展示本机与 GB10 的哪些现有材料已经进入稿件、分析或实验，哪些保留为历史边界，哪些独有材料按 manifest 取回。
3. **G2/G3 的真实新观察**：可以是少量 scout、零新请求重分析、方法控制测试或小训练结果，但必须有原始证据和下一项判断；没有运行则明确说明。
4. **中文大论文审计章节和一页方向稿**；后两项创新继续标为候选，解释主问题和近邻区别。
5. **资源与代码实况**：新增 attempts/tokens、训练消耗、失败和重试；实际 commit、主机、未提交状态与恢复位置。不要抄旧“均为零”模板。

每个实质里程碑给出简洁更新：改变了什么判断、证据在哪里、还缺哪项、下一动作是什么。不需要海量重复回执；持续工作至当前阶段成果可审阅，不能把“准备了脚本/另有计划”当作实验或论文完成。

遇到负结果应提取边界，调整或停止具体候选；遇到工程阻塞先有界修复，再利用其他素材推进。研究自由体现在选择有价值的问题、敢于排除原假设和及时换路线，同时守住证据身份、成本透明和发表倒排。
