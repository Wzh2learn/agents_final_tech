## 4. 优先动作：从已有自然错误定位信息损失

A先用冻结ordinary输出、训练/开发/确认曝光清单和原始可见输入做零生成分析。可从source_disjoint_confirmation_v4的ordinary原题候选入手：24条中19条program_correct=True，5条False只是待审候选；相关/无关变化另列为控制，不能称自然错误。扩展现有自然错误池可以做，但均记曝光开发，不把旧错误池或本次选样称新确认。

逐例建立最小诊断链：

    实际可见输入 → 合法证据 → 充分性/适用性 → 模型程序/单位/引用 → 工具执行 → 完整语义答案

依次区分：参考或评分缺陷；可见信息不足；已有信息被输入处理丢掉；证据语义绑定错误；运算/单位/方向错误；严格输出失败；合理UNKNOWN。没有可见尺度、参考冲突或多种合法解释的题列UNRESOLVED，不能强打错或教师补造。

检查器分“模型输入内的部署可见信号”与“离线参考审计”两条路径。参考行号、gold程序和答案只进监督/评价，不能泄漏为部署特征；训练参考可以合法给正确方向/单位，不再冻结反号目标。检查器“没找到证据”不等于“答案错误”。

每类失败给最强简单对照：完整表头/上下文恢复、固定计算器、标签/时期规则、算式规范化、普通one-shot和neutral retry；允许简单工具成为最终方案。不强制学习。判断必须来自完整答案及合理引用，而非相同数值/集合/格式。

机制假设最多保留一个，例如“模型未把问题语义约束绑定到证据角色”；它只是候选。用等信息的raw、透明规范化表示与一种候选表示/决策，区分信息缺失、表示损失和模型使用失败，不让oracle信息只进候选臂。已知正确参考臂只作能力上界，不混入部署结果。

若简单修复解释全部、没有合格自然错误、或完整参考无法建立，则停止该候选，写成明确边界。不能为凑C2重启旧R/E、重加弱visible filter或堆生成样本。

## 5. 独立备选：固定模型下的证据充分性与取证成本

389个text-only screen作为短上下文负对照，不能包装为report/corpus retrieval。若扩展候选范围，明确选择：
- record内检索；
- 同报告可合法取得的表格/段落；
- 来源/时间约束明确的语料检索。

只有后两者真正取得对应文本且可复原时才声称更大范围，不凭文件名重建虚构全文，不人为堆干扰文本制造自然难度。507个table-text题可先做资格，不是已合格新任务或自动未曝光确认集。

固定同一actor、计算器、输出合同及上下文上限，比较小top-k、固定邻域、较大top-k、always-expand、透明停止/补查规则；只再加一个候选。Gold证据ID和答案不用于选择动作。若全上下文本来便宜且有效，接受always-expand为最终强基线。

同报：最终完整答案正确率、错误交付/正确覆盖/合理未知、证据充分性，以及端到端tokens、读出/检查/补查调用、延迟和失败。字符数只作上下文代理；离线oracle、静态回放成本与真实在线节省分开。候选要么在预先规定答案/风险容差内节省总成本，要么在匹配总成本时改善答案。非劣容差与预算点在出数前冻结；小样本置信区间过宽则UNDETERMINED，不把p>0.05当等效证明。

Adaptive-RAG、Sufficient Context和TAT-QA/TAGOP已覆盖通用路由、充分性分析和表文语义抽取。只精读与当前机制有关的3—5个近邻，写清相同/不同及可反驳实验，不声称“金融场景+计算器+规则”本身是方法创新。
