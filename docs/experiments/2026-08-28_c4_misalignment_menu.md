# C4 错位治理方案菜单（视觉探针 33% 错位/读串的处置三案）

## 0 问题定位

错位/读串 = VLM 转写的列位与图像列位不对齐（读了邻列表头或下方数据行），与"视觉判别力"正交——
错位率不压下去，判别谱被定位噪声淹没（首批 ocr_similar 61.5% 的信号置信度受限）。

## 1 三方案（各带预注册预期 + 改动面）

### 方案 a · 列对齐校验（后处理, 最廉价）
- 机制: 转写结果与图像列数比对; 数不符或长度异常 → 标 unaligned 弃用该表; 符合者按序对位
- 改动面: c4_visual_probe.py +~15 行（渲染侧不动）
- 预注册预期: 错位判定率 33% → ≤20%（弃用部分样本换对齐置信, 有效样本量下降 ≤30%）
- 风险: 数对齐但内容串位的错位仍漏检（弃用只抓列数异常）

### 方案 b · 单列裁剪渲染（源头治理, 推荐主案）
- 机制: 判别任务改"逐列问"——每注入列单独裁剪渲染（该列 + 相邻 1 列上下文 + 表头行）, VLM 只读单列; 列错位物理上不可能（一次只看一列）
- 改动面: render_c4_tables.py 增裁剪模式 +~40 行; probe 改逐列调用（调用数 ×列数, 预算 ~118×2 调用 ≈ 仍 <10min, p50 0.6s 实测）
- 预注册预期: 错位率 33% → ≤5%（残余 = 裁剪边界切字）; 判别谱数字相对首批可能整体移动（定位噪声去除后的真实谱）
- 风险: 单列上下文减弱全局版式线索; 与全表模式对照跑以量化该效应

### 方案 c · 列索引标注（提示侧治理）
- 机制: 渲染时在每列表头上方叠加列序号标签（"列3:"）, 转写指令要求输出 {列号: 列名} 字典, 显式对齐
- 改动面: render +~10 行, probe prompt + 解析 +~20 行
- 预注册预期: 错位率 33% → ≤15%（标注辅助但仍整表读, 串位可能残留）
- 风险: 标注本身可能被 VLM 当作表头内容读出（新错位形态）

## 2 执行编排（下次探针窗）

- 序: b（主案）+ a（兜底校验叠加于 b）同窗; c 留对照不首选
- 对照设计: 同一 95 表, 全表模式（已有首批数据）× 单列模式各跑一遍, 错位率与判别谱双指标对照
- 判据（预注册）: b 案错位率 ≤5% 且 ocr_similar 判别率仍 ≥50% → 采纳为协议标准, 更新 C4 臂协议; 未达 → 回菜单加案（候选: 更高分辨率渲染 / 两轮转写自一致投票）
- 工件: c4_rendered_cols/（单列图）+ c4_visual_probe_results_v2.json + 对照记录
