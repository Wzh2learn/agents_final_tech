# 低分归因三类（甲方问答依据）

> 状态: 活跃 | 更新: 2026-08-11 | 用途: 甲方问"某样本命中率为什么低"时的标准回答依据
> 证据口径: tests/baselines/scenario1_baseline.json + config/schema_suggestions.json + 辅助对话逐表实测（2026-08-11）

## 一句话结论

当前低分样本的成因可归为三类：**规则覆盖（已解决）、OCR 识别（物理上限）、统计口径（非解析问题）**。没有一类是"系统读不懂数据"。

## 类别 A：规则覆盖型 —— 数据全在，缺的是映射规则

**案例：华泰紫金（扫描传真）**
- 一轮 35.7% → 规则沉淀后 **100%**（baseline 实测 [100.0]，--no-llm 纯确定性复验）
- 根因：源文件数据完整，8 个账号上下文类列名（交易账号/交易账户名称/证件类型/证件号码/网点/截止日期等，见 schema_suggestions.json 华泰条目）不在 schema 同义词表
- 修复方式：建议映射面板勾选确认（场景 A，已上线）——甲方做选择题，系统沉淀规则
- **甲方话术**：这类低分提升最快，一次确认永久受益，同版式后续样本自动 100%

## 类别 B：OCR 识别型 —— 传真件物理质量决定上限

**案例：TraFax（传真扫描），逐表 [50 / 81.8 / 81.8]%**
- 实测根因 1（错认表头）：OCR 把机构名"新华养老保险股份有限公司"误识别进表头区域、数字串"240052288113"混入列名——表结构本身被传真噪声破坏
- 实测根因 2（可映射残余）：收费方式 / 交易净值 / 分红方式 / 可用份额 等列可映射但尚未沉淀规则（走类别 A 流程即可提升）
- 修复方向：① 残余列走建议映射面板（确定性收益）② OCR prompt/视觉模型升级（实验已做：8B VLM Q4 对乱版传真输出退化，VERIFIED-CLOSED，见 THREADS）③ 更高质量扫描源
- **甲方话术**：50% 的表受限于传真件原件质量，属物理上限；可映射部分正在以规则方式持续回收

## 类别 C：统计口径型 —— 不是解析失败，是不该算表

**案例：nanhua HTML 邮件中的 0% 表（该样本逐表 [33.3 / 75.0 / 0.0]）**
- 实测根因：0% 表为备注/说明类文本（非数据表），解析器按结构检出，但没有可映射的数据列
- 处置建议：命中率统计剔除此类表（口径调整），或标注为"非数据表"不计分——这是口径问题不是能力问题
- **甲方话术**：系统能区分"数据表"和"备注文字"，把备注算进命中率反而失真；我们按数据表口径报告

## 使用指引

| 甲方问 | 回答路径 |
|--------|---------|
| 为什么这份只有 X%？ | 先归因（A/B/C），A 类当场演示建议映射面板修复 |
| 能不能到 100%？ | A 类可以（华泰已实证）；B 类受原件质量约束，给实测上限；C 类换口径即消失 |
| 低分会不会影响问答？ | 不会编造——未映射字段问答明确回答"未找到"（eval 拒答题验证） |
