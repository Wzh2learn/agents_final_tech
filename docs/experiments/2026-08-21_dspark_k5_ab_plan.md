## 3 预期收益算术（如实，不修饰）

- 每轮草稿 token 数 7→5：草稿生成开销降 2/7 ≈ 28.6%（drafter 1.3B 顺序生成，单轮节省两个 drafter 步）；
- 期望接受 token/轮：1.29 → ~1.22（去掉 pos5/pos6 合计 0.068），即每轮推进 2.29→2.22 token（-3%），轮数相应 +3%；
- 验证步序列长度 8→6 token/轮，目标模型单步前向略省；
- **净估计：agent xhigh 流量端到端 +3~8%**（草稿开销下降被轮数增加部分抵消）；对接受率更低的流量（如 D2 若证实 XML 段 <1.5）收益同比例缩小——k 裁剪解决的是"草稿浪费"，不解决"接受率低"这个主矛盾。
