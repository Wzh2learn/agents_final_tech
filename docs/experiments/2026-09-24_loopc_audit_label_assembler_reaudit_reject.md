# Loop C re-audit of the assembler hardening (model qwen3.8-max)

> Dispatched 2026-09-24 against commit 2dc4c98; evidence packet inline; no tools; 1 turn(s), cost $0.1895.
> Verdict: REJECT - F2/F3 closed but F1 residual: top-level non-dict inputs dereferenced .get before validation (bare AttributeError); two guards dead code.
> Body verbatim.

**VERDICT: REJECT** — F2 and F3 are closed and no artifact/independence regressions were found, but F1 is **not** fully closed: a bare `AttributeError` can still escape `assemble` on a plausible malformed input.

**Findings**

1. **[BLOCKING — F1 not closed] Top-level non-dict input documents escape as bare `AttributeError`.** `assemble` dereferences `r1.get("reviewer_id")`, `r2.get("reviewer_id")`, and `adj_doc.get("adjudicator_id")` on its very first lines, before any type validation. `_load` in `main` accepts any parseable JSON, so an input file containing `[]`, `"x"`, `0`, or `null` reaches `assemble` and raises `AttributeError: 'list' object has no attribute 'get'` — exactly the failure class F1 required eliminated. Worse, the hardening added guards for this case but placed them where they are dead code in the main flow:
   - `_judgments_by_pair`'s `invalid_review_doc` non-dict check is unreachable via `assemble`, because `r1.get(...)` crashes first (it only fires if the helper is called directly, e.g., from a unit test — which likely explains why tests pass);
   - the `if not isinstance(adj_doc, dict): raise LabelAssemblyError("invalid_adjudication_doc")` check sits **after** `aid = adj_doc.get("adjudicator_id")` and after both `_judgments_by_pair` calls, so it can never trigger for a non-dict.
   **Fix:** validate `isinstance(r1, dict)`, `isinstance(r2, dict)`, `isinstance(adj_doc, dict)` with coded errors as the first statements of `assemble` (or in `_load`), and move the `invalid_adjudication_doc` check above the `adj_doc.get` dereference.

2. **[NOTE — F1 adjacent] Unwrapped `OSError` paths in `main`.** `_load` catches only `UnicodeDecodeError`/`ValueError`; a missing file, directory, or unreadable path raises bare `FileNotFoundError`/`IsADirectoryError`/`PermissionError`. Similarly, `write_text` failures (including a partial state where the artifact is written but the meta sidecar write fails) are unwrapped. These are outside F1's enumerated classes (KeyError/AttributeError/JSONDecodeError) so they don't block, but they should be coded (e.g., `input_io_error`) for consistency. Also, `LabelAssemblyError` itself propagates out of `main` as a traceback rather than a clean `code: detail` message with a nonzero exit — fail-closed semantics hold (errors fire before any writes, so no partial artifact from `assemble` failures), but CLI ergonomics suffer.

3. **[PASS — F2 closed]** In the disagreement branch, `rationale_ref` is validated as a non-empty `str` (`missing_rationale_ref`) **before** `gold = choice` is assigned; ordering relative to `missing_adjudication`, `adjudication_col_mismatch`, and `adjudication_invalid` is correct, and no path sets gold from an adjudication without passing the rationale check. `test_missing_rationale_ref_rejected` covers it.

4. **[PASS — F3 closed, with caveat]** All six previously untested rejection paths now have named tests: `test_missing_target_key_rejected`, `test_missing_uid_rejected`, `test_non_dict_judgment_rejected`, `test_non_dict_adjudication_entry_rejected`, `test_missing_rationale_ref_rejected`, `test_unparseable_input_rejected`. Caveats: (a) only names were supplied, bodies not audited; (b) notably absent is any test for a non-dict review/adjudication **document** at the `assemble` boundary — consistent with Finding 1 surviving the test suite. Add `test_non_dict_review_doc_rejected` / `test_non_dict_adjudication_doc_rejected` exercising `assemble`/`main` end-to-end, not just `_judgments_by_pair`.

5. **[PASS — no regression: independence rules]** All protocol rules intact and correctly ordered: generator excluded from {r1, r2, adjudicator}; reviewers distinct; adjudicator ∉ reviewers; `incomplete_review_pair` for one-sided keys over `sorted(set(j1) | set(j2))`; disagreement requires an adjudication whose validated choice becomes gold; `multiple_columns_per_sample` enforces per-sample uniqueness; uid equality/non-empty re-checked at merge (`uid_disagreement`). Key-presence validation (`sample_id`, `uid`, `col`, `action`, `target`), strict `type(col) is int` (correctly rejects `bool`), and `_valid_choice` (map_to requires non-empty str target; skip/hold require `target is None`) are sound.

6. **[PASS — no regression: artifact shape]** Rows carry exactly the eight LABEL_FIELDS keys (`sample_id`, `uid`, `col`, `gold_action`, `gold_target`, `quality_grade`, `reviewers`, `adjudication` — per the cited contract lines 72–81; contract file not independently re-verifiable without tools). Internal `_choice` never leaks into rows. Output is pure JSON Lines (one `sort_keys` object per `\n`-terminated line, `newline="\n"`); diagnostics (carriers, template versions, agreement rate, generator id, timestamp) are sidecar-only in the meta file, with a safe `None` agreement rate for zero rows.

7. **[MINOR]** Two non-blocking hygiene issues: (a) duplicate adjudication entries for the same `sample_id` silently last-write-wins in the `adjudications` dict rather than raising a coded `duplicate_adjudication`; (b) an empty `--generator-id` string is accepted (it can't collide with validated non-empty carrier ids, so independence holds, but rejecting it would be consistent with `missing_carrier_ids`).

**Bottom line:** Findings 3–6 confirm F2/F3 closed and no regressions, but Finding 1 is a direct recurrence of the F1 defect class (bare `AttributeError` escaping `assemble` on malformed input, with the new guards shadowed into dead code). Re-audit after moving the dict-type validation ahead of all `.get` dereferences and adding end-to-end tests for non-dict documents.
