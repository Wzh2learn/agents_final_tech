# /m1 问答延迟与“快路”命名核验（2026-08-29）

## 结论

`/m1` walkthrough 的 13/13 只能证明功能链完整，不能签署“快路体验通过”。最终单实例复验三条问答耗时 48.6s、50.6s、49.7s（中位数 49.7s，均值 49.6s），服务端 B4 四条请求（含步骤 3 QA）均为 `route=direct, fell_back=true`：请求先等待约 45s 的验证链，超时后才由直连链回答。因此页面显示“直连（本次曾回落）”是事实，“快路”则与用户体感不一致。

证据采集器调试期间曾有浏览器结束后服务端请求继续完成，叠加复跑观察到 105.5s/105.6s 尾部；该现象与既有孤儿轨迹/争用记录一致，只作风险注记，不混入最终单实例三问统计。

本轮只优化证据命名，不改 UI、路由或生产配置：验收脚本与摘要把这组三问改称“回落问答回归”；旧文件名 `step5_fast_regression.png` 为保持证据路径兼容暂不改名。

## 两个最小方案（待用户裁定）

### T. 真实提速

给问答请求增加显式 `direct` 模式，并在 `/api/m2/ask` 入口直接跳过 `ask_via_opencode`；工作台仅在用户选择“直连问答”时发送该模式，默认 `auto` 行为不变。用同三问热态复验，闸门建议定为 p50 ≤ 8s、p95 ≤ 12s、答案与引用断言 3/3。该方案能直接消除当前约 45s 的等待，但涉及 API/UI 行为，应另开授权，不在本轮实施。

### N. 如实改名（本轮推荐）

在真实提速过闸前，所有验收材料使用“回落问答”或“标准问答”，不再称“快路”；页面现有实际链路提示“直连 · 生效（本次曾回落）”保持不变。该方案不改变功能与路由，风险最低，已先用于本轮证据描述。
