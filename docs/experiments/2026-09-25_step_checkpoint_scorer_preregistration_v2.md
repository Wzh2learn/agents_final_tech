## V2-0 动因（先写死，避免事后合理化）

v1 实测 `interpretation_fidelity` = 0.16345178（分母 1 970）。其分层显示：
`pct` 形态 res 的 mismatch = 1 429 / 1 478（match 仅 44），divide 族 mismatch = 1 638 / 1 812；
而 `num` 形态 match = 2 571 / 3 096（83.0%），minus / add 族 88-91% 忠实；
变体位 1 与 2 的 mismatch 比例几乎相同（42.8% vs 43.6%），故变体位不是解释变量。

⇒ v1 的 R4「res 带 % 时其尾数与重算值直接比较」在 pct 形态上被**实测证伪**；
问题出在百分号约定，不在算子语义、不在变体位、也不在检测器。
本件据此只改必要之处，并把改动限制为「增加并列读法与增加指标」，不删改 v1 的任何既有规则。

## V2-1 与 v1 的差异（只有三处，其余逐条继承）

1. **R4 百分号比较改为双读法并列**：新增 `mantissa_scaled`（重算值 × 100 后与 res 尾数比较），
   与 v1 的 `mantissa_direct`（重算值直接与 res 尾数比较）**并列计算、并列上报**；
   不设主读法、不得只报其一、不得取两者中较好者作为头条。
   `#N` 下游消费规则不变（尾数 ÷ 100）。所有指标（fidelity / detection / 三个 localization）
   均须在两种读法下各出一份，产物中以 `reading` 维度并列。
2. **R5 新增第三个定位指标** `root_cause_localization_rate` = `min(flagged) == 注入 index` 的例数 / 被检出例数。
   机制依据（不是结果依据）：注入点是最早被改变的步，其下游 mismatch 是 `#N` 传播的后果而非独立检出，
   故因果定位应取最早被标记步。诚实披露：v1 结果已公开显示 exact 与 inclusive 的差距集中于
   `res_scale`（exact 120/288，inclusive 288/288）而 `arg_swap` 为 31/31，本条并非事后才发现该现象；
   但本指标的引入依据是上述因果次序，且 v2 要求三指标同时上报，故不存在「只报好看的那个」的空间。
3. **三个定位指标（exact / inclusive / root_cause）必须同时上报**，缺任一即验收不过。

## V2-3 停止条件（防无限调参，本件的核心纪律）

- 若 v2 在**两种读法下**的 pct 形态保真度均仍低于 0.5，则结论固定为
  「FinQA 步级 res 的百分号与变体约定，在 D-C 批准范围内无法由官方文档确定」，本线**停止**；
  不得开 v3 继续试约定。此后唯一合法动作是：新申报官方算子代码或文档（超出 D-C 范围，需用户批准），
  或放弃该来源的步级重执行路线并如实记录。
- 任何 v3 都必须先提交规格、再运行，并同时保留 v1 与 v2 的全部结果。
- 保真度、检出率、定位率一律**不得**通过改分母、改容差、改族语义、改故障定义或换读法口径来提升；
  两读法并列正是为了堵死「换口径救结果」这条路。
