## 2. 菜单（按 收益/风险 排）

**M1 · playbook 预注入（合并 skill 加载步）** — 收益 ~5.0s/每尝试（−15%）
把 m2-rag-playbook 内容直接编进 m2-qa 系统提示, 去掉运行时 skill 工具调用。4 步→3 步。
风险: 系统提示变长 → prefill 增量; L2 实测 63.2% 请求 context 已在 10k–20k, 需先量 playbook token 数（实施前测量, 预期 <1.5k, 占比可控）。改 opencode 配置, 需窗口。

**M2 · 单检索纪律（消双查）** — 收益 10.4s × 37% 尝试 ≈ 加权 −3.8s（−11%）
37% 完成会话做两次 search。playbook 加规则"一次检索定案; 仅当 0 命中才许换词重查", 或首查 top_k 5→8 降低重查动机。纯提示词改动, 零代码。
风险: 跨文档题召回下降; 门禁 = 确定性 16 题 + NF 零回归。

**M3 · 终答瘦身（decode 段）** — 收益 ~8-10s（−25%, 估计值）
18.4s 的 gap3 是 decode 主导（无投机栈 ~14 tok/s, 答案 ~250 token）。答案体例改"数字 + 一句出处"（现答案常带复述）。
风险: 体感信息量下降, 需 judge 四维抽样守 ≥4.9; 与明日 L1 thinking 矩阵同批判读。

**M4 · 组合拳 M1+M2+M3** — 4 步 ~34s → 2 步 ~19s（−44%, 实测算术拼接）
2 步形态 = [检索 → 终答], 无中间决策轮。这是"减 step"的 3→2 具体路径。

**M5 · （激进, 列而不做）意图分流**
单跳事实题（kiosk 主力）本可 2-3s 直连; agent 路只留多跳/勾稽/验证题。这已不是减 step 而是路由选择, 与"快与准菜单"同源, 留给路由维度讨论, 不在本轮动手范围。
