## 3 操作化定义

### 3.1 E5.1 Hungarian 全局分配 vs 现行贪心

- 每表构造二部图: 行 = 非空归一化表头列, 列 = canonical 字段; 边权 = 匹配器打分元组 (score, syn_len) 的标量编码 score*100 + min(syn_len, 99)（忠实贪心优先级序）。
- 贪心臂 = map_headers 原样（候选按 (score, syn_len) 降序, 每标准字段/每源列至多一次）。
- Hungarian 臂 = 最大总权重精确匹配（纯 stdlib O(n^3) 实现, 确定性; n = 表列数, 语料内小表, 无需外部依赖）。
- 双臂各跑 original 与 injected 两套表头（95 表 × 2 臂 × 2 头）。
- 指标: 分配差异表数/列数; 注入级正确性变化（注入列是否映射回其真值 canonical）; 吸收/可见判定翻转数（尤其 ocr_similar 13 条）; 差异案例逐条原文审计清单。

### 3.2 E5.2 oracle ACC 天花板复核

- 从 p1_correctness_backfill.json 复算/引用: ACC_oracle plain = 0.952381（118 注入）, overlay = 0.597015（185 注入列）; 匹配器下界 0.558095 / 0.594762。
- 机制解释（论文效度威胁节素材）: overlay 共享表头下同一 canonical 多变体争唯一槽位, 即使真值规则全在, 列间竞争压缩正确性上限; 门控只拦增量伤害, 不解决存量竞争。
- 范围声明: 天花板数字属 VGMC 碰撞语料（185 注入列）, 与 95 表 plain 语料分列, 不混同。

## 4 预注册预测与判据

1. 复现门 G1: 贪心臂重算 = 冻结工件逐表一致（75/95 + by_type, 误差 0）。
2. 复现门 G2: oracle 天花板数字与 p1_correctness_backfill.json 一致（0.952381 / 0.597015, 误差 <1e-6）。
3. 判据 P1（方向不预判, 双分支皆信息）:
   - 分支 a（差异 ≈ 0）: 贪心在该打分层级下已全局近优 → 结论 = "匹配竞争不可由分配层消解, 根因在打分层污染（形近串获得与真值同档打分）", 效度威胁节按此写;
   - 分支 b（差异显著）: 报告 Hungarian 带来的注入级正确性增量与吸收翻转清单, C1 可见性谱加"匹配器次优性"注记。
4. 判据 P2: ocr_similar 13 条吸收判定在 Hungarian 臂的翻转数逐条列出（预测: 多数不翻转, 因形近串对真值字段的打分不低于竞争字段——以实算为准）。
5. 判据 P3: 影响范围声明——明确"匹配竞争对主结论（C1 全盲 + 类型不均匀）的影响 = {无实质改变 / 限定条件下成立 / 需降级}", 三选一由实算定, 不预设。
