## Scope

验证 M1 的真实业务：**把各家格式不统一的对账单/报表，通过「标准字段 → 近义词」
映射，解析成标准化结构**。引擎流程为：解析文档表格 → 识别表头 → 近义词映射到
标准字段 → 提取行数据 → 输出标准化记录；映射不上的列标 `unmapped`（对应甲方 UI
的「新增字段」），表头信息区键值对单独提取。

  `2000****8295`、`9131****5193`、`2216****.90`）。
- 未下载任何模型/数据集；本轮为纯规则解析，**未调用 :8004**（m1-batch 在用）。
- 未改动 `src/biz/m1_service.py`（旧中文规则基线保留不动）。

## 映射规则覆盖度分析

匹配优先级：精确 > 归一化包含（去空白/标点后子串）> 编辑距离≤1（仅 ≥3 字符）。
每个标准字段贪心只占一次。

**稳定命中（近义词表已覆盖）**：

- `证券代码`/`证券名称`/`交易市场`/`币种`/`最新价`/`成本价`/`盈亏金额` 在 txt、pdf、
  xlsx 三类样本里均精确命中。
- 变体列名靠「包含」命中：`参考市值→市值`、`参考市价→最新价`(via 市价)、
  `参考盈亏→盈亏金额`(via 盈亏)、`股东账户→股东账号`、`股票名称→证券名称`、
  `当前数→持仓数量`、`发行公司→基金公司`、`股东帐号→股东账号`(精确 synonym)。

**总是命中不上的标准字段 / 需扩 synonyms**：

| 源列名 | 出现样本 | 建议标准字段 | 现状 |
|--------|----------|--------------|------|
| 基金名称 | xlsx | 产品名称 | `证券持仓明细` 无「产品名称」字段，被精确匹配到 `证券名称` 占用后 unmapped |
| 参考成本 | jiaxing | 成本价 | 既非子串、编辑距离=2（>1），未命中；建议给 `成本价` 加 synonym `参考成本` |
| 股份余额 | jiaxing | 持仓数量 | synonym 仅有 当前数/持仓/数量/持有数量；建议加 `股份余额` |
| 市值价 | fuxi | （无） | 源表冗余列，无对应标准字段，正确 unmapped |
| 资金余额/资产总值/多金融市值/总资产/资金可用 | fuxi, jiaxing | （资金汇总） | 当前两张 schema 表均不覆盖「资金资产汇总」语义，需新增第三张表 |
| 客户姓名/制表/开始日期/结束日期 | jiaxing | 表头区 KV | `header_meta_fields` 未含（仅有 客户全称/户名），建议加 `客户姓名` 等 |

**过宽 synonym 的误配风险**：`持仓数量` 的 synonym `数量`、`证券名称` 的 synonym
`名称`、`证券代码` 的 synonym `代码` 过于通用，会把 `在途数量`/`配号数量`/`基金名称`
等也吸过来（如 jiaxing `持仓数量←在途数量`、`持仓数量←配号数量` 语义并不等价）。
建议甲方对这类泛化 synonym 收紧或加表级限定。

**编辑距离阈值取舍**：阈值≤2 会把 `币种→券商`（距离 2）误配；收紧到≤1（且≥3 字符）
后误配消失，但同时失去 `参考成本→成本价`（距离 2）这类 desirable 命中。结论：
短中文列名靠编辑距离不可靠，应**以「扩 synonyms」为主、编辑距离仅作弱兜底**。

## 发现与下一步

**发现**：

- 纯规则「表头近义词映射」对**带表头的规整网格表**效果好：股票/证券持仓明细类
  命中率 78%–90%，组合证券 xlsx 83%。
- 三类文档**无法用规则解析**，需 OCR/VLM 兜底：
  - `20260506_233222LU.pdf`：纯图片 PDF（1 图、无文本层）。
  - `sample_xinhua.docx`：内嵌 7 张图、零文本（`w:t` 计数 0）。
  - `boshi_chuantong.pdf`：有文本但**无网格表**，是「基金名称：xxx / 基金代码：xxx /
    基金份额净值：xxx / 基金资产总额：xxx」式**逐基金 KV 报告**；当前
    `header_meta_fields`（客户/账号/证件类）不覆盖基金级键，故 KV 命中 0。
- PDF 表头信息区常被 `find_tables` 当成一张「标题表」（如 jiaxing p0_table_1），
  更应按 KV 块处理；表头区 KV 提取（正则键名）在 txt 上 6/6、pdf 上受 synonym 覆盖
  限制（2/6）。

**下一步**：

1. **扩 schema**（最高 ROI，纯配置）：给 `证券持仓明细` 增 `产品名称(基金名称)`、
   `成本价 += 参考成本`、`持仓数量 += 股份余额`；新增第三张「资金资产汇总」表
   （资金余额/资金可用/资产市值/总资产/资产总值）；`header_meta_fields` 增
   `客户姓名`、`制表`、`开始/结束日期`、基金级键（基金名称/基金代码/基金份额净值/
   基金资产总额）。
2. **KV 报告体解析**：对 boshi 这类无网格表文档，用「表字段 synonym 当键名」从
   文本里按块提取多条标准化记录（一个基金一条），作为 grid 解析的补充路径。
3. **OCR/VLM 兜底**：对 image-only PDF/DOCX 走 M1 OCR 链路（`vision_ocr_extract`），
   先取文本/表格再进同一套近义词映射；LLM 仅对无表头/复杂合并表做最后兜底并限流，
   避免与 m1-batch 抢 :8004。
4. **与 M2 衔接**：标准化记录（产品/对账日期/券商/托管行/合计金额/明细行）即甲方
   `ui_extraction_result.png` 的结构，可直接作为 M2 数据分析问答的结构化输入；
   `unmapped` 列作为「新增字段」回写规则配置，形成 M1→M2 闭环。
