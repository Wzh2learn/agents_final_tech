> **用途**：研究 Agent 每次完成精读升级后，按本格式输出"动作清单"，写作 Agent 直接据此执行修改。
> **创建**：2026-06-15（写作 Agent 定义）
> **v2 更新**：2026-06-26 — 段落式 → 6 列表格（协议 §4.3 / §3.1 同步引用），降低结构噪声、提升 grep 命中率
> **原则**：写作 Agent 只接收这种格式，拒绝无结构的"建议一下""看看要不要改"。
> **协同规则出处**：`AGENT_COLLABORATION_PROTOCOL_v1.0.md` §0.5 / §3.1 / §4.3

## 一、单篇精读后的动作清单模板

落盘文件名：`session/ACTION_Research Agent_{论文简称}_{YYYY-MM-DD}.md`

```markdown
# ACTION: {论文简称} 精读动作清单

> 日期：YYYY-MM-DD | 产出 Agent：研究 Agent | 精读笔记：`reading_notes/{文件名}.md`
> 影响 Paper：the paper (YourProject) | 影响章节：§2 / §4 / §5 / §6

## 精读笔记路径
`reading_notes/{文件名}.md`

## 影响正文动作清单

| # | 位置 | 当前写法 | 精读发现 | 建议修改 | 优先级 | 原因 |
|---|------|---------|---------|---------|--------|------|
| 1 | §2.x {小节标题}，L{行号} | > 引用当前正文原句 | {事实偏差/遗漏/过强claim} | > 修改后的句子 | 必须/可选/不建议 | {精读笔记证据行号} |
| 2 | §4.x {小节标题}，L{行号} | ... | ... | ... | ... | ... |
| 3 | §5.x {小节标题}，L{行号} | ... | ... | ... | ... | ... |

## 红线检查
- [ ] 是否涉及"端到端可微"claim？
- [ ] 是否涉及"首个"表述？
- [ ] 是否把"我们抽象出的机制"误写成"对方论文原文贡献"？
- [ ] 是否与 current paper version（project core operations / current terminology / per-user representation）冲突？

## 写作 Agent 接收确认
- [ ] 行号已 grep 确认
- [ ] 修改已附 diff 片段磁盘证据
- [ ] 红线检查全通过
```

## 二、字段定义

| 字段 | 必填 | 说明 |
|------|------|------|
| **位置** | ✅ | `§章节号 小节标题，L行号`。多个连续行用 `L12-18`，跨节用 `§2.3 L45 / §5.1 L210` |
| **当前写法** | ✅ | 引用正文原句（`>` 引用块），不允许意译。grep 必须能命中 |
| **精读发现** | ✅ | 一句话说明问题类型：事实偏差 / 遗漏 / 过强 claim / 命名冲突 / 引用错位 |
| **建议修改** | ✅ | 修改后的完整句子（`>` 引用块），不允许"略""微调"等模糊表述 |
| **优先级** | ✅ | `必须` / `可选` / `不建议`。必须=不改会被审稿人抓；可选=改了更好；不建议=有思路但不成熟 |
| **原因** | ✅ | 引用精读笔记行号（`reading_notes/xxx.md L88`）或公开论文证据。不接受"直觉""感觉" |

## 三、写作 Agent 接收规则

1. **只接收上述表格格式**。无结构建议（"建议看看 §2.3"）一律退回，退回时附"缺字段：位置/发现/修改"。
2. **三级优先级处理**：
   - `必须` → 立即执行，执行后在原表格末列加 `✅ 已改 L{新行号}`
   - `可选` → 写作 Agent 自主判断，未改需在闭环记录中说明理由
   - `不建议` → 默认不改，记录到 `cross_agent_lessons.md` 备查
3. **修改前** `grep -n "原句关键词"` 确认行号（防止合并稿迭代后行号漂移）。
4. **修改后** 在 ACTION 文件对应行尾追加 `✅ 已改 L{新行号} (diff 见 commit {hash})`，作为磁盘证据。
5. **过渡期**（2026-06-15 → 2026-07-15）：允许 `ACTION_DRAFT_*` 命名的非完整表格，但必须标注"缺字段"。
