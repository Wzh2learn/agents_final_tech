# 07 角色B 模型调研与研究方向

## 1. 定位

角色 B 不只负责把本地模型跑起来，还需要把模型部署、任务评测和调优过程沉淀成可复现的实验路线。第一阶段围绕 M1 规则抽取和 M2 RAG 问答，逐步扩展到 OCR、Embedding/Rerank、Tabular Foundation Models 和轻量微调。

核心目标：

1. 在开发机上下载、部署和评测不同 SOTA 小模型；
2. 建立 M1/M2 的模型效果、速度和资源占用对比表；
3. 找到可以写小论文或支撑研究生开题的研究问题；
4. 形成可复用的模型服务、下载脚本、实验记录和评测模板。

## 2. TabFM 是否适合加入计划

适合加入，但要放在“表格基础模型 / 结构化决策”专项里，而不是放在普通 LLM 聊天模型池里。

TabFM 的价值：

1. 它面向表格分类和回归，适合结构化数据预测；
2. 它使用 in-context learning，把训练行作为上下文，在推理时完成新表格任务；
3. 它可以和 M1 形成组合：先用 LLM/OCR 抽取文档规则，再把规则整理成表格，由 TabFM/TabPFN/XGBoost 做下游判断；
4. 它适合构造研究问题：业务文档中的规则是否应该由 LLM 直接判断，还是先结构化再交给表格模型判断。

需要注意：

1. TabFM 不处理原始文本、PDF 或图片；
2. 它不能替代 Qwen、MiniCPM 这类通用语言模型；
3. 当前权重有非商业许可限制，实验记录里要标注；
4. 对 Python 和依赖版本有要求，建议单独建 Python 3.11 实验环境，不直接污染 `wzh_vllm`。

## 3. M1/M2 任务到模型方向的映射

| 任务 | 主要问题 | 候选模型/框架 | 评测重点 |
| --- | --- | --- | --- |
| M1 规则抽取 | 从文本/PDF 中抽取字段、条件、阈值和动作 | Qwen3-4B/8B/14B, MiniCPM5-1B, 现有 Qwen3.6-35B-A3B | JSON 合法率、字段完整率、人工修正量、延迟 |
| M1 文档解析 | 复杂 PDF、扫描件、表格、印章、公式 | PaddleOCR-VL-1.6, MiniCPM-V 4.6, Qwen3-VL-8B | OCR 准确率、表格还原、Markdown/JSON 可用性 |
| M1 表格决策 | 抽取后表格上的分类/回归/规则适用性判断 | TabFM, TabPFN, XGBoost, LightGBM | 小样本效果、稳定性、可解释性、推理成本 |
| M2 RAG 问答 | 业务规则问答和来源追溯 | Qwen3-8B/14B, 现有 35B 模型 | 答案准确率、来源命中率、拒答能力 |
| M2 检索排序 | 找到正确规则片段并排序 | BGE-M3, Qwen3-Embedding, bge-reranker-v2-m3 | Top-K 命中率、rerank 提升、延迟 |

## 4. 推荐候选模型池

### 4.1 文本小模型

1. Qwen3-4B GGUF：已用于轻量 baseline，适合快速调 prompt 和结构化输出；
2. Qwen3-8B GGUF：M1/M2 的第一批主力小模型；
3. Qwen3-14B：质量和成本的主力候选；
4. MiniCPM5-1B：超轻量文本模型，适合测试端侧/低资源 Agent、工具调用和规则问答边界；
5. 现有 Qwen3.6-35B-A3B GGUF：作为大模型效果上限和对照组。

### 4.2 OCR 与多模态文档模型

1. PaddleOCR-VL-1.6：优先测试 PDF、图片、表格、印章、公式和版式解析；
2. MiniCPM-V 4.6：优先测试轻量多模态、OCR、文档问答和本地部署；
3. Qwen3-VL-8B：作为通用视觉语言模型对照。

### 4.3 Embedding 与 Rerank

1. Qwen3-Embedding-0.6B：轻量中文/多语言 embedding baseline；
2. BGE-M3：稠密、稀疏和多向量检索基线；
3. bge-reranker-v2-m3：轻量 rerank baseline；
4. Qwen3-Reranker：与 Qwen embedding 体系配套测试。

### 4.4 表格基础模型

1. TabFM：老师给出的重点论文方向；
2. TabPFN：成熟表格 foundation model 基线；
3. XGBoost / LightGBM：传统强基线；
4. 简单 MLP / TabTransformer：深度学习表格模型补充对照。

## 5. 可以发展成论文/开题的方向

### 方向 A：业务文档到结构化规则的可靠抽取

问题：小模型能否稳定完成金融/业务规则文档的 JSON 结构化抽取？

实验变量：

1. 模型大小：4B / 8B / 14B / 35B；
2. 推理模式：thinking / no-thinking；
3. 输出约束：纯 prompt、JSON schema、重试修复、SGLang 结构化生成；
4. 文档类型：纯文本 PDF、扫描件、复杂表格、图片。

可写点：小模型结构化输出稳定性、错误类型分析、低成本模型部署实践。

### 方向 B：OCR/文档解析质量对 RAG 的影响

问题：文档解析模型的表格还原、版式理解和 OCR 错误，会如何影响 M2 问答质量？

实验变量：

1. PaddleOCR-VL vs MiniCPM-V vs 传统文本抽取；
2. Markdown、纯文本、JSON 三种中间表示；
3. 不同 chunk 策略和表格保留策略；
4. Embedding + rerank 是否能弥补 OCR 噪声。

可写点：面向业务规则文档的 OCR-RAG 联合评测。

### 方向 C：LLM 直接判断 vs LLM 抽取 + 表格模型判断

问题：对于规则适用性、风险等级、产品匹配等任务，LLM 直接回答是否比“先抽取成表格，再由 TabFM/TabPFN/XGBoost 判断”更好？

实验变量：

1. LLM 直接分类；
2. LLM 抽取字段 + 规则引擎；
3. LLM 抽取字段 + TabFM/TabPFN；
4. LLM 抽取字段 + XGBoost/LightGBM。

可写点：文档智能中的神经符号/结构化中间表示是否提升可靠性。

### 方向 D：本地硬件上的小模型部署与量化 Pareto

问题：在开发机硬件约束下，哪类模型在 M1/M2 上达到最优的效果、速度和资源占用折中？

实验变量：

1. llama.cpp / vLLM / SGLang；
2. GGUF Q4/Q5/Q8、AWQ、GPTQ、BF16；
3. 上下文长度、batch、并发；
4. OpenAI-compatible API 封装方式。

可写点：面向业务文档 Agent 的本地小模型部署和调优实践。

## 6. 近期执行顺序

1. 用 Qwen3-4B、Qwen3-8B、Qwen3-14B 和 Qwen3.6-35B-A3B 跑同一批 M1/M2 样例；它们仅作为同家族的规模控制组，35B 只用于质量上限对照；
2. 下载并测试 Qwen3-14B，作为质量、成本和本地部署的主力候选；
3. 准备 Qwen3-Embedding-0.6B、BGE-M3 和 bge-reranker-v2-m3，先建立 M2 检索/重排序基线；
4. 下载并测试 PaddleOCR-VL-1.6，先跑单页图片和 PDF 文档解析；
5. 下载并测试 MiniCPM-V 4.6，与 PaddleOCR-VL 做 OCR、表格还原和文档问答对照；
6. 只有在需要通用视觉语言模型对照时，再补 Qwen3-VL-8B；
7. 单独创建 TabFM/TabPFN 的 Python 3.11 实验环境，先跑 sklearn 风格分类/回归 demo，再接入 M1 抽取后的表格样例；
8. 每次仅常驻一个待测生成模型；完成一组测试立即停止服务，以给下一组模型释放统一显存和系统内存。

## 7. 每次实验需要记录

1. 模型名称、来源、license、下载时间；
2. 权重格式和量化方式；
3. 推理框架和启动命令；
4. 显存、内存、磁盘占用；
5. 首 token 延迟、生成速度、总耗时；
6. M1 JSON 合法率和字段正确率；
7. M2 来源命中率和人工评分；
8. 失败样例和错误类型；
9. 是否值得进入下一轮调优。
