## 2 三线框架：评估 + 改进 + 自学习

导师的三段式与系统已建成的三条链一一对应，缺的只是数学形式化与公开数据实验。

### 2.1 评估线

**现成资产**：run_eval.sh 一键 eval（确定性 16 问 + 数值忠实度 NF + 四维 judge 防泄漏）+ scenario1 回归门禁 + B4 灰度仪表（route/latency/fallback 结构化日志）。

**升级目标**：面向金融文档智能体的分层测评协议——
- 解析任务检查点树：文档级（解析成功/页数/耗时）→ 表级（表边界/表头识别）→ 字段级（映射命中）→ 勾稽级（恒等式通过），每级带权，按 GTA-2 Algorithm 1 聚合
- QA 任务：RAGAS 五件套（Faithfulness / Answer Relevance / Context Precision / Context Recall / Answer Correctness）+ 拒答恰当性 + 数值忠实度（本项目特色，公开文献少见）
- Agent 链路：长流程可靠性指标（passk 重复成功率、RDC/RDS 衰减、GDS 部分完成、MOP 工具调用熵崩溃检测）——B4 日志与 opencode 轨迹是现成数据源

**HarnessEval 锚点（2026-08-18 快查对照，出处见 docs/experiments/2026-08-18_harnesseval_alignment.md）**：MirroS 联合清北/Berkeley/MIT/xbench/NVIDIA 发布，把评测本身 harness 化（case 理解→Skill Library 动态路由→sub-agent 拆解→证据验证聚合），落 evidence tree，声称是 RSI 叙事。Blog: https://mirros.ai/blog/harnesseval | Code: https://github.com/mirros-lab/harnesseval-w | Project: https://mirros-lab.github.io/HarnessEval-W。定位：评测形态从静态 metric 升级为"可执行评测工作流"，是论文 B "evaluation harness" 表述的借势对象（术语决议见下）。引用细节以其仓库 README 为准（用户批复 ④，K1.5 已证 README 与文章存在口径差）。

**FORCE-Bench 锚点（2026-08-19 直连核验，用户批复 ④ 补录）**：arXiv 2607.19409 "FORCE-Bench: A Benchmark, Dataset, and Evaluation Harness for Agentic AI in Enterprise Finance"（Microsoft，开源 dataset+rubrics+harness+analysis code）。规模口径以 README 为准：github.com/microsoft/FinanceBenchmark 载 ~300 问三任务型（ERP 义务查询/公开财报绩效研究/商业简报生成），arXiv 摘要写 251 expert-annotated queries，两处不一致已如实记录（同 HarnessEval README/文章口径差模式）。评测方式：LLM judge + rubric assertions + 多 provider 对比（Finance Agent / Claude CLI / OpenAI Responses API），带工具访问与延迟约束。**对照口径：FORCE-Bench 评 agent QA 工作流端到端答案质量（8 维 rubric: accuracy/citations/clarity/depth/groundedness/recency/relevance/structure）；我们评解析管线 + schema 漂移 + 勾稽 + 自学习闭环（确定性检查在前）——评测对象互补不重叠，related work 必引。**

**差异化口径（三条）**：
1. **确定性检查层在前的混合三层 harness**：我们是"确定性优先"（run_eval.sh ①M1 门禁 ②确定性 16 问 ③NF 全确定性）→ 静态检查点树聚合（K2 v0）→ agent 深挖按需（v1 新增）；HarnessEval 是主智能体驱动、per-case 动态路由 skill。同为"三层"，但我们的前两层确定性可复现，agent 只做按需深挖。
2. **评测直接驱动验证门控自学习**：我们是闭环执行器——评测产出→schema 规则固化→回归门禁（GTA-2/Judge 精读已证路线，§1 长流程.md 旁证）；HarnessEval 是诊断系统——评测终结于分数与证据树，供研究者改进模型，不驱动被测系统自修改。
3. **将 evaluation harness 范式引入金融文档领域**（措辞定稿：用户批复 ④ 08-19，"首个"主张降级为"引入范式"）：HarnessEval 落在交互式世界模型（视频），我们落在金融文档智能体（解析+QA 检查点树）；FORCE-Bench 证明企业金融 agent 评测已有工业先行（但其对象是 agent QA 工作流，非解析管线/schema 漂移/勾稽/自学习闭环）。不宣称首创，只主张评测对象与闭环机制的差异化。

**K2 设计决策升级（2026-08-18）**：
- 方法骨架从"静态检查点树 (GTA-2)"升级为"**混合三层**"：确定性检查（已有，run_eval.sh 前三步）→ 静态检查点树聚合（K2 v0 已交付，config/eval_checkpoint_trees.json + scripts/eval_checkpoint_aggregate.py）→ 按需 agent 深挖（v1 新增，对标 HarnessEval Route+Verify：对低分/拒答/缺口叶子派 agent 追加证据与判断，B4 日志与 opencode 轨迹作审计数据源）。
- 核心实验 = **评测成本 vs 判别力曲线**（含与纯 agentic 评测的对照）：确定性层全量跑（低成本、低判别力）→ 第三层 agent 按触发子集跑（高成本、高判别力），量化 Pareto；HarnessEval 式全 agentic 评测作为对照臂。

## 4 数学形式化清单

**可直接引用（hbkeyan 已有公式）**：GTA-2 递归聚合（Algorithm 1）、Root SR / Leaf SR / Tool SR、Score/Cost、RAGAS 五件套、passk/RDC/RDS/VAF/GDS/MOP、TSR/ARS/ATS、ECE/Brier。

**本项目需自定义（论文方法章核心）**：
- 命中率：$H = |\text{matched fields}| / |\text{all target fields}|$（按表加权）
- 固化门：建议 $s$ 被接受当且仅当 $\Delta H(s) \geq \tau_{acc}$ 且基线无退化（$\Delta H_{baseline} \geq -\varepsilon$）；reject/hold 的置信判据
- 学习曲线：第 $t$ 轮样本集上 LLM 介入次数 $\lambda(t)$ 的衰减率 vs $H(t)$ 上升率，收敛条件
- 路由：期望质量-成本 Pareto $\max E[Q]$ s.t. $E[C] \leq b$，覆盖度 $c$ 作为状态变量
- PSO 适配：粒子编码 = 检查点权重向量 / 题集选择向量，适应度 = 判别力正则化目标
