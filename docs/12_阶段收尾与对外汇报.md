# 阶段收尾与对外汇报

**状态日期：2026-07-21。** 本文是面向老师和协作同学的当前单一简报；历史实验记录仅用于追溯。

## 项目目标与边界

项目在既有 JinRongAgents 上验证两类本地模型能力：

- **M1：** 将文本、PDF、扫描件和表格中的业务规则抽取为可校验的结构化结果；
- **M2：** 基于既有知识库检索证据、回答问题、引用来源，并在证据不足时拒答。

保持松耦合：已有 Web、`RAGService`、知识库、检索、来源追溯和数据仍是唯一事实来源；本地模型仅通过统一 API 接入；OpenCode/MCP 只是薄适配层。不得另建向量库，也不得绕开 `RAGService` 直接查库。

## 已实现架构与数据流

```text
现有页面 / FastAPI / LangGraph
             ↓
       RAGService（唯一知识底座）
             ↓
只读 MCP：检索、来源读取、知识库列表
             ↓
OpenCode + 已验证的 Qwen3-14B 本地生成服务路径
```

知识 MCP 保持三个只读工具：`knowledge_search`、`knowledge_get_source`、`knowledge_list_collections`。
另有独立 Vision MCP 首版，当前仅提供受限的 `vision_ocr_extract`：图片根目录、模型键和
token 上限均在服务端校验，推理在隔离视觉解释器中执行既有 smoke 脚本。它不访问数据库，
不改变知识 MCP，也不等于 M1 闭环或 OCR 质量验证。配置中的 M1、M2、校验 Agent 是逻辑定义，
不等于已完成编排。

## 角色 B 的责任与交接

角色 B 负责模型/数据侧：受控环境、候选模型、M1/M2 数据与标注、评测脚本、模型服务接口、数字结果和最小演示。交付应是冻结的接口、批准的数据口径、可复跑脚本、脱敏汇总和已知限制。

另一位同学负责工程集成：完整 Agent 编排、业务 Prompt 深化、会话/状态、权限、异常降级、前后端与企业接口集成、运维。交接条件不是“配置文件已有多个 Agent”，而是单 Agent M1/M2 的数据、指标和接口都已可复核。

## 已完成工作（按阶段）

1. **基础与模型准备：** 保留现有 RAG 架构，准备本地生成、检索、视觉和表格候选的下载/冒烟记录；这类记录不等于业务效果。
2. **只读 MCP 接入：** 复用 `RAGService` 实现三个知识工具，并配置 OpenCode provider、权限和逻辑子 Agent；2026-07-21 增加了与其隔离的 Vision MCP 实现，采用全局询问、M1 允许、M2 禁止、校验 Agent 可允许的最小权限。
3. **服务与协议验证：** Qwen3-14B 完成历史本地生成服务验证，MCP 协议和真实工具路径通过验证。Qwen3-14B 是当前唯一已验证的 OpenCode/MCP 生成服务路径。
4. **稳定性修复与验收：** 定位到子进程继承输出描述符，使已退出的 OpenCode 父进程看似超时；改为临时输出文件、等待父进程并只清理本次进程组。正式只读稳定性验收 **20/20 通过**。
5. **M2 评测准备：** 提交 20 条合成/脱敏夹具和评测器；聚焦 MCP、稳定性、夹具和评测器的测试 **19 项通过，6 个弃用警告**。

## 处理过的问题（已脱敏）

- 网络与 SSH 连接曾有波动：采用可恢复的 Git 同步和 tmux 观察，不把连接状态当作模型结果。
- 曾连接到错误的开发数据库环境：恢复为通过既有服务层和受控环境变量接入，避免直连和信息外泄。
- OpenCode 的 JSON 状态解析不完整：稳定性脚本只认目标工具的成功状态，不保存回复正文。
- 进程描述符继承造成超时误判：生命周期修复后，正式 20 次检查全部通过。

## 已验证结果，以及它们不证明什么

已证明：只读 OpenCode/MCP 调用在当时的受控条件下可连续完成 20 次；MCP 仍复用既有知识底座；测试覆盖了关键脚本和回归场景。

未证明：当前任何服务仍在运行；M1 OCR 或规则抽取质量；M2 的业务 Recall@5、来源命中率、拒答率或答案质量；多 Agent 编排、生产权限、状态管理或企业集成已经完成。Vision MCP 的实现与协议发现也不构成真实 OCR 效果或持续运行结论。

截至 2026-07-21，Vision MCP 的发现协议已在 `wzh_vllm` 中通过；要求使用的公开中文报纸
demo 图片未在可用文件系统中找到，因此未运行真实 OCR 调用，也没有记录原始文本、耗时或
显存数据。该缺失是补做受控真实推理验证的唯一直接阻塞，不得用其他图片替代或推断结果。

## 未完成项、依赖、风险与优先级

1. **P0：M2 数据授权与标注。** 负责人提供并批准合成标签到稳定来源的本地映射，以及人工答案质量标注；映射和私有来源不得提交。没有它们不得报告正式业务指标。
2. **P0：运行正式 M2 评测。** 仅在 P0 数据齐备后，用已有评测器报告检索、引用、拒答、延迟和人工质量结果。
3. **P1：建立 M1 基线。** 准备批准的 OCR/规则抽取集，定义人工复核口径，得到首个数值基线；此前不比较模型优劣。
4. **P1：单变量优化。** 在固定数据后逐项评估切分、检索、重排和生成候选，保留可复跑的脱敏结论。
5. **P2：工程交接。** 数据、接口和指标冻结后，由工程同学实现完整编排、权限、状态、降级和集成。

主要风险是把下载、冒烟、历史服务验证或 20/20 工具稳定性误写成业务质量或当前运行状态。所有后续结论必须标注数据口径、批准状态和验证范围。
