2026-10-31。根据[事前冻结的实验卡](archive/plans/FEEDBACK_CONFLICT_AGENT_PILOT_PLAN_20261031.md)，用 OpenCode + GB10 本地 Qwen3.6-35B-A3B 实际运行了 6 条隔离工具 Agent 轨迹。任务改造、资源合同和参考 hash 在 `0c449e2e` 冻结；聚合数字、轨迹哈希、检查绑定及可见行为指标见[可复算摘要](13f_feedback_agent_summary_20261031.json)。

## 实际历史：两个检查器确实产生不同反馈

先前 Agent 在 T1 根据明确的 25 类规则和 Q3 报告期，从 13F 输入算出 **2,710**，受控合同检查通过。之后用其真实输出构造只改变 q2 的原任务 verifier 控制：原基准检查器要求 **2,451**，因此返回失败。其余原题答案借用发布 expected，仅用于隔离检查器的 q2 谓词；Agent 并未解决原四题。历史由[生成器](prepare_13f_agent_history.py)绑定实际输出、原始轨迹与两个检查日志，再给目标任务使用。

这确实是“受控新增书面类别合同与旧检查器不一致”，但**新合同是我们人为加的**；不意味着旧自然题的股票分类存在唯一人工 gold。[之前的源码审计](FINANCIAL_FEEDBACK_CONTRACT_FINDING_20261031.md)另行记录了旧 solution 的相邻字符串拼接。

## 下一任务的五个条件

目标 T2 使用同一 Q3 数据及明确规则、更换管理人；目标合同结果为 938。每组只运行一次，Agent 独立启动：

| 提供给 T2 的信息 | 合同结果 | 转发 POST | Agent + verifier 墙时 |
| --- | ---: | ---: | ---: |
| 无历史 | 938，正确 | 7 | 47.705 s |
| 只有 T1 实际历史 | 938，正确 | 9 | 72.873 s |
| 历史 + 明确合同检查通过反馈 | 938，正确 | 12 | 175.195 s |
| 历史 + 原基准检查失败反馈 | 938，正确 | 14 | 271.468 s |
| 同一失败反馈 + 先核实冲突的提示 | 938，正确 | 12 | 218.584 s |

五组均正常退出、生成严格 `count.json` 并通过同一个目标合同测试；结果文件的内容与 hash 完全一致。无模型程序只读取同样可见的输入与任务文本，直接按明确条件过滤：T1/T2 分别为 **2,710/938**，两次均通过对应 verifier，程序内部墙时分别 5.568/5.583 秒。这是同任务的强简单基线；其程序时间不含 Docker 和 verifier，不能与表中端到端墙时直接相减。

## 轨迹支持什么

五条目标轨迹的 shell 命令均没有出现 T1 管理人名或两个 T1 计数，Agent 可见文本也没有出现 `feedback/checker/conflict/discrepan` 这些字符串。这个文字匹配只能说明**没有观察到按上述标记显式复核历史冲突的动作**，不能证明模型内部完全没有使用反馈。各组最终均按当前书面规则得到同一目标答案，所以本实验没有发现错误反馈损害目标结果，也没有证明“核实冲突”提示改善结果；无历史和确定性程序已完成同一任务。

不同条件出现 7–14 次调用和不同墙时，属于单次过程观察；上下文内容、模型生成和机器负载均不同，不能归因为反馈本身。仅历史组曾有一次 Python 子进程被系统 `Killed`，随后仍完成；该资源故障也说明直接把耗时差解释为认知机制并不可靠。每组只有一次、同一来源族，且反馈组给出的检查器名称不同，不是严格的单因素重复或跨来源统计比较。历史仅作为上下文提示，**没有自动生成或更新持久 skill**。

## 资源与后续

六次合计 **61 次转发 POST、550,076 reported step tokens，其中 474,278 为缓存读取**；0 本地 proxy 拒绝。含源任务的一次结果，历史反馈按实际原检查器执行日志生成；未训练、未调用付费 API 或人工 judge，未写生产 Memory。原始任务、输入、实际 Agent 轨迹和检查日志保存在 GB10 `/home/testuser/wzh/research_evidence/agent_learning_20261030/13f_feedback_conflict_20261031/`；本仓库只保存构建/运行/复算脚本、聚合数字及 hash。

与近邻 [RSE-Bench](https://arxiv.org/html/2610.19910) 对照：其 N-Bind 将真实结果与另一条执行记录错配并保持原评分合同；本次是对已暴露的旧检查器与人为明确的新合同作一次对照。后者不是自动成立的新问题或方法，且尚未实现其学习后冻结评估。

下一步应让经验具有**影响后续行动的真实机会**：寻找规则不能从当前任务一眼直接计算的多个工作流，包含可靠反馈、过期反馈和证据不足三类；让 Agent 实际从源任务生成可复用经验，并对新任务冻结。比较原始轨迹、普通历史、简单可见规则、当前任务重试和可核查的经验更新策略；分别衡量新任务正确率、旧任务保留、错误复用、合理不确定以及生成、检索和验证成本。把本例保留为检查器冲突正负控制，不再在这个已被简单规则和无历史完成的面板上堆提示或宣称 IJCNN 方法收益。
