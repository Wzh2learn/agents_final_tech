## 关键尸检：数据结果与输出合同要分开

无经验组的每个修改项使用 `{id, changes: [{field, old_value, new_value}]}`，而题目要求每个修改项平铺为 `{id, field, old_value, new_value}`。我们在模型全部运行结束后编写[严格无损转换器](flatten_pdf_excel_changes.py)：仅展开已有字段、不读取参考答案、不改变值，遇到未知嵌套字段就拒绝。转换后无经验输出恢复 **15/15 删除、20/20 修改与值**，与带经验组的输出 JSON 内容完全一致；原 verifier 在独立无网容器中为 **11/11**。原始 7/11 结果和原始报告不被覆盖，转换后的通过也不等于原 Agent 按合同交付。

因此，本例观察到的原始通过差异体现为**最终输出格式**的差异；两次各一条轨迹、模型随机性和新增提示信息并未被控制，不能断定是经验导致格式正确。两组生成的代码均以完整 ID 做集合/字典匹配，公开任务本身就给出 ID 格式；在其可见叙述文本中没有找到发票或模糊匹配的明确引用，但这不能证明模型内部没有使用提示。带经验组自述“20 处变化覆盖 18 名员工”，参考实际为 20 名；这次正确的是产物，不是该句自报。

## 强简单对照

运行后，根据公开任务与输入构造[确定性精确 ID ＋锚定字段对照](pdf_excel_exact_baseline.py)。它只读取 Agent 也能访问的 PDF 和当前 Excel，使用现有 pypdf/openpyxl，对齐其他字段重建单个变化，歧义情况留作未解决；不读原始 Excel、expected 或测试代码。隔离无网容器内处理 10,500 条旧记录，得到 **15/15 删除、20/20 修改及字段值**；单独挂载原 verifier 为 **11/11**。实际程序内部墙时 7.442 秒、模型调用 0；这与上表包含 verifier 的端到端时间不是严格同口径比较。

该对照是**事后、同一合成实例、针对任务格式编写**，不能推断它对其他 PDF 或多个字段同时变化都有效。它说明本任务不能单凭“Agent 找到正确差异”支持比现有规则更强的经验学习主张。模型报告、无损转换和确定性程序的比较既保留了实际合同失败，也避免把格式差异误写成事实恢复差异。

- 三次合计 **36 个实际转发 POST**，step 计量总共 **464,901 tokens，其中缓存读取 299,137**；不能将总量当作全新输入 token。无训练、付费 API、人工 judge 或生产 Memory 写回。输出预算和逐组成本在 JSON；确定性转换、对照与复评无需模型调用。
- 原始事件、失败、代理回执、原 verifier、规范化副本和事后对照在 GB10 `/home/testuser/wzh/research_evidence/agent_learning_20261030/pdf_excel_transfer_20261031/` 与相邻 `pdf_excel_exact_baseline_20261031/`。本仓库只保存脚本、聚合数字和 hash；第三方数据仓库许可仍待核实。
- 原始任务规则和两个外部评分检查都在 Agent 退出后单独挂载。旧/新表及 benchmark reference 的数值复核属于同一数据制作链，PDF 只独立核了 ID，没有将其称为人工 gold。
- 一些 Agent 尝试在无网容器中安装缺失的 `pdfplumber`，没有访问外部网络；也出现将大段或完整数据打印到工具输出的命令，提示词中的“只看样本”并未由 harness 强制。这影响工具和上下文成本，是后续实验需要处理的运行条件。

**下一研究动作**：转向不同数据来源、包含经验适用/不适用且可从执行反馈观察差异的多个工作流族；冻结原始轨迹、等信息普通历史、任务 skill、简单规则/无损输出转换及可学习候选。在模型和总体预算匹配下分开报告事实、行动、合同与完整交付，先验证经验是否实际改变动作，再评估跨来源的最终结果。训练只在取得来源隔离、可核验监督和比这些简单对照更有空间的任务后推进；本次结果不否定其他形式的经验学习。
