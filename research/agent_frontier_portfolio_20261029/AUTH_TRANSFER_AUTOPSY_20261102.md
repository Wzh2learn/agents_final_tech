# Agent 历史经验与任务变化：API 认证开发试验

2026-11-02 | `POSTHOC_DEVELOPMENT_NOT_OFFICIAL_HARNESS` | [可复算摘要](AUTH_TRANSFER_SUMMARY_20261102.json) | 下一步以新来源和不同变化类型为主，不把本例结果外推。

## 问题与设计

研究源任务中关于 HTTP 429 限流重试的真实 Agent 程序和反馈，能否帮助同族的新任务区分令牌过期与临时服务失败。源任务由 OpenCode 和本地 Qwen 模型完成；目标任务来自同一 SkillEvolBench 版本，属于**同源开发探索**，不是独立来源确认。

目标任务分别执行一次：① 无历史；② 可选择读取源任务说明、源程序与反馈；③ 明确要求读取同一组源材料并判断其适用性。第三臂是在看到前两臂结果后追加的，研究者启动前已查看目标任务测试和参考实现；模型本身在执行时均未挂载目标测试和参考实现。三臂提示信息、运行时间和执行顺序不同，也没有多种子重复，因此不能作随机或因果比较。

环境代码、原始响应、请求和执行日志均保存在 GB10 的 `research_evidence/agent_learning_20261030/`；上游任务源码许可尚未确认，不向 Git 复制或公开。三次目标 Agent 使用本地模型服务与隔离容器；任务来源、镜像及核心资产哈希见每条 `intervention.json`。本次未独立核验服务端实际模型权重哈希。

## 校准与反例

事后在隔离容器中运行上游嵌入式 verifier 的 Python 主体；没有执行其 pip 安装，也不是官方 Harbor 环境。构造的伪造返回仅为白盒负对照，不代表自然 Agent 输出：

| 程序 | 上游 outcome | 上游 process | 上游加权分 | 自写 mock 行为 |
| --- | --- | --- | ---: | --- |
| 起始程序 | 4/7 | 2/4 | 51.67 | 5/8 |
| 上游发布的参考实现 | 7/7 | 4/4 | 100.00 | 8/8 |
| 人为伪造返回与字符串对照 | 4/7 | 4/4 | 85.00 | 0/8 |
| 三条真实 Agent 输出 | 各 7/7 | 各 2/4 | 各 66.67 | 各 8/8 |

这个构造性反例的 **整体 verifier 仍然拒绝**，不能说它被错误判定为任务成功；但加权总分将该反例排在三条行为检查全过的真实输出之上。过程检查在 `auth_client.py` 内搜索特定字符串，而这三条输出通过它调用的 `auth_policy.py` 实现相应分支。因而若仅用该 process 分数或加权分理解“是否实现恢复动作”，会忽略跨文件委托；若原任务另有必须在特定文件内实现的合同，则需独立核实，不能单凭此处称上游检查器普遍错误。

事后自写 mock 不调用候选项目自身的 mock，覆盖初始成功、过期后刷新、503 恢复与上限、非过期 401、其他错误、过期与 503 混合、刷新失败，共 8 项。它由同一研究者在观察结果后设计，**不是外部独立评测或未见任务确认**。另加持续返回过期状态的压力观察：三条 Agent 解与上游参考解都会持续刷新，均在自写测试的第 9 次认证调用触发保护上限；原任务未规定这类持续过期的上限，不将其计入 8 项成功数或直接裁定为违约。

## 对下一步的影响

1. 本例中，“提供但未读取”和“确实读取”最终均与无历史产生同一程序，**没有识别出旧经验的效果增量**；此前没有读取经验也提醒我们必须记录检索、读取和使用过程，不能只看是否提供了文件。
2. 上游任务对直接文件字符串的过程测量，与跨文件可执行行为不完全一致；下一批需要将行为、过程合同、结果消费与不可判定情况分开报告，继续保留原始评分。
3. 下一步应寻找与本例不同来源、不同变化机制的自然任务，并加入无历史、普通历史、任务 skill、透明规则和相关方法；只有在新的任务确有可区分的错误或成本空间时再设计学习方法。当前材料可作学位研究的开发记录，不作为第二篇论文方法成立的证据。
