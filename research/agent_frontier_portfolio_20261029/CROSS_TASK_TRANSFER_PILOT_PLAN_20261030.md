# 跨任务经验迁移：制造缺陷分类开发实验

2026-10-30，模型调用之前的计划；本文件不能证明实验已运行。目标是研究实际工具 Agent 能否把前一任务中发现的经验用于不同工作流，不以提示词形式出现就宣称发生了学习或有效迁移。

## 起点与问题

前序公开发票任务中，供应商 `Vendor 11` 被 `partial_ratio` 与 `Vendor 1` 视为满分相似；具体反馈促使 Agent 先尝试精确名称再模糊匹配。强确定性补丁也完成同一任务，见 [发票回执](INVOICE_AGENT_RETURN_20261030.md)。从这个已经暴露的开发案例中，仅提炼“在适用时，先核对完整标识/名称，再谨慎处理局部匹配造成的歧义”的经验；不提供制造任务标签、测试代码、参考输出或示例答案。

目标任务是 SkillsBench v1.1 的 `manufacturing-codebook-normalization`：把制造测试日志映射到各产品 codebook。其约 2.6 MB 的公开日志和三个 codebook 原样提供，完整任务要求由公开 `task.md` 提供；工具通过文件读取输入、编写并执行程序。目标任务与发票是同一公开 benchmark 的不同任务族，原始数据不相同，但这不是独立 benchmark，模型预训练接触情况未知。任务涉及文本、语义、设备及 station 约束，旧任务中的名称匹配不一定适用；特别不能把局部文字相等视为分类真值。

## 比较与执行合同

三个条件各一次，固定同一任务文件和输入哈希、同一 Qwen checkpoint、OpenCode、容器权限、可用库、启动提示、工具及预算：

1. `no_memory`：仅有当前任务和输入。
2. `transferred_memory`：同一当前任务和输入，额外提供前述由发票轨迹归纳出的短经验；允许 Agent 根据当前任务判断经验是否适用。多出的经验信息和输入 token 如实计入；这不是信息量相等的处理效应。
3. `task_skill`：加入原任务公开 skill；该 skill 含该任务的详细流程和规则，信息量不同，是任务专属能力参照，不解释为公平等信息因果比较。

每次最多 16 次物理 POST、900,000 字节请求体、每步骤输出上限 8,192 token、最长 600 秒；失败、截断和全部请求也计入。Agent 在无网络、资源有界的 Docker 环境中运行，外部仅允许受限连接已有本地研究模型服务；测试、oracle 和参考答案不挂给 Agent。每次结束后，在单独无网络容器内运行原 verifier。保留完整原始事件、请求数、usage、输出及失败；结果不能改写为官方 BenchFlow 成绩。

原任务的 16 项 verifier 包括格式、覆盖、合法 code、文本重叠、station 与置信度约束；它不是逐记录人工语义金标准。主要报告：有无可交付输出、通过/失败的检查名称、覆盖、非法代码、station 与匹配证据等可计算统计；不将 `16/16` 等同于真实分类准确率。必要时对公开输入作事后独立、可复核的抽样标注，但不能泄露给 Agent，若无法可靠判断则标 `UNRESOLVED`。多个记录来自单一任务工作流，不作为多个独立任务族。

## 解释与后续

按此前发票数据/轨迹定义经验，在本任务启动前冻结本卡和脚本；实际脚本、输入 hash 与各次启动时间在回执中核对。单次结果属于开发性可行性与机制观察，即使记忆组更好，也要查它是否真的使用旧经验、成本、无效匹配以及简单规则是否可获得同一信息并追平。若所有组无输出，先分离执行预算、依赖、输出合同和任务困难，不能宣布方法失败或有效；若有可识别信号，再设计来源隔离、多族、多随机种子与匹配知识/预算的确认。原先看过公开任务列表和 verifier 结构用于资格判断，不能称严格盲选或预注册确认。
