# 经验中的错误操作：来源可见验证试验

2026-11-01，面向[跨项目开发结果](DEPENDENCY_CROSS_PROJECT_RETURN_20261101.md)的后续计划。原 skill 包含有效的本地缓存步骤，也包含“首次不能使用 `--skip-db-update`”和“将时间改到未来”的建议；目标运行中确实使用了后者。普通历史与确定性工具已有成功例，因此这里验证一个局部机制，不预设复杂经验方法有优势。

先在**源任务**的原始锁文件、同一个冻结扫描器/漏洞库上，建立全新预填充缓存副本，在隔离容器首次扫描时执行 `--skip-db-update`。记录返回码、完整扫描报告、相对源扫描的漏洞身份及 CVSS、缓存时间元数据前后哈希。该测试不读取两个目标项目的扫描结果或隐藏参考。仅当扫描成功、结果与已有源扫描一致且时间元数据未变，才可以把“本环境的新缓存副本可用该命令”作为经验修订的有限见证；否则保留失败并重新判断，不得假装通用有效。

若有见证，在保留原始 skill 的前提下，做一份**人工规则驱动的局部对照**：只纠正“首次不能 skip”和伪造日期的建议，把该命令限定在已经测试的工具/缓存条件；其他步骤、旧 HIGH/CRITICAL 的任务范围和错误示例代码保留，提醒执行者以当前任务为准。它不是模型自学，也不是完整的通用 skill 安全检查器。

在同两个已看过的公开项目上各运行一次修订 skill，沿用前批相同输入、模型、代理和 32 POST / 2.4 MB / 900 秒上限；对照前批原 skill 和普通历史。记录最终快照相对正确性、空输出、可见元数据变化、是否保留不适用的严重程度过滤及成本。比较是开发性、非随机、多条件单次观察；若没有改善或出现新退化照实保留。不要将这个针对单技能的修补称为通用方法创新。

后续需要扩展到新来源和**不同工具工作流**，并与 Skill-V、CoEvoSkills、普通历史、明确工具文档及同预算验证对照；任何学习型版本还需同模型和训练成本控制，证据不足则调整方法方向。
