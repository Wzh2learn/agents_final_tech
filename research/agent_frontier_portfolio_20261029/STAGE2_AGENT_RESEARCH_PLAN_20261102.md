# 第二阶段：反馈条件化的可复用纠正技能学习

> 2026-11-12。Goal active；用户已确认FCCL主线及校内API总额度1000M。inquiry：first-principles → minimal-experiment；依据最新专家全文及独立复核调整，不再以主动审计为论文主线。

## 研究问题与第一条技能

**问题：**Agent能否从真实纠正成败中，学到“同类反馈在什么执行条件下应采用哪一种纠正片段”，并在新任务中提高成功率或降低同等成功的全成本？FCCL为工作名，方法有效性和独立增量均待实验。

**第一条技能：修复调用/返回契约时保留已满足的功能约束。**代码报接口、返回结构或参数错误时，不能仅靠删除操作数、绕过分支消除报错；应依据当前调用关系与已获得的反馈，选择适当的调用绑定修复或结果适配修复，再执行检查并决定退出/继续。Astropy旧A5中删除第二操作数破坏回归，是开发动机而非新方法结果；不把一句手写禁令当学习。

**表示：**输入x=(h,f,e,q)，分别为决策前公开历史、实际在线反馈、可见环境/接口绑定、当前已有检查证据。隐藏评分、参考补丁、未来动作不进入x。技能ω=(I,π,β,V)含适用条件、可执行纠正策略、退出条件与公开验收；经典option表示本身不主张新颖性。

**已检验参考：**[原型](corrective_skill_policy.py)的配对偏好/布尔效果转移不是新方法；两题实跑未超过强基线，一题未调用规划器。停止文字卡片与自由绑定路线，细节见[批次记录](results/FCCL_FORMATION.md#transfer-v1)。

**下一学习靶标：联合学习纠正程序、适用条件与参数绑定。**Pθ(x)输出能执行的程序、绑定b、前提I及退出β；条件可在程序内部，不强制另建外层选择器。学习从实际纠正成败提出参数化程序，经来源执行约束排除错误版本，反馈只修订受到反例否定的绑定或分支。Getafix模式、CEGIS反例修订、CIPO绑定和SkillRevise保留约束均已有；它们是实现参照，不单独作创新。

**已排除的复杂化：**[结构参照](results/FCCL_FORMATION.md#program-learning-v2)已解释两来源。随后[关系抽取](results/FCCL_FORMATION.md#relation-learning-v1)读取7个已有完整程序状态，分项学习的综合判断在两个完整谓词域均与正例Find-S相同。停止本面板的绑定选择器、表示变体与分类层扩展；这些不是独立迁移证据。

**下一判别：**在未参与形成的新自然任务中固定真实失败现场，对照同源数据/反馈/预算的ReGAL式程序提取与重试、强静态参照，以及候选“仅从失败路径的数据流/AST关系生成新谓词、细化纠正程序”。更新须输出可执行程序/绑定并保留已通过要求；若产生动作差异再测原生成功/回归及全成本。普通失败定位同样纳入，排除只缩短输入的收益；无区分信号则不扩样。此为自动抽象候选，不宣称已有新方法。

**监督与退出：**完整程序及续行结果产生监督；多种修法有效则保留多解，不造唯一负例。共同失败不造正例，9/10也不算整题成功。强基线共享源程序、AST/栈线索、反馈和总预算，各组程序由同一入口实际调用，再交共同Agent续做。静态程序已够用则不训练选择器；留出不调参，不在测试现场免费试遍候选。
