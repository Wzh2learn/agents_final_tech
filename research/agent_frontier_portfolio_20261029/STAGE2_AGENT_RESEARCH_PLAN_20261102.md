# 第二阶段：反馈条件化的可复用纠正技能学习

> 2026-11-13。Goal active；激活/一函数消融已收束：局部修复生效、完整任务失败，v2停扩跑。下一先修正纠正片段的学习、退出与切换规则。

## 问题与学习对象

从真实纠正成败学习何时、如何执行和退出纠正操作，在新任务提高成功率或降低全成本；同时保留已满足的约束。FCCL为工作名。

公开输入x=(历史,反馈,环境,已有检查)；技能ω=(适用条件,可调用策略,退出,公开验收)。完整程序及续行后果监督更新，不含隐藏评分、参考补丁或未来动作。

## 专家要求：完成与缺口

| 第一条技能与真实闭环 | [SymPy技能调用/反馈更新](results/FCCL_FORMATION.md#execution-fragment-v1)已验；[Django源](results/FCCL_FORMATION.md#formset-source-v1)最终3/3目标＋49/49回归。 |
| 新任务方法对照 | [旧两题四组](results/FCCL_FORMATION.md#transfer-v1)及[新四策略](results/FCCL_FORMATION.md#formset-target-v1)已跑，当前实现无优势。 |

主线仍为“反馈→纠正策略学习→行为变化→后续改善”。形式化、生成脚本或源内成功不能替代后续收益。

## 最新实验及取舍

[冻结五组](results/CONTINUATION_PROGRAM.md#activation-v2)按序原生1/0/0/1/0。普通编辑修好网络却多充值；新规则和一函数消融都忽略移动数据关闭的明确反馈并转人工。新规则仅保住正确充值额，简单拦截和普通Agent完成全题。v1/v2不再扩跑或补提示；数量反例仍约束其适用范围。

## 下一轮唯一交付

从“补全整份旧流程”收回到当前Goal要求的纠正片段：学习何时执行、何时退出或切换，兼顾已满足的条件和剩余目标。当前[定位规则](continuation_program.py)及[client](continuation_client.py)保留为失败参照，不作为已验证方法。

1. 先完成一次离线机制设计：用现有完整成败续行，明确一条片段学习/更新规则的输入、输出、监督与接受条件；解释局部修改为何保不住整体任务。当前题与全部反馈仅作开发，不转成留出。
2. 同时比较固定短片段/固定交还Actor、普通反馈更新和HASP/SkillRevise等近邻。单纯更早交还控制或修复旧函数不算独立创新；具体区别必须落在学习规则和可观察预测上。
3. 规则明确后冻结最小同预算验证，在新开发任务比较原生成功和形成＋执行总成本。无信号停具体实现；有收益再扩独立来源、重复及跨项目，随后考虑训练。不在本面板重复追成功。
4. Actor只见公开输入；私有状态/参考/评分留host。保留现役隔离、节流及全部角色/失败计量，不扩治理系统。测试留出未启用；协议或方法重大改变时再定向审阅。

用户已更新Goal：近期交付为新任务方法收益；源内闭环/旧四组按完成处理，保留学习主线和12月中旬IJCNN决策点。
