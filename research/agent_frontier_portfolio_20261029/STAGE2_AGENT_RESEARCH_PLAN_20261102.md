# 第二阶段：反馈条件化的可复用纠正技能学习

> 2026-11-12。Goal active；当前为方法发现。新SymPy来源已完成代码修复及尸检，停止在该题追加运行；下一候选尚未实现。

## 问题与学习对象

从真实纠正成败学习何时、如何执行和退出纠正操作，在新任务提高成功率或降低全成本；同时保留已满足的约束。FCCL为工作名。

公开输入x=(历史,反馈,环境,已有检查)；技能ω=(适用条件,可调用策略,退出,公开验收)。完整程序及续行后果监督更新，不含隐藏评分、参考补丁或未来动作。

主线仍为“反馈→纠正策略学习→行为变化→后续改善”。形式化、生成脚本或源内成功不能替代后续收益。

## 最新实验及取舍

四策略补丁全过，普通反馈同效更省，旧重绑定停止。[效果预测](results/FCCL_FORMATION.md#effect-forecast-v1)6次/172,861tokens亦未增加选择收益，停止该控制器。新[SymPy12481](results/FCCL_FORMATION.md#new-source-v2)实际OpenCode＋DeepSeek16次/101,458tokens：代码1/1目标＋7/7回归通过，Actor追查额外失败至触帽；CPU配对复算发现那两项在原版也同样Skipped/XFail。保留真实正确修复与失败停止行为，基线差分诊断列作强简单参照；不再救该单题。

## 下一轮唯一交付

候选：从真实反馈学习可执行的跨角色纠正续行程序。节点为工具调用或向协作方发出的请求，包含公开反馈分支、参数绑定、退出；保留已确认进度，未知条件先取证。学习规则为“失败前缀→提出一处程序编辑→同起点执行旧/新程序的完整续行→按原生结果、约束与总成本决定更新”。推理时只执行已选策略，不能免费试遍分支。

1. 先在新协作任务验证是否存在超出静态流程的纠正需求。候选载体tau2官方v1.0.1（`fc0055dc`）只读核查完成，尚未安装/运行；固定版本、公开输入及同模型预算，先3个开发来源＋1个未见任务，不强制造失败。
2. 同时保留普通反馈/历史、固定重放、**按用户已报告进度继续的官方流程**及匹配近邻。官方流程同效更省则停；角色标记、配对、恢复、图结构本身均不新。WER/Skill-α/HASP/CIPO已覆盖执行更新等关键部件，具体差异须来自程序编辑及新任务收益。
3. 接入GB10＋OpenCode。服务端保留用户私有状态/评分，Actor只见合法工具、公开观察和用户消息；不能直接调用用户工具。分支须恢复双侧历史、turn及双数据库，不把仅重放写操作称为完整恢复。所有角色/形成/失败调用计入总预算。
4. 有收益再扩2项目或独立来源、4—6任务及重复/留出/消融，之后考虑LoRA。tau2不同领域仍是同一benchmark。无残差就调整具体机制，不建设通用调度框架。

用户已更新Goal：近期交付为新任务方法收益；源内闭环/旧四组按完成处理，保留学习主线和12月中旬IJCNN决策点。
