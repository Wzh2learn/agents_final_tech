# 第二阶段：反馈条件化的可复用纠正技能学习

> 2026-11-13。Goal active；方法发现。纠正程序及反馈更新已实跑，迁移优势未立；当前先收束证据，再做有限机制比较。

## 问题与学习对象

从真实纠正成败学习何时、如何执行和退出纠正操作，在新任务提高成功率或降低全成本；同时保留已满足的约束。FCCL为工作名。

公开输入x=(历史,反馈,环境,已有检查)；技能ω=(适用条件,可调用策略,退出,公开验收)。完整程序及续行后果监督更新，不含隐藏评分、参考补丁或未来动作。

主线仍为“反馈→纠正策略学习→行为变化→后续改善”。形式化、生成脚本或源内成功不能替代后续收益。

## 最新实验及取舍

旧重绑定/效果预测、SymPy12481及tau2三来源按原记录冻结。[最新五组](results/CONTINUATION_PROGRAM.md)普通反馈原生通过，普通编辑反复充值导致未过；G0/普通历史/局部编辑因限流缺原生评分。离线真实公开状态重放显示三份程序均会重复写操作，局部编辑只修末端退出。该反例指导下一学习规则，不把中断记作方法失败。

## 下一轮唯一交付

学习对象已实现：[续行程序/局部编辑](continuation_program.py)及[实际执行器](continuation_client.py)。下一只验证触发/退出和已完成效果保持，仍以新任务原生成功及**形成＋执行总成本**裁决。

1. 先完成已有新DEV三组的有效比较。新批统一声明请求间隔3秒、开跑冷却61秒，错误后止发；同一冻结程序/过去信息/原预算，另存attempt，不覆盖429。只补中断组，不扩其他面板，不计为独立确认；不同节流批次不直接比较墙时。
2. 具体学习修正：从公开执行回执定位失效触发条件，而非一律编辑最后交还节点；更新须保留已提交动作效果。先对比“成功写操作只做一次”的简单规则与同信息普通编辑；同效更省则停复杂实现。尚未实现/验证此更新规则，不预设新颖性。
3. 后续须补静态流程/短历史及匹配WER、Skill-α、HASP或SkillRevise参照；执行、配对、局部修订已有，须落到具体增量。推理只运行所选策略，所有角色/形成/失败都计成本。
4. Actor只见公开输入；私有用户状态和评分留host。分支恢复双侧历史、turn、双DB，并使用原题评分。测试留出未启用；有收益再扩独立来源、4—6任务/重复/消融，之后考虑训练。

用户已更新Goal：近期交付为新任务方法收益；源内闭环/旧四组按完成处理，保留学习主线和12月中旬IJCNN决策点。
