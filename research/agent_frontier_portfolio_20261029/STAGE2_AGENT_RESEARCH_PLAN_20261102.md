## 两条并行问题线

1. **经验的形成与适用**：从实际执行过程、工具输出和反馈中生成技能或经验，研究模型能否区分可复用步骤、前提条件和可能过期的细节。比较无历史、原始轨迹/代码、普通总结、任务 skill、透明规则及公开近邻；观察旧知识有用、无用和误导三类情形。
2. **变化后的自我修订**：面对新的任务合同、工具版本或反馈冲突，探索 Agent 通过小规模可执行检查、失败反馈与局部修订更新经验。备选包括提示/工具、经验选择器、轨迹监督与小规模 LoRA；先有可核验的训练信号，再做预算匹配和来源隔离，避免把训练集参考或隐藏答案当反馈。

两线既可形成独立机制，也可能合成一个有说服力的方法；最终是否构成两个硕士创新点以实证和文献对比为准。已有 Paper E 负责评价与证据解释；后两点与 Agent 学习相关即可，不要求三个点共用同一数据集或都包装成系统贡献。

## 输入格式变化的可视化工作流：资格与开发（2026-11-04）

**问题与假设**：真实源任务的经验能否同时保留可迁移的可视化步骤，并在输入从 CSV 变成 JSON、TSV 时及时替换读取方式？这是同一数据及工作流上的格式变化开发问题，不是自然软件版本变化或跨来源泛化。研究者已查看三题说明及目标测试，Agent 本身只接收当前说明、输入和指定来源经验；测试只在任务结束后加载。数据来自 SkillLearnBench 固定提交 `726e1f79b96b0cb3d729d0e55a1c847e0b5353ae` 的 `stock-data-visualization-1/2/3`，上游注明 Kaggle 输入来源，底层再分发许可待核；输入和上游代码只在 GB10 内部保留。

**先验执行合同**：先固定隔离环境、D3 版本和浏览器验证器，并对发布参考及明显错误反例核验；若参考无法通过或浏览器不可用，先修环境并记录，不能把工程故障记作 Agent 能力。资格通过后先用无历史 Agent 完成源 CSV 任务，保存实际轨迹及独立反馈；源结果无论成功失败都如实保存，生成经验只使用源任务中模型实际可见信息和事后允许的源反馈，不泄漏目标测试。目标 JSON 与 TSV 分别比较无历史、由源轨迹及产物整理的历史、源轨迹生成 skill；以相同工具、时间和调用上限执行，记录文件实际读取、正确动作、原始浏览器测试、独立必要条件、失败与总成本。另尝试从真实源产物出发的透明格式适配作为强基线，其适用条件与所用信息单列。首批目标每臂单次只作开发，任何追加条件说明事后选择；未变更 CSV 对照或更多重复视实际结果补充。

## 任务组合和实验顺序

- **开发阶段，11 月上旬**：复用现有依赖扫描、DBSCAN、PDF/Excel 和工具代理基础设施，同时搜寻至少两个不同于这些已暴露面板的新工作流或公开版本变化。每个候选保留可运行任务、变化前后合同、来源/许可、可见反馈和可执行或人工可复核结果；无法判断时保留未决，不用已知答案凑例子。3–5 个工作流族是开发目标，不把同一代码库的多行或两个参数变体当作独立族。
- **开发比较，11 月中下旬**：让源 Agent 实际完成任务并产生历史或从失败中学习，再在目标任务固定直接执行、原始历史、普通总结、任务 skill 和简单规则的比较；其中技能生成、检索、校验、重试与最终执行的全部成本分别记录。设置未变化、相关变化和不适用/误导经验的对照，不仅关注最终正确数，也看关键工具动作、错误执行和不必要拒绝。先诊断信息差、接口错误与执行预算，再决定是否迭代方法。
- **方法与确认，11 月下旬至 12 月中旬**：结合公开近邻 [Skill-V、SkillShift、SkillEvolBench、RSE-Bench](IJCNN_RELATED_WORK_REFRESH_20261030.md)辨别具体差异，条件允许时复现或清楚标注等价近似；在未用于设计或调参的新来源族、版本及随机种子上冻结方法后验证。候选方法可包含自动选择或修订的神经模块，但要有足量可信反馈和训练/确认隔离；用同预算规则、普通 SFT 或零训练方案对照。按真实来源族作统计单位，报告不确定性与总成本。
- **2026 年 12 月下旬至 2027 年 1 月下旬**：如果方法和多源结果足以支撑论点，形成问题、近邻、方法、实验与局限完整稿，按 IJCNN 模板做独立首次读者和数值检查；若不支持投稿主张，继续寻找更合适的来源、机制或后续窗口，不把单次成功写成泛化结论。
