# 用来源可见证据修订一份经验：开发性对照

2026-11-01。基于[事前写入的试验计划](archive/plans/SKILL_VERIFICATION_PILOT_PLAN_20261101.md)，先在源任务中用新建的预填充缓存副本测试旧经验中的离线扫描建议，再人工做局部修订，在此前两个已暴露项目上各执行一次。结果和原条件逐次对照见[复算数据](skill_repair_summary_20261101.json)，可由[汇总脚本](summarize_skill_repair_20261101.py)从冻结轨迹及快照重建。

## 来源验证

首次独立尝试因容器丢弃 DAC 权限、宿主机新复制的 DB 对容器不可写而失败；[失败记录](trivy_fresh_cache_initial_failure_20261101.json)保留，未把它作为模型或方法结果。修复隔离副本权限后，在全新预填充缓存上使用 `--skip-db-update` 执行源任务扫描，[来源见证](trivy_fresh_cache_probe_20261101.json)为退出码 0，8 条记录的身份、严重程度和 CVSS 与原源扫描一致，元数据内容哈希未变。证据限于这一个 Trivy 版本、DB 和执行环境。

据此人工替换原 skill 中伪造未来日期和“首次不能 skip”的建议，补充旧严重程度范围应服从当前任务；其他步骤和未经验证的 Python 示例保留。[修订清单](skill_repair_manifest_20261101.json)绑定原 skill、来源见证和修订 skill 的 SHA-256。它是人工规则修订，不是 Agent 自主学习或已成立的通用算法。

两个修订 skill 轨迹都使用了带 `--skip-db-update` 的扫描命令。React 轨迹没有严重程度过滤，包含一个 MEDIUM 且所选 CVSS 为 9.8 的目标；Node 轨迹仍调用 `--severity HIGH,CRITICAL`。Node 的目标结果恰好为空，故其正确空 CSV 无法检测这条潜在的不适用过滤，不能据此认为范围选择已修好。已保留的副本中未发现时间改写也不排除先改后删；并未独立验证 URL、标题、修复版本、现实漏洞或 DB 文件的全部行为。

这个后验、单次对照表明，在两个已看过的项目上，人工纠正一条有见证的错误建议后，保持了快照相对输出，并未在留存副本中观察到之前的日期改写；同时另一个旧范围建议仍被沿用。普通历史在 React 上也完成了任务，确定性扫描报告筛选基线在两个项目均通过，且先前扫描成本未计入基线。因此结果不能证明统计优势、泛化、自动经验更新，或优于同信息同预算的简单基线。

本批两次 Agent **33 POST、0 次本地拒绝、349,726 reported step tokens**，其中缓存读取 **326,510**；源验证和人工生成 skill 为 0 模型请求。依赖任务相关序列累计 **407 POST、11 次拒绝、5,424,041 reported tokens**，其中缓存读取 **4,835,471**。上述累计包含旧实验和修订两次；缓存读取不等于同量新 token。无训练、付费 API 或生产 Memory 写回。

后续不应继续只修这一个 Trivy 例子。应在独立工作流中检验可见反馈是否能够定位经验的多个相互独立前提，并与普通历史、工具文档、透明规则和预算匹配的多次重试比较；若可得到可执行且来源隔离的监督，再探索学习型技能选择或更新。当前可将“单条经验局部修复不保证其他前提有效”保留为具体机制观察。
