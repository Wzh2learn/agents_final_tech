# 真实 Agent：从反馈生成经验并适配变化任务

2026-10-31，开发实验卡；正式模型运行前冻结。基于已看过的 [公开任务及原测试资格检查](DEPENDENCY_SCOPE_SHIFT_QUALIFICATION_20261031.md)，不是独立确认或官方 harness。

## 问题

同一真实依赖文件，源任务要求 `HIGH/CRITICAL`，新任务要求所有严重程度中 `CVSS > 8.0`。Agent 能否将源任务实际执行和评测反馈形成可复用的持久 skill，在新任务上正确使用或修订经验？这只是具体、可观察的开发例子；因为当前新任务明确写出新条件，“直接按当前要求筛选”是强简单基线，不假定复杂记忆具有优势。

## 来源与隔离

- SkillLearnBench 固定提交 `726e1f79b96b0cb3d729d0e55a1c847e0b5353ae`；任务、验证器与公开原生 skill 在执行前生成 hash 清单。任务 1 和 3 的 `package-lock.json` 相同（`a2a42a32…`），因此不是不同来源。
- Trivy 固定官方 ARM64 镜像内容摘要 `sha256:f3359e94924f81eeb95ce1297c9432889cc21a62759eaa16256ce2abc49dce31`、版本 0.65.0。漏洞库为公开 [Hugging Face 数据集](https://huggingface.co/datasets/zodi1121/skillbench-software-db/blob/main/db.zip)提交 `d005409588e3f74449ab3f13cde29cfea87a80bc`，下载文件 SHA-256 `e67dd9144e93897c5e2dbe4228e3444e4818130923e39389f32164a01bb62d0f` 与官方页面一致；展开 DB SHA-256 `30478db8b8393e41e549ea5df7dff96e99e3c6de199b71f1a920527a23306e21`。数据库元数据更新时间为 2026-01-21，**不是当前安全漏洞清单**；许可待核实，不将原库分发或训练。
- Agent 在无网络容器中使用固定的公开输入、独立复制的数据库和 Trivy 二进制；只有经限制的本地 Qwen 模型代理。原任务 verifier 及预先保存的扫描报告在 Agent 容器内不可见，任务执行结束后单独验证。各次数据库副本独立，不写入原始快照。
- 源和目标任务原说明不变，增加相同的离线工具位置提示。学习任务只给源任务说明、实际源轨迹摘要、源输出及真实反馈，不给新任务说明或目标答案；目标任务没有源检查器或发布参考。

## 运行顺序及条件

1. **source**：独立工具 Agent 完成源任务；记录原测试和后续逐漏洞身份检查。保留失败或缺失输出。
2. **learn**：另一段实际 Agent 从源任务真实历史与反馈写 `/root/experience.md`，明确经验适用范围；将生成文件和 hash 冻结。若未生成合格文件，skill 条件标记为不可评价，不人造成功。
3. **target_none**：只给新任务与相同工具，没有历史或 skill。
4. **target_history**：新任务加与学习阶段相同的源历史和反馈摘要。
5. **target_generated_skill**：新任务加生成的持久 skill；不把源历史或目标 gold 放在此组。
6. **target_native_skills**：新任务加 SkillsBench 公开原生的三份 Trivy/CSV/CVSS skills，作为信息量较高的公开能力参照，不视为信息等量方法比较。

另外，固定扫描器实际报告，使用同一可见任务条件的无模型代码筛选并构造 CSV；扫描报告来自真实工具运行，不读取隐藏 verifier 的参考。源和目标 baseline 均须在原测试及逐条身份/阈值检查下报告。此基线已经在无网环境生成并通过对应原测试，细节和 raw 需在结果回执中记录。

每组先运行一次，按实际顺序记录模型、代理上限、raw、失败、输出、墙时和 token；不同历史长度与随机性未匹配，不能据此给出因果或泛化结论。学习组即使来源失败，也可以从**真实失败反馈**总结，不得伪造成功。代理每 episode 最多 16 次 HTTP、900,000 字节累计 POST、每步最多 8,192 输出 token、600 秒墙时；6 个 episode 至多 96 次 HTTP，遇到接口错误或未交付按实际记账。

## 结果判读

原验证器存在同一包/版本多个漏洞被覆盖的问题。另以固定 Trivy 全量扫描报告为来源，用 `(package, version, vulnerability ID, severity)` 的多重集合比较目标输出，检测漏项、额外项、重复项及 `CVSS > 8` 数值边界。该检查是**相对于同一固定漏洞库的记录与筛选检查**，不独立认证现实漏洞，不验证全部描述字段，也不自动解决不同评分来源冲突。原测试结果、逐条检查、进程退出与输出合同分开报告。

重点观察：源经验是否被实际写出；新任务有无沿用旧 `HIGH/CRITICAL` 范围，是否处理低严重程度但高分记录；每组正确身份、无输出与工具故障；生成 skill 的成本是否改变后续总成本。即便 skill 成功，也必须和无历史、可见规则、普通历史及公开 skill 比较；单例差异不当方法结论。后续确认必须换来源或任务族，避免把同一锁文件的多个变体当多个独立样本。
