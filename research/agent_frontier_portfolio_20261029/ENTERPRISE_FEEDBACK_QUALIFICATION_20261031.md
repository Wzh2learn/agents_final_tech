## 实际结果

六份题目文件都提出 q1、q2、q3；对应的原测试 `EXPECTED_ANSWERS` 只包含 q1、q3。每个变体以公开参考填充其他答案，再逐项构造以下控制，直接运行该变体的原 `test_outputs.py`：

| 每个变体一份输出 | 原测试全部通过的变体 | 可据此判断 |
| --- | ---: | --- |
| q1/q3 按参考填写，q2 给空列表 | 6/6 | 运行和输入检查的阳性控制；不宣称 q2 为空是正确答案 |
| 直接省略题目要求的 q2 | 6/6 | 当前测试不要求所有题目都有结果 |
| 给 q1/q3 追加明显不是员工 ID 或 URL 的占位符 | 6/6 | 它只检查参考项是否被覆盖，不惩罚这个额外字符串 |
| q1/q3 的 `tokens` 均为 -123 | 6/6 | 它接受可转数值，不检查题目要求的正数，也没有核对实际调用消耗 |
| 删除一个 q1 或 q3 发布参考项 | 0/6 | 原测试确实检查了被删除的必需项，失败不是测试没有运行 |

这是故意用参考答案制作的诊断夹具，不能用于估计真实 Agent 的作弊频率、真实任务准确率或自然反馈污染发生率。我们没有判断未标注的普通额外答案都一定错误：控制中的字符串刻意违反了题目要求的 ID/URL 形式。各变体有共享底层资产，不能当作六次独立外部验证。

## 对 IJCNN 研究的作用

这项发现使连续学习实验更可操作：可将原检查器反馈视为 Agent **实际可见但不完整的反馈来源**；研究者另行使用不向 Agent 公开的题目覆盖、非法答案检测和真实 usage 账本，区分任务完成与反馈通过。对于需要判断全部正确实体的 q2，尚缺独立可靠参考，不能用空答案当 gold，也不能让发布答案进入学习提示。研究重点仍是 Agent 如何从真实执行与反馈中形成、选择和更新技能，以及新任务上的行动与保留情况，而不是把一次评分器缺陷包装成学习方法。

可复用同源任务的 6 个变体做开发；跨来源或未见工作流确认必须另找来源并控制数据重叠。后续若使用此任务，应同时对照无经验、普通轨迹、原生 skill、可见的简单合同检查、同预算重试及候选经验更新，并计入经验产生与检查成本。该发现本身不支持特定方法优于基线。
