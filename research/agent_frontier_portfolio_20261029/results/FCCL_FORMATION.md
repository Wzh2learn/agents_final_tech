## 目前学到的对象及方法边界

[守卫归纳部件](../guarded_repair_learning.py)在有限布尔特征上，从实际执行的候选结果寻找能覆盖已解决检查的分支；共同失败不造偏好，找不到一致程序则退出。编译只产生候选，还须隔离执行验证。

它目前学习的是**应用代码的分支条件**。它没有学习 Agent 应在什么反馈下选择哪段工具动作，也未自动提取、绑定新任务中的候选与锚点。[条件片段选择器](../corrective_skill_policy.py)仍没有真实的完整片段配对数据。两者均不能直接作为 FCCL 有效性结果。

历史修复模式与上下文选择已有 [Getafix](https://arxiv.org/abs/1902.06111)；验证器反例与修复迭代已有 [CEGIS agents](https://arxiv.org/abs/2606.11521)；锚点与反例增补约束已有 [CESS](https://arxiv.org/abs/2607.15854)。这些控制是复用部件，不以组合命名主张新颖性。

下一步须让来源经验实际影响 Agent 的纠正动作：观察部分修复与公开回归冲突，读取原版/当前版本，绑定可观察条件，执行纠正并根据复测结果退出或回到普通修复。比较对象共享来源信息、工具和预算；固定规则同效时，不成立学习选择收益。

### 11-12：完整纠正操作的重放与互补性

按运行前计划，对同一冻结源码执行两个真实生产修复操作的全部子集，排除自测修改。实际隔离Bash执行后，评分器重建相同冻结测试：

| 完整操作集合 | 原题通过 | 回归通过 |
|---|---:|---:|
| 不修复 | 0/3 | 132/132 |
| 仅数据/单位修复 | 0/3 | 132/132 |
| 仅掩码修复 | 2/3 | 132/132 |
| 两者都执行 | 3/3 | 132/132 |

在此候选集合中，以整个原生合同通过为V，数据修复的增量为V(data)−V(空)=0，但V(data+mask)−V(mask)=1。这是一个来源内的纠正互补性实例：单独执行不提高最终通过数，不能据此把该操作标成无用。它支持以完整纠正片段及后续执行作监督；不证明跨任务条件策略已经有效，也不把4次干预计成4个独立任务。

全量幂等回放同样达到最终修复，并在再次执行时跳过已应用操作、保持源码逐字节不变。因此本来源不训练复杂选择器；完整片段保留为静态技能及强基线。当前0偏好策略更新。首次翻译执行因容器root在移除权限后不能写uid1001文件而无效；所有臂统一绑定宿主uid/gid后重跑，原无效记录保留，不作方法负例。现有原生扩展ABI警告照录。

另从SymPy真实接续提取并重放第32行Bash：一次全局替换实际命中`row_join`和`col_insert`两处，输出与原候选`common.py`逐字节一致；先前MatMul修改保持不变。两处修改属于同一次工具动作，不能拆成两条独立经验。早期请求了不存在的测试节点，工具completed不代表测试通过；后续公开检查与独立原生2/2＋98/98分开记录，原episode仍为请求帽退出。
