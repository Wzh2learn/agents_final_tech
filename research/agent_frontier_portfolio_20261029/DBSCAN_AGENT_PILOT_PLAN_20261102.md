# 聚类任务中的经验适配：开发性 Agent 探针

2026-11-02，启动模型前冻结。研究问题是：真实工具 Agent 完成一种聚类合同后，能否在相关但不同的合同中正确复用经验，同时识别必须改变的部分？本计划先取得源任务轨迹与无历史目标基线；是否及如何形成经验，依实际源轨迹和反馈另行固定，不预设结果。

## 任务与对照

复用 [DBSCAN 工作流资格](DBSCAN_METRIC_SHIFT_QUALIFICATION_20261101.md)中的 SkillLearnBench 固定提交 `726e1f79b96b0cb3d729d0e55a1c847e0b5353ae`：源任务使用加权欧氏距离，目标任务使用加权切比雪夫距离，两者均要求对相同公开数据搜索 847 组参数并输出 Pareto 前沿；聚类后的专家匹配都仍使用标准欧氏距离。两个任务使用相同数据和测试源码，是**同一来源族的受控合同变化**，不是跨来源确认。

第一批独立运行两条轨迹：`source_no_history` 只给源任务要求与数据；`target_no_history` 只给目标任务要求与数据。二者使用同一 Agent、模型服务、工具、文件权限和预算，各一次。Agent 只看到本次任务说明、只读输入数据和可用计算依赖；公开参考实现、预期前沿和测试在运行时不挂载。结束后才在无网容器中运行对应原测试。若无输出、超时或接口故障，单独记录，不将其编码成某个方法的零准确率。

若源任务形成实际代码或明确失败轨迹，后续可从真实源历史与可见反馈形成历史或技能条件，比较同一目标任务；须冻结材料哈希并计算经验生成及目标的总成本。模型预训练接触这些公开任务的情况未知；此前研究者已阅读过任务及测试，故全部为开发阶段，不称为盲测、预注册确认或官方 benchmark 得分。透明按当前说明直接计算、无历史和普通源历史均是重要基线。

## 执行与计量合同

- 复用固定 SHA-256 为 `4111a0be97845740769722e2e596871d51c7693d14d2372d7f6931b4d06e7afb` 的 OpenCode 隔离执行器，通过[适配器](run_dbscan_agent_pilot_20261102.py)校验源、任务说明、数据、测试、参考和容器镜像哈希后运行。适配器不修改历史执行器；记录派生脚本 hash。
- 源 CSV 还包含志愿者标识等与任务无关的字段。先使用 [投影脚本](prepare_dbscan_projection_20261102.py)生成只包含 `file_rad`、`x`、`y`、`frame_file` 的独立副本；最后一列用于保留公开参考程序的诊断输出。逐行核对投影并用两种参考程序复核完整结果一致后，Agent 才能接触该投影；原始 CSV 不挂载到 Agent。
- 每条轨迹各自使用新工作目录、Docker `--network none`、只读投影及依赖，资源上限 2 CPU、3 GB、1,200 秒。通过限流本地代理访问既有研究模型服务；不挂载凭据、宿主 home 或 Docker socket，不访问生产应用或生产 Memory。
- 每条轨迹最多转发 24 个 HTTP 请求、累计 1,500,000 字节 POST 请求体，模型输出配置上限 8,192 token/步骤；记录实际 POST、拒绝、step usage、缓存、墙时、原始事件、输出和失败。两条第一批理论请求上限为 48，训练、付费 API 与生产写回均为 0。
- 现有 Python 3.12/scikit-learn 1.9 等环境与上游 Python 3.9 环境不同，结果仅针对当前适配；源数据许可仍需核查，原始文件及其投影只作本机/GB10 内部研究，不纳入仓库或对外提供。

检查输入时曾用 `head` 读取少量原始样本行，因此相关标识字段进入过这次会话的工具输出；没有将这些行发送给另一个研究 Agent 或公开。后续不再打印原始记录，只保留列数、哈希及逐行等价统计。

投影已在 GB10 生成：两份输入分别为 25,856 与 1,940 行，各从 54 列投影为 4 列，逐行顺序及选定字段值一致。投影 SHA-256 分别为 `c7d14431e5b002691086708c7485e6b9097d4584adcc573bbe5fc1de166a7453` 和 `71fd0da3fd70d2c09cb1b803d1916763f43d1f0adee5a9d889f43746dbc81407`；投影文件与收据只保存在 GB10 `research_evidence/agent_learning_20261030/dbscan_metric_qualification_20261101/projection_20261102/`。两种参考程序均在投影上完成 847 组搜索：输出分别与各自发布参考逐字节一致，原测试各为 `8 passed`；这些复算使用当前适配环境，不代表原始软件环境已复现，且未调用模型。

## 评价边界

原测试结果和文件是否交付分别记录。已有白盒对照表明原测试可接受额外矛盾行，因此后续另外检查参数键是否重复、同一参数是否对应冲突结果、参考点的相对覆盖与额外行；这些相对公开参考的比较不是独立人工 ground truth。对未能判定的额外结果标 `UNRESOLVED`，不能自动说全部错误。

[事后输出审计器](audit_dbscan_agent_output_20261102.py)在查看 Agent 成绩之前固定：按发布参考的目标值容差核对参数键与对应结果，分别记录缺失、冲突、非法网格、额外或重复参数；仅有未核验的额外或重复行时报告 `UNRESOLVED`。脚本通过合成正反例及两份发布参考自身的检查；它不能独立证明参考之外的参数是否真正位于 Pareto 前沿。

源 Agent 的实际程序已经形成并通过源任务参考检查。目标无历史 Agent 仍在运行、其成绩尚未查看时，增加[透明迁移对照](run_dbscan_metric_control_20261102.py)：保持源程序的坐标缩放、计算和匹配步骤，仅根据目标说明把 DBSCAN 的距离从欧氏改为切比雪夫，再运行目标检查。该对照有人工识别合同变化的帮助，是单个案例的强规则基线，不是 Agent 自学习或与 Agent 等人力成本的比较；须如实记录其无模型调用与完整计算时间。

目标无历史结果可见后，增加一次[普通源历史条件](run_dbscan_history_pilot_20261102.py)：目标 Agent 得到源任务说明和源 Agent 生成的完整程序，自行判断如何遵守当前合同；不提供源/目标隐藏测试、参考输出或人工修改后的程序。模型、数据、容器和单次预算不变。该条件比无历史获得更多信息，且是事后选定的单次开发探针；主要观察最终结果、是否保留旧距离和请求/时间成本，不能作为记忆方法或因果优势的确认。

只有真实源历史存在、目标任务有可评价输出、并且能与直接按当前说明执行的简单基线比较时，才开展经验条件。若两条均无交付，先区分接口/预算/运行环境与任务求解能力；本批结果不证明一般性的技能适配成功或失败。
