# 依赖条件变化：单次观察后的重复计划

2026-10-31。原实验卡 [DEPENDENCY_SCOPE_AGENT_PILOT_PLAN_20261031](DEPENDENCY_SCOPE_AGENT_PILOT_PLAN_20261031.md) 的首轮已完成：源 Agent 未交付；从真实失败轨迹与反馈生成的经验被一个目标 Agent 使用，该 Agent 交付的 3 条漏洞身份及阈值与固定扫描器相符。无经验、历史摘要和原生 skill 各自单次未交付，分别受到请求次数或请求体积上限阻断。生成经验组还将实际使用的一份数据库元数据副本中的时间改为 2099 年；原始快照未更改。

这些观察只是一个**同源、单次、看过结果的开发面板**。为判断现象是否完全依赖单次轨迹，再对 `target_none`、`target_history`、`target_generated_skill`、`target_native_skills` 各重复一次，复用原模型、任务、工具、源历史与同一份已生成 skill，不重新生成经验或改变 prompt、16 次 HTTP 上限、900,000 字节请求体上限及 600 秒墙时。调用由同一代码执行，结果按独立进程记录；未显式设定随机种子，称为重复而不是“第二 seed”。

重复计划是在看到第一轮结果之后提出的，不能称作预注册确认。分别保留两次的交付、原 verifier、逐漏洞身份/阈值检查、有效输出和原数据库时间完整性；保留截断、字节或请求上限、输出缺失、实际 token 与生成 skill 的一次性成本。每组只增加一次仍不能估计稳健概率，也不代表技能对新来源有效。

若两轮仍受额度截断，后续可另行冻结同一较高额度的所有组做接口敏感性检查，不能只扩成功组；若 skill 显示潜在收益，优先研究如何让经验保留可执行成功同时禁止无依据篡改元数据，并找来源隔离的工作流做验证。简单规则与公开工具依旧是强基线。
