# Prefix-cache repair: second task development experiment

Written before the new episodes. This is a task-distinct development experiment within the same SkillsBench benchmark, not an independent benchmark or a preregistered confirmation. Goal: compare whether a real tool-using Agent can use a small task-contract diagnostic while preserving the rest of a complex output. Contrast with the dialogue task, whose verification contract was faulty; inspect this verifier and preserve its limits separately.

Frozen initial output: prior no-skill `llm-prefix-cache-replay__no_skill__258386`, which produced `solve.py` and `report.json`, with the same public `trace.jsonl` and `config.json` as the task. Prior agent exited after a timeout; its result had 1 passed / 9 failed. Source code used `input_length // block_size` as prompt tokens, although the public task describes input length in tokens, and emitted a list for `final_cache_blocks` although the public task requests a count. These diagnostics are supported by visible task/data/code, not hidden oracle values.

Two independently restarted no-skill agents begin from byte-identical initial `solve.py` and `report.json` and public input. Neutral feedback says the candidate failed checks. Diagnostic feedback additionally says to check the prompt-token unit and final-resident-block count against the visible task specification. Both can read, write, and run local files. No verifier or test oracle is mounted until a separate evaluation after the run. Shared caps: 16 accepted model requests (including any GET), 900,000 cumulative POST bytes, 8192 output tokens per step, 600-second agent wall timeout and 300-second local service timeout. Copied files have mode 0666 in the isolated work directory, verified by the previous study; the original is not modified.

Report all original verifier cases, task-specific aggregate self-consistency, file hashes, agent exits, actual HTTP and usage events, wall time, and semantic issues. A task-level outcome is one paired initial artifact, not 10 independent benchmark samples. Additional ordinary deterministic repair of just the visible unit/count contracts is a useful lower-cost comparator, not an oracle; remaining S3FIFO logic and side effects must be checked independently. Whether the correct update rule is observable from the public spec and skill instructions should be documented, rather than hiding reliance on inaccessible verifier behavior.

After the two agents finish, compare raw outputs and feedback-use traces. Do not expose hidden tests or reference answers to either agent. If either approach only fixes field contracts while leaving policy behavior wrong, report the partial repair and consider a bounded check-based, rollback-aware candidate against the same-source neutral baseline; do not treat it as a verified paper method.

Prior project work found an all-skill agent could pass this task when started from scratch, so add a third, post-hoc reference arm `task_skill`: start from the identical saved files, offer the two original task skills as the base runner does, and supply only the same neutral failure notice. Keep resource caps and all other contracts fixed. This is an unequal-information comparison, not a test of a new skill-learning method; it strengthens the baseline against which the two repair conditions are interpreted.
