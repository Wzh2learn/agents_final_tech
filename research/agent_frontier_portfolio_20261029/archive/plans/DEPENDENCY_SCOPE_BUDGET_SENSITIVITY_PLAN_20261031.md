# 依赖条件变化：统一扩大调用预算的事后敏感性实验

2026-10-31。前两轮均在同一任务族、同一份源历史和生成 skill 上执行。生成 skill 组两次均输出目标三条漏洞身份；原 verifier 分别为 8/8、7/8，第二次是输出的 Red Hat 参考链接不等于基准预置链接，链接内容仍待核查。无历史、历史及原生 skill 三组各两次均在请求数或请求体上限前未交付。两次生成 skill 组都改写了工作副本的 DB 元数据日期，原始快照没有改动。

由于此观察可能由额度和上下文长度驱动，增加一项**看过结果后设计的开发性预算敏感性检查**。四个目标组各重新运行一次，保持同一任务、Qwen、工具、数据、源历史、生成 skill 和 prompt；统一将每次允许的转发 HTTP 上限从 16 扩至 **32**、累计 POST 请求体从 900,000 扩至 **2,400,000 字节**、进程墙时从 600 秒扩至 **900 秒**。每步输出上限 8,192 不变；不称为不同随机种子、独立数据、预注册确认或与第一轮同额度的重复。

按无历史、历史、生成 skill、公开原生 skill 的顺序分别运行，保留 Agent 原始轨迹、输出、原测试、逐漏洞身份/阈值、CVSS 来源、元数据变化和完整调用账本。源经验/skill 仍为原来的真实失败轨迹所产生，不重新训练或从目标答案生成。额外的更新前测试、验证与前序学习成本一并报告。

若扩大额度后简单无历史或历史组也完成，说明先前的结论需要同时考虑预算；如果只有生成 skill 仍能完成，也只能说该单来源的观察对这一组额度有持续性。任何情况下，以原始历史、公开 skill 和真实扫描工具加确定性筛选为基线，不能据此直接宣称 IJCNN 创新方法成立。元数据篡改、原 verifier 对同包多漏洞及参考链接的限制均另计。
