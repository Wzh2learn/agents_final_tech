# 跨任务经验迁移与元件匹配尸检

2026-10-30；**开发探索，不是跨 benchmark 确认，也不是已成立的 IJCNN 方法**。实验卡和各组输入哈希见 [预先冻结的运行计划](archive/plans/CROSS_TASK_TRANSFER_PILOT_PLAN_20261030.md)、[Agent 汇总](codebook_transfer_summary_20261030.json)；后续回放的四个控制及哈希见[控制计划](archive/plans/CODEBOOK_COMPONENT_CONTROL_PLAN_20261030.md)、[控制汇总](codebook_component_controls_summary_20261030.json)。目标是检验来自发票任务的标识符匹配经验在另一种工具任务上如何被使用，而不是根据一个成功轨迹宣称可泛化学习。

## 三次真实工具 Agent 运行

同一公开 SkillsBench v1.1 制造缺陷分类任务，输入为 12,000 条日志与三个 codebook；分别由无经验、发票任务迁移经验、任务原生 skill 三组执行。Qwen/OpenCode 使用相同容器和预算；skill 与经验改变可见信息，因此不是等信息比较。原 verifier 只在 Agent 停止后在另一个容器运行。结果：

| 条件 | 交付和原检查 | 可见记录覆盖 | 已转发模型 POST | 记载的 step tokens（含缓存） |
|---|---|---:|---:|---:|
| 无经验 | 有输出，13 项通过、3 项失败 | 12,000/12,000 | 16 | 243,889 |
| 迁移经验 | 有输出，12 项通过、4 项失败 | 12,000/12,000 | 16 | 250,322 |
| 原任务 skill | 无最终输出；16 项检查因缺输出而失败 | 无可评价输出 | 15 | 204,072 |

三次 Agent 进程均返回非零，各有一次后续请求被本地 proxy 拒绝。前两组到 16 次已转发请求上限；skill 组 15 次后被拒，已转发请求体总和为 811,405 字节，但现有记录不足以单独确认最后一次拒绝的具体触发条件。拒绝请求没有转发至模型。**47 次模型 POST、3 次本地拒绝、698,283 已报告 step tokens**；这些 token 含缓存读取且不代表 698,283 个独立新 token。没有训练、付费 API、人工 judge 或生产 Memory 写回。三组各一次，随机性、任务顺序和预算均可能影响比较。

原检查包括合法格式、覆盖、词项重叠、工站约束及置信度分布，没有逐记录人工语义 gold。无经验组失败项是语义重叠代理、工站范围和解释依据；迁移组失败项是置信度分布、语义重叠代理、解释依据及置信度与证据相关性。原 skill 组没有报告，不能把 16 个缺文件测试当成 16 条独立分类错误，也不能据此判定该 skill 本身无效。

## 经验是否在此任务起作用？

公开输入中，原始整条理由与 codebook 完整标签精确相同、或包含完整标签的记录均为 **0/12,000**；这是表述层面的统计，**不排除**理由中存在可精确匹配的元件或信号标识。两组输出的分段方式明显不同：17,179 个 `record_id + segment_id` 相同，但其中只有 **283** 个具有完全相同的 `span_text`，这 283 个里有 244 个选码不同。段号并不是自然相同的语义单元，不把前一数字当作配对准确率，也没有证据证明 244 个变化有利或有害。

无经验程序将输入转为小写后用仅匹配大写字母的正则提取编号，keyword 也有同类大小写门，因此该分支没有按预期利用编号。迁移经验组生成的程序包含组件集合等值匹配，但同时改变了分段、分类、置信度等逻辑；由于各组只有一次运行，不能把组间差异归因于经验。可见正则抽取在 1,871 条记录得到含字母和数字的片段；其中 313 条有与 codebook keyword 等值的正则片段、234 条存在部分包含候选。**这些是可见文本的正则候选，可能截断信号，不是 313 个正确匹配或 234 个实际误分类；两组计数也可重叠。**

## 同程序、无模型事后控制

首次控制运行因临时输出目录权限不足而写入失败，三个失败日志保留；修复权限后在新目录独立重跑。原程序复跑输出 SHA-256 与 Agent 留下的报告完全相同。

| 同一程序的变化 | 原检查 | 相同 record、segment 和 span 上的代码变化 |
|---|---|---:|
| 原始复跑 | 13/16 | 基线 |
| 修复大小写，保留双向子串 | 13/16 | 相对原始改变 25/36,066 |
| 修复大小写，改为完整编号等值 | 13/16 | 相对原始改变 0/36,066；相对子串组改变 25 |
| 再将信号 token 保留字母、数字和下划线，按完整 token 等值 | 13/16 | 相对上一组改变 6/36,066 |

四组最终输出 hash 不同，即使最终选码一致，其他字段也可能改变。25 个变化来自重复的少数文本：例如原正则把 `I2C_SCL` 截成 `I2`，子串规则可将该片段与不同的 `I2C_SDA` 关联。追加 token 修正引起的 6 个变化实际上是同一条重复文本；该文本含 `I2C_SCL open`，新选标签含 `Short circuit ... I2C_SCL`，信号名对齐并不能单独证明故障类别正确。这是从输出和 codebook 可观察到的文本冲突，未作独立专家裁决。

四组都维持相同 13 项通过和 3 项失败；这些检查不足以认定变化是否提升语义质量。这个对照说明 **经验中的“完整匹配”必须与目标任务的标识符切分和类别语义一起核验**；它并未证明一种新的 Agent 学习算法，也不能否定其他形式的跨任务经验。

## 下一步与可复用资产

在更多具备可执行且可信参考的不同来源、不同任务族中，同时设计适用与不适用旧经验的样本。固定同一可见信息、模型与预算，比较原始任务 skill、普通历史、直接重试、完整标识符规则、固定 verifier/rollback 和候选经验选择；按工作流/来源拆分而不是把重复文本当作独立样本。除最终正确率，还要分别评估标识符解析、类别语义、拒绝、风险及累计推理和验证成本。自然样本不足或分类含糊时使用独立人工/专家裁决并保留 `UNRESOLVED`；公开代码分析提供候选信号，不自动成为 gold。
