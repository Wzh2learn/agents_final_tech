# 真实 Agent 从失败反馈生成经验：首次运行

2026-10-31。按事前提交的 [实验卡](archive/plans/DEPENDENCY_SCOPE_AGENT_PILOT_PLAN_20261031.md)在 GB10 运行 OpenCode + 本地 Qwen；[逐组哈希、评测和成本](dependency_scope_agent_pilot_summary_20261031.json)可由 [复算器](summarize_dependency_scope_pilot_20261031.py)从原始回执和扫描报告重建。接续：[看过首轮后冻结的重复计划](archive/plans/DEPENDENCY_SCOPE_REPEAT_PLAN_20261031.md)。这是一个已暴露来源上的开发性观察，不是独立确认。

## 真实连续流程

源任务要求只报告 HIGH/CRITICAL。源 Agent 进行了扫描器尝试，但最后只留下空扫描文件、没有交付 CSV，在 16 次转发请求后触及上限；原 verifier 和逐条检查均无法给出合格输出。我们把**真实源任务、截取的工具轨迹、无输出和原测试/源记录反馈**交给另一次 Agent；该 Agent 写出了实际存在、4,000 字符以内的 `experience.md`。没有向生成者提供目标任务或目标答案。

新任务要求跨严重程度筛选 `CVSS > 8.0`。四个目标条件分别独立启动，且任务、工具、原始 DB、模型和调用上限相同：

| 条件 | Agent 进程 | 原测试 | 逐漏洞身份及阈值 | 转发 POST | 阻断 |
| --- | --- | --- | --- | ---: | --- |
| 无历史 | 非零 | 失败 | 无 CSV | 16 | 请求数上限 |
| 源历史与反馈摘要 | 非零 | 失败 | 无 CSV | 16 | 请求数上限 |
| Agent 生成的 experience | 正常 | 通过 | **3/3 身份与阈值符合** | 14 | 无 |
| 公开原生三份 skills | 非零 | 失败 | 无 CSV | 14 | 累计请求体上限 |

源 episode 消耗 16 POST，经验生成消耗 9 POST，四个目标 episode 消耗 60 POST；合计 **85 次转发 POST、4 次本地拒绝**。返回的 step 账本共 **1,099,502 tokens**，其中缓存读取 968,688；这不是等量未缓存 token。没有训练、付费 API、人工 judge 或生产 Memory 写回。因每组仅一次、skill 与历史的信息和长度不同、三组受到上限阻断，这不是技能方法的因果优势或胜率估计。

## 正向现象与新的问题

生成经验组实际读取了其生成的 skill、运行本地扫描器并自行解析结果，最终在目标合同下保留三条漏洞，其中包括一条严重程度为 LOW 但分数大于 8 的记录。它没有简单照搬源任务的 HIGH/CRITICAL 范围。逐条检查按 `(package, version, vulnerability ID, severity)` 多重集合和数值阈值比较，避免原测试按包覆盖多条漏洞的缺陷；但该检查相对于同一固定漏洞库，不独立认证真实漏洞或所有描述字段。

事后另用 [CVSS 源值检查](audit_dependency_cvss_sources_20261031.py)核对，这三行的分数都能在冻结扫描输出的至少一个来源找到；这不能证明 Agent 实际使用了哪个来源。第一条报告 9.8，与公开参考的 8.1 不同，但两者分别存在于该扫描记录的 Red Hat 和 GHSA 分数中；原 verifier 按包及版本覆盖了这一行，不能据通过结果推断它检查过该分数。这里没有把不同来源的数值自动判成错误。

同时，生成的 skill 不只是正确指引。它从失败轨迹过度推断“首次不能使用 `--skip-db-update`”，并建议将 DB 元数据日期写到未来；而研究者的无模型基线在指定正确 cache 目录后，使用原始元数据及 `--skip-db-update` 已经成功。目标 Agent 确实按经验改写了**自己工作目录中新复制的** `metadata.json`，把多个时间写为 2099 年；随后用该副本扫描。源 Agent 与历史组也各自留下过未来日期的元数据副本；原始 GB10 数据库快照与随任务复制的 `trivy-cache` 原件保持不变。修改时间可能让后续使用者误判该副本的新鲜程度，必须同成功结果一起报告。

生成 skill 的 Python 示例还使用了与本次扫描报告不一致的若干字段名。事后从 skill 原文抽出该 Python 代码，不做修改地输入源任务 HIGH/CRITICAL 扫描结果，在无网络隔离容器中实际运行：产出三行，但包名、版本和漏洞 ID 全为空；原测试 **2/7 通过**，逐条检查漏掉 **3/3** 预期身份。构造器为 [prepare_generated_skill_literal_control_20261031.py](prepare_generated_skill_literal_control_20261031.py)，原代码、输入、输出和测试日志均保存在 GB10 `generated_skill_literal_control/`。这个字面代码控制不是另一次 Agent 运行。

成功的目标 Agent 没有直接复制该片段，而是重新观察实际 JSON 并编写了解析代码；故不能把这次成功解释为所生成示例逐字正确。另一方面，使用同一可见扫描器报告并依任务条件筛选的确定性程序，源任务原测试 **7/7**、目标任务 **8/8**，逐条身份与阈值检查均通过；其没有学习成本。因此该数据支持进一步研究“从反馈形成可迁移经验时如何核验经验中的可执行操作与来源”，尚不证明超越强简单基线。
