# 依赖审计：可用于经验适配的任务变化候选

2026-10-31。对 [SkillLearnBench](https://github.com/cxcscmu/SkillLearnBench) 固定提交 `726e1f79b96b0cb3d729d0e55a1c847e0b5353ae` 中的 `dependency-vulnerability-check` 做事后资格检查。它提供一个比“重复同一任务”更有信息量的开发序列：依赖输入不变，用户要求的筛选条件发生变化；把早先有效的范围不加判断地用于新任务会产生不同结果。

## 三个真实任务条件

| 任务 | 可见要求 | 发布参考 CSV 行数 |
| --- | --- | ---: |
| 1 | 仅 `HIGH` / `CRITICAL` | 3 |
| 2 | 所有严重程度 | 8 |
| 3 | 所有严重程度中 CVSS 严格大于 8.0 | 3 |

三者引用的 `package-lock.json` 字节相同，SHA-256 为 `a2a42a3255e814e75bed9958c40cd9b35de7331b310bfeb8f93306d806643d44`；环境说明称输入来自 [npm/cli v8.19.4](https://github.com/npm/cli/blob/v8.19.4/package-lock.json)，本轮未将在线源文件与本地逐字节比对。任务 3 的参考中有一条严重程度为 `LOW`、CVSS 为 9.8 的记录，因此“旧经验总是只保留高危”不能等同“遵循当前分数阈值”。这是发布数据中的两个字段值，不在此判定其权威漏洞严重程度。

## 原测试交叉对照

将每个任务**发布参考**原样写为 CSV，分别运行三个任务的原 pytest 测试，9 次无网络容器执行结果如下；✓ 表示测试进程返回 0：

| 构造输出 → / 原测试 ↓ | 参考 1：HIGH/CRITICAL | 参考 2：全部等级 | 参考 3：CVSS > 8 |
| --- | ---: | ---: | ---: |
| 任务 1 测试 | ✓ | ✗ | ✗ |
| 任务 2 测试 | ✗ | ✓ | ✗ |
| 任务 3 测试 | ✗ | ✗ | ✓ |

这表明**静态复用已给出的旧参考输出**不能满足其他任务的当前检查；它还没有证明 Agent 会产生这一错误、不能证明生成 skill 带来迁移收益，也没有验证参考的漏洞事实。每份输出均直接使用隐藏参考，只能作为评分器控制，不可喂给 Agent 或当作学习轨迹。

## 原测试的逐条覆盖盲区

任务 2/3 的 `test_csv_matches_ground_truth` 将 CSV 转成以 `(Package, Version)` 为键的字典。同一包、同一版本存在多条漏洞时，后面的行覆盖前面的行。按源码这一规则只保留最后一条：

- 任务 2 的发布参考从 **8 行减至 6 行**，原测试仍为 **7/7 通过**。
- 任务 3 的发布参考从 **3 行减至 2 行**，原测试仍为 **8/8 通过**。

因此后续应使用含漏洞标识的逐行多重集合（并对重复项、字段及顺序分别建合同）作补充检查，不能把原测试通过当作漏洞记录全部覆盖。具体适配仍需先核实漏洞源快照、严重程度来源及日期；不同漏洞数据库的字段和结论可能不同。

## 对第二篇的价值和下一步

这是一个**真实任务来源中的适用条件变化**，符合经验学习与技能适配主线：Agent 可以从任务 1 的实际运行和反馈中形成一条可执行经验；任务 2/3 再观察它是否根据当前要求修订筛选、保持或拒用旧 skill。设计时应比较无历史、原始轨迹、从轨迹生成并冻结的 skill、公开原生 skill、同信息预算的工具文档/可见规则，以及候选经验选择或更新；记录真实行为、逐漏洞输出、错误沿用、旧任务能力和总成本。原任务说明明确给出了新筛选条件，强简单基线包括直接读取并执行当前条件，不能仅把 Agent 跟随新指令当成创新。

三个条件共享同一依赖文件，且题目与参考已被本研究者检查，只能作**开发任务**。后续仍需来源族不重叠的新依赖项目或完全不同工作流，以及真实反馈驱动的持久经验生成、冻结和确认；如果简单规则已解决，继续找需要模型理解与学习的环境，不强行包装这个例子。

原环境通过网络安装 Trivy，并下载 Hugging Face 的 [84 MB 漏洞数据库文件](https://huggingface.co/datasets/zodi1121/skillbench-software-db/tree/main)。本机和 GB10 对官方文件地址直接请求超时后，已从镜像下载固定提交文件，并将完整 SHA-256 与官方文件页核对一致；同时按 Docker Hub 官方 ARM64 镜像摘要固定 Trivy 0.65.0。使用 2026-01-21 的数据库快照，在无网络容器中对相同锁文件实际扫描出 8 条记录，按当前任务筛选的无模型程序分别通过源任务 **7/7** 与目标任务 **8/8** 原测试及逐条身份检查。旧快照不能作为当前安全审计结论，数据库许可待核实，原数据仅保存在 GB10。[Agent 开发实验卡](DEPENDENCY_SCOPE_AGENT_PILOT_PLAN_20261031.md)使用真实扫描器和数据库，不把预期 CSV 伪装成 Agent 可用数据库。
