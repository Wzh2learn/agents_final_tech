四、科研大方向：可以选、可以改、可以否定

共同问题是：旧结论、依赖或经验可能变化、信息不完整、观察和重算有成本时，怎样选择核查、复用、失效与修复，最终减少真实任务错误和总成本。

A. 面向行动损失的主动核查

研究 Agent 应先查哪条依赖、哪项变化或哪个测试；关注最终行动与修复损失，不以恢复完整图本身作为唯一目标。允许 partial/noisy dependency、跨步骤预算与必要的 unknown。

最小环境可从 8–12 个可执行节点、2–4 个输出、变化前成功快照和变化后状态开始；提供 inspect_dependency / inspect_change / run_target_test 等公开工具。actor 不得到隐藏 checker 图、Gold 或由它们派生的捷径。

必须比较不查、随机、单位成本贪心、两步前瞻、全量重算。非 oracle 策略只用公开信息或训练期估计，不能从隐藏 checker 取得真实收益。完整图/完整 trace 仅作为分列的 oracle 上界。固定 repairer 回放不同查询策略得到的证据，分开“查什么”与“拿到证据后会不会修”。

可以探索查询互补性，但同时保留近似可加场景和部分成功指标；不能人为设置 all-or-nothing 评分来制造贪心失败。若简单策略足够，接受边界；若收益全来自多查或多推理，归因为资源而非策略。

B. 变化后的局部重验证与依赖获取

研究输入、配置、API 或代码变化后，如何在不完整依赖、缺少可靠 change contract 时重验证旧结果。区分潜在依赖、实际激活路径、数值变化、来源/证据有效性与历史查询。

包含 breaking/benign、未激活分支、多个合法支持、来源改变但数值相消等情形。用独立执行和测试判断局部修复是否真的正确，记录漏失效、过失效、回归和修复成本。

强基线包括不失效、全量重算、TTL、changed-key、BFS、query-lazy/on-access。图由 oracle 提供、trace 观察、静态分析或模型推断时分别报告；若只有 oracle 条件下有效，转向图/证据获取或停止，不把正确图作为免费能力。

C. 从有限历史归纳可检验的经验适用条件

研究何时能从真实成败历史学到“此经验在什么条件下可复用”，而不是给旧例子加摘要。可用 true/false/unknown guard、有成本的条件核查、经验冲突和组合；条件必须可观察、可证伪。

先把单经验条件归纳做清楚，再决定是否需要多记录组合。普通示例、一般经验、条件文本、可执行 guard 来自同一历史和候选信息；文本/guard 尽量共享同一中间表示，避免一个臂知道更多事实。

比较无经验、solved examples、一般经验、条件文本、可执行条件，并加入浅决策树/有界 DSL 枚举、公开规则、等成本重推导。给定正确条件是 oracle；手写 guard、动作改名和给定 rewrite map 不等于经验学习。

历史必须是真实执行 episode，所有结果可追溯，不强制制造预设失败，不靠隐藏参考挑“有效历史”。成功历史也可以提供条件。全拒绝、全 unknown、always-defer 需要完成率和成本约束，不能冒充可靠收益。

资格、canary、历史采集、反思、重推导、judge、重试与失败都计入；多轮 agent 每次模型请求分别计入。区分 physical HTTP、预留 accounting attempt 和 HTTP 前失败，两个口径可核对。不因换 candidate、模型、窗口或 run_id 重置总账；不通过改名重复发出已存在的请求。

允许必要的辅助 LLM judge，但计入新账，不能单独充当语义 Gold 或执行正确性。旧实验 judge/训练/Memory 写回为 0 的历史事实不变。本轮可用离线计算及现有工具，另记工具次数、时长、重算量、缓存、历史/归纳/查询总成本，不能只报告便宜的最终调用。

九、实验必须能区分的东西

每条保留路线用一张简短实验卡说明：问题、最强近邻、竞争解释、actor 可见信息、独立目标、baseline、实际成本、首个淘汰条件。不要为每个小探针制造一套治理文档。

必须区分：
- 新信息与新表示；提供正确图/正确条件与独立获取能力。
- 选择证据与利用证据；多采样/多推理与经验/结构本身。
- 局部值正确、证据/来源有效、所有允许动作集合与真正执行策略。
- 手写机制环境、公开合成更新、自然变化；开发观察与新确认。

用独立执行/测试/可核查规则作为优先参考，必要语义歧义标注不确定，不从隐藏参考反推 actor 输入。保留 actor view，做标签/隐藏 trace 变动不影响输入的检查。输入污染与额外 oracle 信息即使提高结果，也只能单列诊断。

按 family/API/变化谱系/历史来源拆分，防近重复与未来信息；确认时使用未参与开发选择的新 families。采用配对家族差值与适当区间，不把同 family 的大量记录当独立样本。先冻结主指标与实际意义阈值；空集合和弃答指标提前定义，不能事后换分数救候选。

不规定统一提高几个百分点才叫成功。根据任务风险和成本确定事前阈值；若样本/预算不足以区分，就报告区间与未定，而非把不显著当等效。停止当前方法不等于停止整个问题，解释是任务饱和、信息不足、模型限制还是简单基线充分。

十一、完成标准与回报方式

本轮进度看四种改变：
1. 治理是否真的整合了独有材料、保留可恢复证据、统一当前入口和可验证的两端状态。
2. Paper E 是否形成唯一可审阅稿和明确作者级判断。
3. 新研究是否产生真实模型/执行观察，淘汰竞争解释，选出值得确认的机制，或充分说明为什么停止并转向。
4. 成本与结论能否由原始记录、冻结输入、脚本和账本独立核对。

不要把新增文件数、调用次数、预算消耗、通过手写 fixture 或工程闭环本身当科研贡献。也不要因为允许自主探索就取消对照、隐藏负向结果或扩大 claim。
