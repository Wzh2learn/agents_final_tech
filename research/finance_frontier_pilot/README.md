# 强基座零训练诊断

第一批对同一题分别运行自由推理和可执行 DSL。使用 `ODA-Fin-RL-8B` BF16 固定版本 `948c22ea48f9bf93e5747f4211657fcad9cb0295`，两臂均经 OpenCode 1.18.3。固定题干、报告输入与生成设置。27B FP8 在同一 DSL 合同下对首答错题独立作答。旧 Risk/Value 权重只读出分，首答同时作为两个状态，供分布迁移下比较。

- FinQA 官方 test 抽 200 题，114 道单步、86 道多步。与官方 TRAIN 表内容重复的 15 题排除。TAT-QA 官方 dev 抽 200 道算术题，来自 147 个表上下文，排除旧 C3 确认的 64 个表上下文。抽样以固定哈希排序，确认表只核对事先记录的成员标识。
- `M_strict` 两臂同用官方答案计分，DSL 可执行率另报。`M_norm` 是限定倍数下用参考答案复算的诊断。`M_rule` 在 TAT-QA DSL 臂使用已有公开尺度规则，其余沿用原答案。统计逐题救回与错改。自由臂剩余错误包含未能提取最终答案的情况。
- 表示分差包含输出截断、答案提取、显示精度和程序执行的影响。倍率归一的命中量与自由臂的剩余失分分别作为诊断指标，单独核对错误类型与覆盖率。
- 来源复核从可执行程序回映公开坐标。同值歧义未唯一消除时不传入白名单。报告错误检测 AUC、27B 能恢复的错题 AUC，以及两者的覆盖数和共同样本对照。
- GB10 私有目录为 `~/wzh/research_evidence/finance_frontier_pilot_20261119_v1`。`panel/manifest.json` 固定题号，`calls/` 保留原始 OpenCode 回执，`generation_scores.json` 保存配对生成分数，`summary.json` 保存全批分数、AUC 和推理成本。模型按既有显存租约串行切换。费用按本地与校内分别核算。

路线 A 的开发门槛为规则后差距 ≥6 pp 或格式差 ≥8 pp。若差距较小且排序 AUC ≥0.72，进入路线 B 的交接对照。路线 C 还要求严格成绩高、教师恢复有限且排序 AUC <0.62。开放测试的 200 题用于选方向，后续全量比较记录经过探索的题号。

`diagnose.py --root <运行目录> --receipts-only` 可直接核对回执。全批结束后省略该参数，按报告或表上下文计算同题分差区间。它也用同一批操作数回映复算纯规则 AUC，量化 8B 反查的增量，并分别报告全部教师尝试、正常交付及程序可执行时的恢复排序。

## FinQA 首答结果

2026-11-20 已收齐 FinQA 200 题的两臂回执。自由／DSL 的严格分为 49／56，诊断倍率归一后为 53／117。DSL 有 145 个可执行程序，倍率归一救回 61 题，其中 60 题对应除以 100。两臂分别有 18／32 次触及输出上限且没有最终答案。跨表示分歧的检测 AUC 为 0.765，覆盖 116 题。逐题复算见 GB10 `finqa_generation_audit.json`。

- 公开规则的事后同批回放限定为显式问百分比、倒数第二步为除法、且最后一步将该除法结果乘以 100。保留倒数第二步的结果，66 题触发，修回 53 题、错改 2 题，严格分达 107／200。原定评分结果保留，规则离线回执见 `finqa_ratio_rule_posthoc.json`。
- 另一项离线复核对 166 个已提交程序执行固定版本的官方评分器，严格分逐题一致。自由臂解析若接纳重复百分比标记、数量单位后缀等明确写法，可多得 9 个严格匹配。自由臂表现对答案提取与显示精度敏感，后续比较保留单列。
- FinQA 教师的 144 次尝试已全部返回，其中 140 次正常交付，4 次超时。严格救回 15 题，使用同一公开百分比规则后救回 57 题。其中 37 题已被本地规则救回。对本地规则后仍错且已有教师尝试的 91 题，教师原答救 15、规则后救 20。本地规则另引入两道错题，原协议未对其调用教师。GB10 复算见 `finqa_teacher_complete_replay.json`。
- 按原始严格救回来排序，首答未执行的 AUC 为 0.771（144 题、15 个救回），旧 Value 为 0.749（同 144 题）。跨表示分歧 AUC 为 0.566，覆盖 78 题且仅有 2 个救回。错误检测与可恢复性在此批表现不同。TAT-QA 教师回执收齐后统一裁决路线。
- 在独立认证的 153 个 FinQA TRAIN 来源中，79 道题显式询问百分比，67 道的金标程序以除法结尾，4 道金标程序以除法后乘 100 结尾。同一种题干提示允许两种标注方式，适合作为尺度修复的保持对照。统计在 `finqa_training_scale_contract.json`。

## TAT-QA 首答结果

2026-11-20 已收齐 TAT-QA 200 题两臂。自由／DSL 严格分为 118／124，倍率归一及公开尺度规则均未改变分数。DSL 有 137 个可执行程序，其中 13 个未通过答案评分。63 次未执行中，25 次达到输出上限仍无最终答案，余下主要为程序结构与表行定位问题。自由臂有 20 次截断，另有 30 次已回复但未提取出答案。事后仅修复重复百分比标记和明确的币种、单位后缀，自由臂多得 23 个严格匹配。原定结果另报，自由减 DSL 的严格分差为 −3.0 pp，报告簇配对区间为 [−12.2, 6.0] pp。

两数据集 800 次生成累计记录 2,388,421 tokens，生成墙时 4 小时 31 分。TAT-QA 分解与回执核对见 GB10 `tatqa_generation_audit.json`。同批继续记录来源核验、旧 Risk/Value 对照及 27B 独立重解，路线裁决使用完整证据。

### 无需学习的两臂回退

复用 800 份回执，按原解析器和严格评分事后复算。DSL 未执行才采用自由回答，FinQA 得 72/200（255 次调用，902,591 tokens），TAT-QA 得 158/200（263 次，773,969 tokens）。直接 DSL 分别为 56/200（730,779 tokens）和 124/200（600,265 tokens）。反向策略在自由臂无数值时才用 DSL，分别为 67/200（762,763 tokens）及 142/200（651,543 tokens）。该复算逐次计费，实际串行延迟仍需同条件测量。全量对标将这两条简单策略纳入基线。GB10 回执汇总见 `representation_fallback_posthoc.json`。

## 来源核验的错误检测

400 题均生成诊断记录。其中 249 题调用 8B，95 次产生可解析判定，152 次达到 1,024 token 上限且未交付判定，2 次回复无法解析。FinQA／TAT-QA 的规则加 8B 检测 AUC 为 0.659／0.571，覆盖 144／137 题。对相同题目去掉 8B 判词时，确定性规则 AUC 为 0.654／0.610。跨表示分歧的检测 AUC 为 0.765／0.665，覆盖 116／108 题。两信号共同覆盖的样本及类别数量见 GB10 `detection_audit.json`。这些指标对应已有 DSL 输出的错误检测，27B 实际恢复对照正在同批生成。

## 全量对标的样本来源

以官方全集为比较分母，同时保留分组结果。FinQA 的 1,147 题包括 200 道探针题、337 道同报告或同表题、155 道同公司同年题、15 道与官方训练集同表题，余 440 道未检出上述重叠。TAT-QA 的 718 道算术题包括 200 道探针题、186 道同表题、165 道来自旧 C3 确认表的题，余 167 道未检出上述重叠。GB10 `full_eval_exposure.json` 保存题级归属。现有核查范围为本探针及已登记排除项。

## 同预算对标准备

- CAR 按论文适配。每题计入一次五类诊断，使用官方训练集拟合遗漏率并校准恢复与错改。门控后用相近校准题的错误亚型选检查，再按公开证据指针作有界修订。 [CAR 方法与附录](https://arxiv.org/html/2611.05166v1#S4)
- BudgetVerify 按论文适配。保留首答、局部复查、独立解答后再比较三个固定动作。在官方训练集取得三个动作的成败与实付成本，再训练分档路由器。 [BudgetVerify 方法](https://arxiv.org/html/2609.33052v1#S3)
- Cascade Routing 复用作者代码。在官方训练集上以同版 8B、27B 和 DeepSeek 的真实匹配结果拟合质量、费用与协方差。作者路由可选择起始模型和跳过级别，固定从 8B 开始的级联另列。无 token logprobs 的模型端使用已记录的公开执行与回答一致性特征，并标明特征适配。 [Cascade Routing 作者实现](https://github.com/eth-sri/cascade-routing/tree/9da6cf7da39c42148eae0178635e9211e5b67742)

共享相同设置的首答、证据和评分。探针的 27B 独立重解只覆盖首答错题。端到端比较另行记录正确首答上的保持和错改，以及本地生成、核验和教师的实际 tokens 与墙时。

`benchmark_panels.py` 固定官方 TRAIN 中独立来源的拟合与校准面板，各数据集预备 96/48 个来源。FinQA 从以往证实与封存组分离的 153 个 TRAIN 来源取样。按题号、报告、公司年份和表内容排除与官方评测的重叠，独立保存公开题面和答案。完整评测索引的既有暴露标记仅用于分组报告。

`benchmark_actions.py` 复用 OpenCode 和官方评分器。它采集固定三档动作、同提示独立解答与 CAR 的逐题五类诊断。High 档的盲解和比较分开计费。缓存要求同一面板、权重、推理配置和确切提示。CAR 后续修订、各策略拟合及完整评测还需实测。

- `budget_policy.py` 按每个成本权重从三个实测动作生成路由监督。GBM 默认使用，GB10 已有的 TabFM 权重可用于后续同面板对标。拟合集训练、校准集选参，评测逐题计入整个所选档的成本。
- `car_adapter.py` 用首答和五类诊断拟合错答风险，分别估计有界修复的恢复与错改，再用校准集冻结修订门槛。本任务使用官方数值正确性、DSL 检查与公开证据位置，保留适配名。
- `cascade_benchmark.py` 调用已固定原版 `CascadeRouter`，使用公开程序执行、证据定位与相互分歧作为质量特征。GB10 隔离依赖目录使用作者发布的 NumPy、SciPy、scikit-learn 版本。与固定 8B 起步的逐级调用分开报。上述适配已做合成流程验证，实际推理、拟合及计分另行执行。
- `school_benchmark.py` 通过既有校内网关记录 DeepSeek 的独立解答，明确区分本地模型版本与托管 API 配置。GB10 用实际 OpenCode 和合成响应验证请求校验、计费及断点复用。实际校内调用待路线锁定。重放报告的时延为逐题调用时长之和，正式墙时比较另计路由与服务开销。

ODA 论文的 FinQA 和 TAT-QA 报分使用 CompassVerifier，当前实验对照以自己的统一官方评分为准。[ODA 原文](https://arxiv.org/html/2603.07223v1#S4) · [固定版本](https://huggingface.co/OpenDataArena/ODA-Fin-RL-8B/tree/948c22ea48f9bf93e5747f4211657fcad9cb0295)
