## 2. 必须先修正的科学解释

### 2.1 当前 resource graph 实际是资源成员筛选

`run_adjudicator_oracle.py:43` 使用 `node.agent_id in candidate_features.resource_ids` 定位节点，未遍历依赖边。其性能支持“资源成员信息有用”和“训练族校准规则是强基线”，尚不能证明“图传播有效”或“依赖结构已被确认为唯一瓶颈”。

fresh/staged compact 输入还省略了 plan edges；不同探针的信息集和样本数不同。因此，阶段式模型与全量资源基线的分数差不能单独归因为依赖结构。

下一轮应补明确的名称与机制说明，保留旧报告原文和原始结果；通过带日期的更正说明更新现役解释。

### 2.2 handling 0.012 主要是集合完整性问题

`run_uncertainty_adjudication.py:63` 只要求动作是 `execute,repair,defer` 的一个子集；`:88` 却以整个可接受集合的精确相等计分。

本次复算 250 条已有预测：

- 241 条只输出 `{defer}`，这 241 个动作全部在各自 Gold 允许集合内。
- 6 条输出 `{execute,repair}`，3 条输出三个动作。
- 245/250 的预测集合非空且是 Gold 子集；250/250 与 Gold 有交集。
- 完整集合精确命中仍是 `3/250 = 0.012`；宏平均集合 precision `0.990`，recall `0.4173`。

所以，不能解释成“几乎无法给出合法动作”。也不能因 defer 合法就认为任务解决：Gold 全部允许 defer，使 always-defer 成为必须报告的退避基线。真正的行动质量还需要完成率、覆盖、风险和成本；仅有集合标签不能自行发明真实执行效用。

保留原 exact score，单独增加 post-hoc 诊断。新实验必须分别定义“列全所有允许动作”和“选择一个动作”；一个动作集合包含合法动作，也不等于实际策略一定选择了该动作。

### 2.4 oracle 辅助、真实 trace、Gold 政策是三件事

uncertainty 模型输入直接包含 `o3_relation`，属于带 oracle 输出的诊断条件。它不是完全从原始快照独立推导的能力测量。

队列脚本用了 `alignment`；但本次复算确认，当前 250 条恰等于公开 `blocking_requirements` signature 子集，94 条 `o1_only_disagrees` 全包含于其中。因此本 release 可用公开 signature 等价选样；这个等价关系是本次事后观察，仍需在新数据上验证，且 O1 signature 本身的生成能力也应与“直接提供 O1 输出”分开。

数据发布材料提供 O3 版本、trace 引用和 hash；本地审阅未取得可重放的对应 trace 文件、生成器和模拟器实现。结论是“当前尚未独立重建”，不是“永远不可重建”。数据卡的人类盲审声明只能归因于发布者，软件完整性验证不认证人的身份与采集过程。

此外，O2 裁决与 O3 模拟结果可能有不同目标。拿到 simulator trace 不会自动给出所有可接受动作或人类裁决政策；不得从 Gold 反推 trace，再称为独立执行证据。

### 2.5 当前最合理的假设是竞争解释，而非单一瓶颈

| 竞争解释 | 当前支持 | 区分它需要什么 |
|---|---|---|
| 输出与评分合同不充分 | 未明确要求穷尽允许动作，subset 措辞与 exact-set 目标存在歧义 | 离线复算；明确两类任务；与 always-defer 对照 |
| 输入缺少依赖或裁决政策 | edges 被省略、trace 不可重放、O1/O2/O3 分歧 | 明确公开信息边界，比较同信息下规则与模型；补独立 trace/政策 |
| 模型未能利用已有信息 | 既有 prior anchoring 与节点定位表现 | 在同任务、同信息、同预算下做可执行的结构/表示/推导对照 |

若两个实例在冻结 actor 视图上完全相同但有不同目标标签，可以证明该视图下的非唯一性。仅因当前模型失败或 oracle 有分歧，不能直接证明任务不可识别。

## 4. 下一阶段大方向

建议主问题：**环境、证据或任务约束变化后，Agent 如何用有限验证成本，决定保留哪些经验、重验哪些依赖、修复哪些动作？**

这把当前观察转为决策与信息获取研究，而不预设某一种 memory 表示必须获胜。Loop D 可以选择其他可证伪问题；以下是优先候选，不是封闭菜单。

| 方向 | 值得研究的问题 | 最小有信息量的探针 | 主要替代解释 |
|---|---|---|---|
| 主动依赖获取 | 依赖图不完整时，下一次应查定义、查边还是运行局部测试？ | 固定查询预算，比较随机、词法/不确定性启发式、主动策略；观察新任务成功和查询成本 | 更多调用或更多文本即可解释收益 |
| 局部重验与修复 | 哪些经验仍有效，如何避免全忘与盲用？ | 真实可执行变化，比较保留、全重算、recency、静态依赖规则、选择性重验；同时测误伤与漏修 | 已给完美依赖，算法只是传统增量重算 |
| 带条件的经验抽象 | 历史能否学出可验证的适用条件，优于普通 solved example？ | 同一历史池比较原轨迹、示例、自然语言规则、可执行 guard；测试新组合与选择性条件变化 | 更长上下文、额外工具调用、手写规则全部解释 |
| 分歧下的行动 | 规则、裁决与执行结果不一致时，应询问、验证还是退避？ | 分开事实判定和规范政策；在有独立效用/执行反馈的任务中比较选择 | 单靠多 defer 降风险，或用隐含 Gold 决定路由 |
| 自选探索 | Loop D 认为更有积累价值的新机制 | 给出竞争解释和一个便宜反证动作；允许离开 MA-CERD/金融 | 只是改领域名或重命名已停止候选 |

优先建议：先做测量与信息边界诊断，再选择“主动依赖获取 + 局部重验”的组合。若 MA-CERD 不可重放，可用公开代码构建、表格计算或工具合同的独立可执行小任务；标为新任务机制探针，不能称为 MA-CERD 复现或真实场景普遍有效。

近邻已经相当接近：

- *PACMI*，arXiv:2610.05732v1，2026-10-05。已研究类型依赖边与失效传播；其 §1 Scope 明确假定预更新依赖图由标注提供，不研究从原始记忆归纳图。本次核查摘要及正文相关假设/方法段。
- *Invalidation Contracts for Cross-Episode Agent Memory*，arXiv:2609.00243，2026-08-31。已讨论版本失效、局部保留，以及有效性与模型实际采用的区分。本次核查摘要。
- *When Memory Updates but Behavior Does Not*，arXiv:2608.01619，2026-08-03。区分存储更新与行为适应，并报告额外审阅本身可能解释收益的条件。本次核查摘要。
- *Rethinking the Role of Tool Graph Memory in Multi-Turn Tool Use*，arXiv:2610.21571，2026-10-15。强调与额外计算、随机/无指引和文字经验的对照。本次核查摘要。
- Geifman 与 El-Yaniv，*Selective Classification for Deep Neural Networks*，NeurIPS 2017。风险与覆盖的权衡已有成熟研究，不能将简单 queue + abstain 当作新颖性。本次核查论文官方摘要。

以上不是系统综述或新颖性认证。下一轮应精读真正影响所选机制的少量最近邻，争取可检验差异，例如不完美依赖的主动获取、条件变化后验证预算分配、同成本下的行动修复；不靠“又有图又有记忆”命名创新。

## 5. 可供采纳的分阶段 Goal

候选 ID：`RECONCILE_EVIDENCE_AND_DISCOVER_ADAPTIVE_REVALIDATION_V1`。
总目标：保全并整合科研资产，纠正结论解释，收敛一篇有边界的 Paper E，并通过小型可证伪实验选出值得下一轮投入的机制。

本节是提案，不是已经发给 Loop D 的执行命令。正式采纳后，阶段间由 Loop D 根据证据自主推进；没有新增费用、总额变化或冻结边界变更时，不需反复向 owner 要批准。

| 阶段 | 核心行动与产物 | 完成条件及继续/转向规则 |
|---|---|---|
| S0：保全与解释校准 | 保存现场；冻结本次输入；补 handling 合同诊断、分区指标、资源基线命名、oracle 可见性矩阵、预算沿革 | 一份简洁更正说明能把数值、机制与证据身份对齐；原始分数不变。此阶段无新模型调用 |
| S1：治理集成与可重建性侦察并行 | 完成三方集成和证据安置；寻找可公开独立取得的规则/trace/生成器，核验执行链 | 每件独有材料有归属；能重放则进入结构实验。不能重放则停 MA-CERD 的原模拟器归因，转独立可执行候选；不阻塞其他研究 |
| S2：最小机制探针 | 同任务同信息下比较资源成员筛选、真实边算法、等信息文本与结构化表示；必要时区分无 oracle 与 oracle 辅助条件 | 真实结构、无关结构、扰乱结构及预算匹配对照能区分原因；若强规则已解释全部收益，停止该方法优越性主张，保留边界发现 |
| S3：自主科研探索 | 自主选一至两个机制做薄原型、历史/查询采集与开发小实验；允许快速停线或提出新方向 | 至少一个真实观察改变了任务/机制/资源选择；仅有候选名称、文档或 PASS 不算科研推进。真实负向结果同样合格 |

S0–S4 表示成果依赖，不是全局串行准入门。S3 可在 S0 保全完成、各自输入可用后并行开始，不以全库 clean、MA-CERD 可重放或 S2 完成为统一前置条件。

S2 首先回答“有无值得新请求的信息量”，不默认全量再跑 250 条。结构实验要分别控制信息量与表示：增加真实依赖信息的收益，不等于图表示本身的收益；乱图负对照也不能冒充可信 oracle。规范性处理集合需要明确政策来源，模拟结果只能支持其实际能决定的标签。

S3 若研究经验收益，历史采集、检索、归纳、重验和修复成本均入总成本。与普通示例、固定规则、同调用/同 token 的重推导作对照。原 Gold/旧历史不能通过改名成为新独立数据；成功轨迹可以提供信息，无需强求人为制造失败。

S4 的新确认比较需要 family 级隔离、配对不确定性、覆盖/风险/成本以及明确主要目标；不要把 1,000 条相关干预当作 1,000 个独立样本。若数量不足以支持确认，应明确保留为开发信号，不能靠显著性筛选换主问题。
